# 🎁 頭の中3ノートテンプレート（自己紹介／判断基準／進行中）

AIエージェントに「自分が何者か」を一生忘れさせないための3つのメモです。Obsidianのボルト直下にこの3つをMDファイルとして保存しておくと、新しいセッションを開くたびに前提を説明し直す必要がなくなります。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 各ノートの「書式」部分だけをコピーしてObsidianの新規ノートに貼り、空欄を自分の内容に書き換えてください。「記入例」はそのまま消して構いません。

### 1. 自己紹介ノート（profile.md）

説明: AIに「あなたが何者か」を教える一番土台のメモです。ここが充実しているほど、AIはあなた向けの回答を返してくれるようになります。

```text
書式:
自己紹介

◆仕事・役割
- 職種／立場：
- 担当している業務：

◆今のチーム・環境
- 使っているツール：
- 一緒に働く相手：

◆よく使うAIツール
- 普段使うAIエージェント：
- 得意な使い分け（例：長文作成はA、コード修正はB）：

◆好み・スタイル
- 文章のトーン（例：敬体／簡潔／絵文字なし）：
- 出力形式の好み（例：箇条書き優先）：

記入例:
自己紹介

◆仕事・役割
- 職種／立場：YouTubeチャンネル運営・動画制作ディレクター
- 担当している業務：企画立案、台本作成、分析レポート作成

◆今のチーム・環境
- 使っているツール：Obsidian、ClaudeCode、Codex
- 一緒に働く相手：編集者1名、AIエージェント複数

◆よく使うAIツール
- 普段使うAIエージェント：ClaudeCode（台本・リサーチ）、Codex（レビュー・自動化）
- 得意な使い分け（例：長文作成はA、コード修正はB）：日本語の完成度が必要な作業はClaudeCode、スピード重視の自動化はCodex

◆好み・スタイル
- 文章のトーン（例：敬体／簡潔／絵文字なし）：敬体・簡潔・絵文字なし
- 出力形式の好み（例：箇条書き優先）：結論を先に、詳細は箇条書き
```

### 2. 判断基準ノート（判断基準.md）

説明: 「これはやる／やらない」をAIが自分で判断できるようにする基準集です。毎回口頭で説明していたルールをここに書き溜めると、AIが提案の時点で基準に沿ってくれるようになります。

```text
書式:
判断基準

◆大事にしていること
- 

◆やらないと決めていること
- 

◆迷ったときの優先順位
1. 
2. 
3. 

記入例:
判断基準

◆大事にしていること
- 視聴者が最後まで見られる分かりやすさを最優先する
- 数字や一次情報は必ず出典を確認してから使う

◆やらないと決めていること
- 誇張したタイトル・クリックベイトだけの煽り文句は使わない
- 未確認の情報を断定形で書かない

◆迷ったときの優先順位
1. 正確性（間違った情報を出さない）
2. 分かりやすさ（初心者が置いていかれない）
3. 効率（時間をかけすぎない）
```

### 3. 進行中ノート（進行中.md）

説明: 「今どのプロジェクトの何が動いているか」をAIと共有し続けるための更新型メモです。デイリーノートと違い、終わったタスクは消して常に“今”だけを映す使い方をします。

```text
書式:
進行中

◆今動いているプロジェクト
- プロジェクト名：
  - 現状：
  - 次にやること：
  - 期限：

◆保留中・様子見
- 

記入例:
進行中

◆今動いているプロジェクト
- プロジェクト名：Obsidian解説動画
  - 現状：台本ドラフト完成、プレゼント制作中
  - 次にやること：サムネ確定、公開日調整
  - 期限：2026-09-14

◆保留中・様子見
- 新シリーズ企画（他チャンネルの反応を見てから判断）
```

**ポイント**: 3つとも「完璧に埋める」必要はありません。まずは分かる範囲だけ書いて保存し、使いながら育てていくのがコツです。散らかった書き方はAIが読み取って整理してくれます。

# 🎁 永続メモリ活用 指示文3本＋出力見本

Obsidianに溜めた記憶をAIエージェントにちゃんと使わせるための指示文3本です。「聞き出す」「忘れさせない」「整える」の3段階で、それぞれ実際にどんな返答が返ってくるかの出力見本も付けています。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 場面に合った指示文の〔　〕部分を自分の内容に書き換えて、いつものAIエージェントに貼るだけです。

### 1. 過去の記録を掘り起こして答えさせる

説明: Obsidianに保存済みのメモ・データを前提に、AIに聞くだけで答えを引っ張ってきてもらう指示文です。日付や固有名詞を含めるほど、AIがボルト内を正確に探しに行きます。

```text
指示文:
〔チャンネル名／プロジェクト名〕の〔日付〕の〔対象〕について、Obsidianのボルト内にあるメモやデータから分かることを教えて。無ければ「ボルト内に情報がない」と正直に言って。

出力見本:
ボルト内を確認しました。「AIエージェントチャンネル/2026-05-25」フォルダに該当のアナリティクスCSVと個別レジェンドメモがあったので、そちらから集計します。

- 視聴回数：9,610回
- インプレッション：96,234回
- クリック率：約10.0%
- メモにある補足：「サムネのA/Bテストで文字色を変えた回」

この3点はメモとCSVの両方に記録があるため確度が高いです。それ以外のコメント傾向などはボルト内に情報がなかったので回答できません。
```

### 2. 修正内容を「二度と忘れない反省情報」として記録させる

説明: 指摘した直しをその場限りで終わらせず、次から自動で守らせるための指示文です。この一文をルールとして冒頭に置いておくと、「反省情報を書いて」と言わなくてもAIが会話の最後に自分から残してくれるようになります。

```text
指示文（ルールとして常時有効にしておく）:
今後、私から修正・やり直しの指示が入ったら、そのやり取りの最後に必ず「反省情報」を1件、短く具体的にreflections.mdへ追記して。書式は「発生日／何が起きたか／なぜ起きたか／次から守ること」の4行。私から「反省情報を書いて」と言われなくても、修正が入った会話では毎回自動で行って。

出力見本:
（修正指示への対応が終わった後、AIが自動で追記）
reflections.md に追記しました。

◆見出しの文字数オーバー
- 発生日：2026-09-11
- 何が起きたか：スライド見出しが1行に収まらず折り返した
- なぜ起きたか：全角20文字の上限を確認せずに書いた
- 次から守ること：見出しを書く前に全角20文字以内かを必ず数える
```

### 3. 溜まった情報を週1で棚卸しさせる

説明: 足すだけだと情報はどんどん古くなって溜まっていきます。週に1回、AIに整理を任せる指示文です。オートメーション（定期実行）に登録しておけば、意識しなくてもボルトがきれいな状態を保てます。

```text
指示文（週1回、定型で投げる／自動化にも登録可能）:
reflections.md と 進行中.md を確認して、①もう当てはまらなくなった反省情報、②2週間以上更新のない「進行中」の項目、を見つけて。削除していいか判断できるように、それぞれ理由付きでリストにして。実際の削除は私が確認してから行って。

出力見本:
棚卸し結果です。

【もう当てはまらない反省情報（削除候補）】
- 「動画IDの取り違え」ルール（2026-08-10追加）→ 該当する作業フロー自体が9月から自動化され、発生しうる状況が無くなったため

【2週間以上動きのない「進行中」項目】
- 「新シリーズ企画」→ 最終更新2026-08-20のまま。保留中に移すか、着手するか判断をお願いします

上記2件について、削除／保留への移動のご指示をください。
```

**ポイント**: 3本とも「聞きっぱなし」にしないのがコツです。1と2はやり取りの中で自然に発生させ、3だけは自分から定期的に投げる。この3段階が回り出すと、使うほどAIが賢くなっていく状態に入ります。

# 英語で書かれた Obsidian 公式のAI向けスキル6つを、「何ができるか・どう頼むか・どこでつまずくか」まで日本語で解説しました。Codex に入れたその日から、リンクやプロパティを崩さずに、メモの整理・一覧表・図・Webページの取り込みまでAIに任せられます。

# 🎁 AIがObsidianを使いこなせるようになる「公式AI説明書」日本語解説

英語で書かれた Obsidian 公式のAI向けスキル6つを、「何ができるか・どう頼むか・どこでつまずくか」まで日本語で解説しました。Codex に入れたその日から、リンクやプロパティを崩さずに、メモの整理・一覧表・図・Webページの取り込みまでAIに任せられます。

**受け取り方**: 各コードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: まず「0. 入れ方」でスキルを Codex に入れ、Obsidian のボルト（メモを入れるフォルダ）を Codex で開いてから、使いたいスキルの依頼文を貼ってください。〔　〕は自分の内容に書き換えます。スキルの中身は英語ですが、頼むときは日本語で大丈夫です。

### 0. 入れ方（Codex）

期待できるメリット: 「Obsidian の書き方をAIに教える」作業を自分でしなくて済みます。一度入れれば、どのボルトで作業するときも、AIが Obsidian 専用の書き方（[[リンク]]・プロパティ・コールアウトなど）を正しく使うようになります。
使う場面: Codex で Obsidian のボルトを触り始める最初の1回。
前提: Codex（アプリか CLI）が使えること。スキル集の置き場所は GitHub の kepano/obsidian-skills です。

入れ方は2通りあります。

- Codex に頼む: Codex に標準で入っている `$skill-installer` を呼び、下の依頼文を貼ります。
- 手で置く: GitHub から取ってきたスキル集の `skills` フォルダの中身（obsidian-markdown など6つのフォルダ）を、`~/.agents/skills/` に置きます。そのボルトだけで使いたいときは、ボルト直下の `.agents/skills/` に置きます。

```text
$skill-installer
GitHub の kepano/obsidian-skills にあるスキルを、私のユーザー用のスキルとして入れてください。
・入れるのは skills フォルダの中の6つ（obsidian-markdown／obsidian-bases／json-canvas／obsidian-cli／defuddle／knap）
・入れる前に、入れる場所と6つの名前を一覧で見せて、私の「OK」を待つ
・入れ終わったら、Codex を再起動する必要があるかを教える
```

入ったかどうかの確認は、次の依頼文でできます。

```text
いま使えるスキルの一覧を出して、obsidian-markdown／obsidian-bases／json-canvas／obsidian-cli／defuddle／knap の6つがあるか、表で〇×を付けてください。無いものがあれば、入れ方だけ説明して止まってください（勝手に入れない）。
```

つまずきどころ: 入れたのに一覧に出てこないときは、Codex を一度閉じて開き直してください。defuddle と knap は、スキルとは別に「道具」本体のインストール（Node.js の npm）が要ります（5・6を参照）。obsidian-cli は、Obsidian のアプリを起動している間しか動きません。

### 1. obsidian-markdown — メモの書き方を崩さない

期待できるメリット: AIに書かせたメモでも、[[リンク]]・![[埋め込み]]・コールアウト（色付きの注意書き）・先頭のプロパティ（日付やタグの欄）が正しい形で残ります。「AIに触らせたらリンクが切れた」「プロパティが壊れた」がなくなり、グラフビューでつながりもきちんと見えます。
使う場面: 会議メモや調べたことを、AIに新しいノートとして書かせるとき／雑に書いたメモを、Obsidian の形に整えさせたいとき。

```text
01_Inbox/〔メモのファイル名〕.md を、Obsidian の書き方で整えてください。
・先頭にプロパティを付ける（type／created／updated／tags）
・中に出てくる人名・会社名・案件名のうち、ボルトにノートがあるものは [[ノート名]] でつなぐ（無いものは勝手に作らない）
・期限や注意が書いてある所は、> [!warning] のコールアウトにする
・元の文章の意味は変えない。書き換える前に、変更前と変更後を並べて見せて、私の「OK」を待つ
```

つまずきどころ: リンク先の名前が少しでも違うと、新しい空のノートへのリンクになります。「ボルトにあるノート名だけでつなぐ」と必ず書いてください。整える前に、元のメモを1枚だけで試すと安心です。

### 2. obsidian-bases — メモを「一覧表」にする

期待できるメリット: 案件ノートや読書メモを、プロパティ（状態・期限・担当など）で並べた表やカードの一覧にできます。1枚ずつ開かなくても、「期限が近い順」「状態が進行中のものだけ」が1画面で見られます。
使う場面: 案件・顧客・読んだ本など、同じ形のノートが増えてきたとき。
前提: 並べたいノートに、共通のプロパティ（例: status・期限）が付いていること。

```text
03_プロジェクト にある案件ノートを一覧にする Bases（.base ファイル）を作ってください。
・表示する列：ファイル名／status／期限／相手／updated
・status が「完了」のノートは出さない
・期限が近い順に並べる。期限が空のものは一番下
・カード表示のビューも1つ足す（名前は「カード」）
・保存先は 03_プロジェクト/案件一覧.base。作ったら、Obsidian で開いて確かめる手順を3行で教えて
```

つまずきどころ: Obsidian で開いたときにエラーが出たら、エラーの文をそのまま Codex に貼って「直して」と頼んでください。多いのは、プロパティ名の書き間違いと、記号を含む文字の囲み忘れです。

### 3. json-canvas — 会議メモを「図」にする

期待できるメリット: 長文の会議メモを、「決まったこと」「宿題」「担当と期限」が一目で分かるホワイトボード（Canvas）の図にできます。読み返されないまま埋もれていた会議メモが、次の会議の前に1分で見返せる形になります。
使う場面: 会議の直後に宿題の抜け漏れを確かめたいとき／関係者に全体像を見せたいとき。

```text
02_会議/〔会議メモのファイル名〕.md を読んで、Canvas（.canvas ファイル）の図にしてください。
・真ん中に会議名、左に「決まったこと」、右に「宿題」のカードを置く
・宿題は担当ごとにグループにまとめ、各カードに期限を書く
・「決まったこと」と、それに関係する「宿題」を線でつなぐ
・保存先は 02_会議/〔会議名〕.canvas。元の会議メモは書き換えない
・作ったら、すべての線のつなぎ先が存在するか確かめてから終わる
```

つまずきどころ: カード同士の重なりや、つなぎ先の間違いがあると、図が崩れたり開けなかったりします。最後の「確かめてから終わる」の一行を消さないでください。できた図は Obsidian のアプリで開いて確認します。

### 4. obsidian-cli — アプリを通してボルトを操作する

期待できるメリット: 検索・デイリーノートへの追記・プロパティの書き換え・タスクの一覧・バックリンク（どのメモから参照されているか）を、Obsidian のアプリの機能を通してAIに任せられます。ファイルを直接書き換えるより、アプリの仕組みに沿った安全な操作になります。
使う場面: 毎日のデイリーノートに予定やタスクを足したいとき／あるメモを参照しているメモを洗い出したいとき。
前提: Obsidian のアプリが起動していること。アプリの設定で CLI を有効にし、パソコンから `obsidian` コマンドが使える状態にしておくこと。

```text
Obsidian CLI を使って、次の3つをしてください。
1. 今日のデイリーノートに「- [ ] 〔やること〕」を1行追記する
2. 「〔ノート名〕」を参照しているノート（バックリンク）を一覧にする
3. 未完了のタスクを、ノートごとに件数つきで表にする
・アプリが起動していない、または CLI が使えないときは、何もせずにその旨だけ伝える
・ファイルを直接書き換えず、CLI の操作だけで行う
```

つまずきどころ: 「コマンドが見つからない」ときは、アプリの設定で CLI が有効になっていないか、アプリが閉じています。ボルトを複数持っている人は、依頼文に「〔ボルト名〕のボルトで」と足してください。

### 5. defuddle — Webページを「本文だけ」のメモにして取り込む

期待できるメリット: Webページのメニューや広告を取り除いて、本文だけを Markdown のメモとして保存できます。AIが読む量が減るので、使える回数を節約しながら、調べ物をボルトに貯めていけます。
使う場面: 読んだ記事・公式ドキュメント・ニュースを、あとで自分のメモと一緒にAIに読ませたいとき。
前提: Node.js が入っていて、`npm install -g defuddle` で道具本体を入れてあること（入っていなければ、この依頼文でAIがインストールの許可を求めてきます）。

```text
defuddle を使って、次のWebページを本文だけの Markdown にし、01_Inbox に保存してください。
・URL：〔URL〕
・ファイル名は記事のタイトル（使えない記号は取り除く）
・先頭にプロパティを付ける（type: 資料／source: 元のURL／created: 今日の日付／tags: 資料）
・本文の前に、要点を3行で書いた「> [!summary] 要点」のコールアウトを置く
・defuddle が入っていなければ、インストールしてよいか私に聞いてから進める
```

つまずきどころ: ログインが必要なページや、有料記事は取り込めません。取り込んだ本文が短すぎるときは、ページが読み込み途中の可能性があるので、もう一度頼んでください。

### 6. knap — 表のデータから、メモを一括で作る

期待できるメリット: 名刺の一覧や顧客リストなどの表（CSV）から、「1行＝1枚」のノートをまとめて作れます。10件・50件のノートを手で作る時間がなくなり、全部が同じ形（同じプロパティ・同じ見出し）でそろいます。
使う場面: 展示会の名刺・問い合わせ一覧・読書リストなど、表で持っているものを Obsidian で1件ずつ管理したいとき。
前提: Node.js 20 以上で、`npm install -g knap` で道具本体を入れてあること。表の1行目が見出し（会社名・担当者など）になっていること。

```text
knap を使って、〔CSVのパス〕から、1行につき1枚のノートを 03_プロジェクト/〔フォルダ名〕/ に作ってください。
・テンプレートの先頭にプロパティ（type: 見込み客／会社名／担当者／日付）を入れる
・本文には「話したこと」「次にやること」の2つの見出しを入れ、中身は空欄にする
・ファイル名は会社名にする（使えない記号は取り除く）
・先に試し実行（--dry-run）で、作られるファイル名の一覧だけを見せて、私の「OK」を待つ
・同じ名前のファイルがすでにあるときは、上書きせずに一覧で知らせる
```

つまずきどころ: CSV の文字化けは、Excel から「CSV UTF-8」で保存し直すと直ります。同じ会社が2行あると、同じファイル名になって止まります。先に表の重複を消してから頼んでください。

**ポイント**: 最初は「1. 書き方」と「3. 図」から試すのがおすすめです。どちらも、ボルトの中のファイルを書き換える前に、必ず確認をとらせる一行を残してください。
