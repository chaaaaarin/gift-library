# 🎁 AI利用額が今日わかる 導入手順書

「AIに毎月いくら払っているか分からない」が、今日30分で終わります。手元のログを読むだけで、先月の利用額がモデル別・日別・プロジェクト別の数字になって出てきます。黒い画面が苦手でも進めるように、つまずきどころを全部先回りして書きました。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 上から順に、□ の質問に答えながら進めてください。`指示例:` の行は、そのままAIに貼れば代わりにやってくれます。

```text
【AI利用額が今日わかる 導入手順書】

このシートの目的：
「AIコーディングに毎月いくら使っているか」を、推測ではなく手元の実データから出す。
外部に何も送信せず、アカウント登録もキーの発行もせずに、30分で先月の数字を確定させる。


■ ステップ0：やる前に、期待値を合わせる

□ 出てくるのは「請求書」ではなく「推定額」だと理解しているか
  → YES: 先へ進む。ログに記録されたトークン数は実測値だが、単価は手元の表を掛けて計算する。
    実際の請求と数円〜数十円ずれることがある。ずれても壊れているわけではない。
  → NO: ここで止まる。正確な請求額が要るなら、各サービスの管理画面を見た方が早い。
    このシートの価値は「どのモデルに・どのプロジェクトで・どの日に偏っているか」が分かることにある。

□ 自分が何を使っているか把握しているか（複数可）
  □ Claude Code　□ Codex　□ Gemini CLI　□ Cursor
  → YES: 上3つのどれかに当てはまれば、この手順で数字が出る。
  → Cursorだけの人: 現時点では読み取り機能が未完成のため、数字は出ない。
    ステップ5まで飛ばして「今後に備えてログを消さない」だけやっておく。

指示例: 私のパソコンに Claude Code・Codex・Gemini CLI のログが残っているか調べてください。
それぞれ ~/.claude/projects、~/.codex/sessions、~/.gemini/tmp を見て、
ファイルが何個あるか・いちばん古い日付といちばん新しい日付を表で教えてください。


■ ステップ1：ログが本当に残っているか確認する（3分）

期待できるメリット：ここで「そもそもログが無い」と分かれば、後の20分を無駄にしない。
逆にログが1ヶ月ぶんあれば、この先の数字は必ず出ると確定する。

□ ~/.claude/projects の中に .jsonl ファイルがあるか
  → YES: Claude Code の利用額が出せる。
□ ~/.codex/sessions の中に rollout- で始まるファイルがあるか
  → YES: Codex の利用額が出せる。
□ ~/.gemini/tmp の中に session- で始まるファイルがあるか
  → YES: Gemini CLI の利用額が出せる。
□ どれも空だった
  → YES: ツールを入れ直した直後か、クリーンアップツールで消した可能性が高い。
    今日から溜まるので、1週間後にこのシートに戻ってくる。

指示例: 上の3つのフォルダについて、ファイル数と最古・最新の更新日を調べて、
「どのツールを・いつから・どれくらい使っているか」を3行でまとめてください。


■ ステップ2：集計ツールを入れる（10分）

期待できるメリット：一度入れれば、以降は1コマンドで毎月の数字が出る。
月末に「今月いくらだった？」を10秒で答えられる状態になる。

□ Python が使える状態か（バージョン3系）
  → YES: 次へ。
  → NO: 先に Python を入れる。macOS なら Homebrew、Windows なら winget が早い。

□ 作業用のフォルダを決めたか
  → YES: そこに clone する。ホーム直下でよい。散らかるのが嫌なら ~/tools/ など。

□ インストールが最後まで通ったか
  → YES: ステップ3へ。
  → NO: エラー文の最後の3行をそのままAIに貼る。9割は依存関係かPythonのバージョン違い。

指示例: 次の手順を私の代わりに実行してください。私は技術に詳しくないので、
一度に1つずつ指示を出し、途中でエラーが出たら自分で直してから次に進んでください。
(1) 作業フォルダを ~/tools/ に作る
(2) その中に damejan80/tokentab を git clone する
(3) clone したフォルダに入って pip install . を実行する
(4) 入ったことを確認するため、バージョン表示かヘルプ表示を1回実行する
(5) 最後に、うまくいったかどうかだけを ✓ か × で報告する


■ ステップ3：まず「今日」だけ出してみる（2分）

期待できるメリット：いきなり全期間を出すと桁が大きくて驚くだけで終わる。
まず今日ぶんを見て「読み方」に慣れておくと、後の数字が意味を持って見える。

□ 今日ぶんの集計が表示されたか
  → YES: 表の見出しを確認する。モデル名・トークン数・金額の3つが並んでいれば正常。
  → NO: 「ログが見つからない」と言われた場合、ステップ1に戻る。
    「モデルが表に無い」と言われた場合はステップ4で対処する（壊れてはいない）。

□ 金額が $0.00 と表示されている行があるか
  → YES: そのモデル名が単価表に載っていないだけ。無視せず、モデル名をメモしておく。
    この行を放置すると、合計が実際より安く出てしまう。

指示例: tokentab で今日ぶんの利用額を出して、表示された表をそのまま見せてください。
そのうえで、金額が 0.00 になっている行があれば、そのモデル名だけを一覧にしてください。


■ ステップ4：単価表を自分用に直す（5分）※$0.00 が出た人だけ

期待できるメリット：ここを直すと合計額が正しくなる。
直さないまま運用すると「思ったより安いな」と誤解したまま数ヶ月過ごすことになる。

□ ステップ3でメモしたモデル名があるか
  → YES: 単価表のファイル（tokentab/pricing/prices.py）を開き、
    近い名前の行をコピーして1行足す。単位は「100万トークンあたりのドル」。
  → NO: このステップは飛ばしてよい。

□ 単価が分からない
  → YES: 使っているサービスの公式の料金ページを見る。推測で入れない。
    どうしても分からなければ、その行は 0 のままにして「未計上」と割り切る。

指示例: tokentab の単価表ファイルを開いて、いま $0.00 になっているモデルの行を追加してください。
単価は私が調べて伝えるので、まず「入力・出力・キャッシュのどの数字が必要か」を教えてください。
勝手に推測した数字を入れないでください。


■ ステップ5：先月ぶんを出して、判断材料にする（5分）

期待できるメリット：ここが本番。月単位の数字が出ると
「高いから安い経路に切り替える」「この金額なら気にしない」の判断が初めてできる。

□ 先月ぶんの合計が出たか
  → YES: 次の3つを必ず見る。
    (1) いちばん高いモデルはどれか　(2) いちばん高いプロジェクトはどれか
    (3) 突出して高い日はあるか（1日だけ跳ねていることが多い）
□ ブラウザで見たいか
  → YES: web 表示のオプションを付けると、同じ数字がグラフ付きで見られる。
    外部には通信せず、自分のパソコンの中だけで開く。

□ 金額を見てどう思ったか
  → 高いと思った: 提供元の切り替えや、計画と実装の分担を検討する段階。
  → 想像より安かった: 何もしなくてよい。むしろ使う量を増やす判断もありうる。
  → 判断がつかない: 3ヶ月ぶん出して推移を見る。1ヶ月では傾向が分からない。

指示例: tokentab で先月1ヶ月ぶんの利用額を出して、次の4点を日本語でまとめてください。
(1) 合計金額　(2) モデル別の内訳（高い順に3つ）　(3) プロジェクト別の内訳（高い順に3つ）
(4) 金額が突出して高い日と、その日に何をしていたかの推測
最後に「この金額は一般的な使い方として高いか安いか」の所感を1行で添えてください。


■ ステップ6：毎月続ける形にする（5分）

期待できるメリット：1回出して終わりだと意味がない。月初に3分見るだけの習慣にすると、
使いすぎに気づくのが「請求後」から「請求前」に変わる。

□ 月初に見る日を決めたか
  → YES: カレンダーに毎月1日で繰り返し予定を入れる。所要3分。
□ 数字を残す場所を決めたか
  → YES: スプレッドシートでも手帳でもよい。合計額だけ書き写す。
    3ヶ月ぶん並ぶと、増えているのか減っているのかが初めて分かる。
□ ログを消していないか
  → YES: クリーンアップ系のツールで ~/.claude や ~/.codex を消すと、過去が復元できない。
    除外設定に入れておく。


■ つまずきどころ（ここで詰まる人が多い順）

□ 「コマンドが見つかりません」と出る
  → インストールしたフォルダの中で実行していない可能性が高い。
    フォルダに入り直してから、もう一度実行する。

□ 金額の合計が明らかにおかしい（安すぎる／高すぎる）
  → 安すぎる場合はステップ4の単価表未登録。高すぎる場合はキャッシュの二重計上を疑う。
    どちらもモデル別の内訳を見れば、どの行が原因か1分で分かる。

□ Cursor の数字が出ない
  → 現時点では読み取り機能が未完成。出ないのが正常な状態。

□ 数字を見たあと、結局なにもしなかった
  → いちばん多い失敗。金額を見た日に「来月これを1つ変える」を1行だけ決めて、
    ステップ6のメモに書いておく。変える内容は小さくてよい。
```

**ポイント**: 出てくる金額は実測トークン数×手元の単価表による推定です。正確な請求額は各サービスの管理画面で確認してください。このシートの価値は総額そのものより、「どのモデル・どのプロジェクト・どの日に偏っているか」が見えることにあります。
