# 🎁 AIに頼む前の30秒セルフチェック＋手戻りゼロ指示テンプレ

出力が「惜しい」で終わるのを、着手前に潰すチェックリストです。AIに送信する前の30秒で「目的・成功条件・検証方法」の欠けを見つけられるので、作り直し（手戻り）の往復が減り、1回目の出力がそのまま使える確率が上がります。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: AIに依頼文を送る直前に、上から順に読む。□がYESで埋まらない項目があったら、その場で依頼文に一文足してから送る。最後の「手戻りゼロ指示テンプレ」を土台にすると、5項目が最初から埋まります。

```text
【AIに頼む前の30秒セルフチェック】

■ ステップ1：目的がブレていないか（10秒）
□ 「何を作るか」を1文で言えるか
  → NO: まず1文にする。「〜な人が〜できるように、〜を作る」の形にはめる
□ 誰が読む／使うのかを書いたか
  → NO: 依頼文に「対象：〜向け」を1行足す
□ 「今日はここまでできれば成功」と言えるか（欲張っていないか）
  → YES: 次へ　→ NO: 範囲を今日ぶんに絞る

■ ステップ2：完成の基準を渡したか（10秒）
□ 数・形式・トーンのうち、最低1つを具体値で書いたか（例：800字／表形式／だ・である調）
  → NO: 一番効く1つだけでも数値・形式で書く
□ 「良い例」と「悪い例（これはNG）」を1つずつ添えたか
  → NO: 悪い例だけでも書く。AIは「やってほしくない方向」を外しやすい
□ 参考にしてほしい既存のもの（過去の資料・似た成果物）を指定したか
  → YES: 次へ　→ NO: あれば貼る。無ければ「参考なし」と明記

■ ステップ3：検証方法を指示に含めたか（10秒）
□ 「どうなったら正しいと分かるか」を書いたか
  → NO: 「完成後に、成功条件を満たしているか自己チェックして一覧で報告して」を足す
□ わざと失敗する例・境界のケースを1つ出させる指示を入れたか
  → NO: 「わざと失敗する入力例も1つ作って、それも試して」を足す
□ いきなり全部作らせず「まず骨子で一度止まって」と書いたか
  → YES: 送信OK　→ NO: 1行足してから送信

────────────────────────

【手戻りゼロ指示テンプレ（この5ブロックをコピーして埋める）】

目的：
　（何を・誰のために。1文で）

対象・前提：
　・使う人／読む人：
　・渡す材料：（あれば貼る。無ければ「無い」）

成功条件（満たせば完成）：
　・
　・（数／形式／トーンのうち最低1つは具体値で）
　・良い例：
　・NG例：

制約・やらないこと：
　・
　・指示に無いことは足さない。推測で埋めた箇所は「ここは推測」と印を付ける

検証方法：
　・
　・完成物と一緒に「作成・変更した箇所の一覧」と「成功条件の自己チェック」を付ける

進め方：
　・まず骨子（見出し／設計／ラフ）だけ出して一度止まる
```

**ポイント**: 3つのステップのうち、初心者がいちばん飛ばしがちなのは「ステップ3（検証方法）」です。ここを1行足すだけで「もっともらしいけど間違っている出力」を自分で見抜けるようになります。


### 2. AIに意図を正確に言わせる 復唱・逆質問プロンプト 厳選10（プロンプト集）
# 作り始める前に「AIの理解」と「あなたの意図」のズレを消すための10本です。どれも、AIが本体を作る前に一度立ち止まらせて、理解の復唱・不明点の質問・推測箇所の申告をさせます。着手後の「そうじゃない」の往復が減り、1回目の成果物の精度が上がります。

# 🎁 AIに意図を正確に言わせる 復唱・逆質問プロンプト 厳選10

作り始める前に「AIの理解」と「あなたの意図」のズレを消すための10本です。どれも、AIが本体を作る前に一度立ち止まらせて、理解の復唱・不明点の質問・推測箇所の申告をさせます。着手後の「そうじゃない」の往復が減り、1回目の成果物の精度が上がります。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 依頼文を書いたら、本体を作らせる前にまず該当する1本を送る。AIの復唱・質問に答えてから「では進めて」と伝える。

```text
────────────────────────────────
01. まず理解を復唱させる（全用途の基本）
────────────────────────────────
期待できるメリット：AIの解釈があなたの意図とずれていないかを、着手前の1分で確認できる。ズレたまま完成→やり直し、の一番大きな手戻りを防げる。
使う場面：文章・資料・コード・調査など、少しでも分量のある依頼をする直前。
前提：依頼文（目的・成功条件など）を用意していること。
指示（そのまま貼る）：
　これから依頼を渡します。まだ本体は作らないでください。最初に、あなたの理解を「何を／誰のために／どうなったら完成か」の3点で箇条書き復唱してください。次に、私の依頼で曖昧または未指定だと感じた点を質問の形で3〜5個挙げてください。最後に、あなたが自分の推測で埋めるつもりの箇所を先に教えてください。
出力形式：「復唱（3点の箇条書き）」「質問（3〜5個）」「推測で埋める箇所」の3見出しで返す。本文の作成はしない。
つまずきどころ：AIが復唱を飛ばして作り始めたら「本体は不要。復唱と質問だけ」と一度突き返す。

────────────────────────────────
02. 「完成の基準」をAIに提案させる
────────────────────────────────
期待できるメリット：成功条件をうまく言葉にできないときでも、AIが3案出してくれるので、選ぶだけで基準が決まる。「なんとなく良い感じ」で発注する事故がなくなる。
使う場面：作りたいものは決まっているが、どうなったら"OK"なのか自分でも詰め切れていないとき。
前提：作りたいものの種類（文章／コード／画像など）が決まっていること。
指示（そのまま貼る）：
　この依頼の「完成の判定基準」を、あなたが3パターン提案してください。それぞれ、数・形式・トーン・含めるべき要素・除外すべき要素の観点で具体的に書いてください。提案だけで、本体はまだ作らないでください。私が1つ選ぶか修正します。
出力形式：基準A／B／Cの3ブロック。各ブロックに「数・形式・トーン・必須要素・NG要素」の5項目。
つまずきどころ：3案が似すぎていたら「もっと振れ幅を付けて。厳しめ・ゆるめ・変化球で」と指定し直す。

────────────────────────────────
03. 前提の不足だけを洗い出させる
────────────────────────────────
期待できるメリット：自分では「十分書いた」つもりの依頼から、抜けている前提だけを短時間で発見できる。後出しで前提を足して作り直す往復が減る。
使う場面：依頼文をひと通り書き終えて、送る前の最終チェックとして。
前提：依頼文があること。
指示（そのまま貼る）：
　次の依頼文を読んで、作業を始めるために足りていない前提情報だけをリストにしてください。各項目について「なぜそれが必要か」を一言添えてください。あなたの意見や改善案は不要です。不足の指摘だけに絞ってください。まだ本体は作らないでください。
出力形式：「不足している前提／なぜ必要か」の2列リスト。
つまずきどころ：AIが改善提案を混ぜてきたら「提案は削除。不足の事実だけ」と伝える。「〜という前提でよいか？」の確認文が並ぶのが正常。

────────────────────────────────
04. 推測で埋めた箇所に印を付けさせる
────────────────────────────────
期待できるメリット：完成物のうち「あなたが指示していないのにAIが決めた部分」がひと目で分かる。そこだけ集中して直せるので、全体を読み直す手間が省ける。
使う場面：ある程度おまかせで作らせるが、後から責任を持ってチェックしたいとき。
前提：本体を作らせるフェーズ。
指示（そのまま貼る）：
　作成するとき、私が明示的に指示していない箇所（あなたが推測・裁量で決めた箇所）には、文末に【推測】と印を付けてください。完成後に、【推測】箇所だけを抜き出した一覧を「箇所／あなたが選んだ内容／他に考えられた選択肢」の表で添えてください。
出力形式：本体＋末尾に【推測】一覧の表。
つまずきどころ：印が多すぎる場合は依頼の前提が薄い合図。02や03で基準・前提を足してからやり直す。

────────────────────────────────
05. 「わざと失敗する例」を先に作らせる
────────────────────────────────
期待できるメリット：正しく動く例だけでなく「うまくいかない入力・境界のケース」を先に出させることで、AIが見落としがちな穴を着手前に共有できる。公開後に事故る種類のミスを予防できる。
使う場面：フォーム・自動化・集計・チェックツールなど「変な入力」が来うるものを作るとき。
前提：作るものの入力と出力のイメージがあること。
指示（そのまま貼る）：
　本体を作る前に、この成果物が「うまく扱えないと困る入力・境界のケース」を5つ挙げてください。空欄、極端に長い入力、想定外の形式、権限のないユーザー、同時操作、などの観点で。各ケースに「望ましい振る舞い」も1行で書いてください。その後で本体を作り、これら5ケースも通るようにしてください。
出力形式：「ケース／望ましい振る舞い」の5行 →（承認後）本体。
つまずきどころ：5ケースが浅い場合は「実際に事故る例を。教科書的な例は不要」と促す。

────────────────────────────────
06. 骨子だけ出させて一度止める
────────────────────────────────
期待できるメリット：全部作ってから方向性のズレに気づく、を防げる。骨子の1分レビューで軌道修正できるので、完成後の大きな書き直しがなくなる。
使う場面：長めの文章・複数ファイルのコード・章立てのある資料など、分量が出るもの。
前提：目的と対象が決まっていること。
指示（そのまま貼る）：
　いきなり完成形は作らないでください。まず骨子だけ出して、そこで一度止まってください。文章なら見出しと各節の要点1行、コードなら構成（ファイル・関数の役割）とデータの流れ、資料ならページ構成。私がOKを出すか修正したら、続きを作ってください。
出力形式：骨子（箇条書き or 構成図の文字表現）のみ。「ここまでで一度確認してください」で終える。
つまずきどころ：骨子なのに中身まで書き始めたら「要点1行まで。本文は書かない」と制限する。

────────────────────────────────
07. 2つの解釈を並べて選ばせる
────────────────────────────────
期待できるメリット：あなたの依頼文が2通りに読める場合に、AIが勝手に片方で突き進むのを防げる。5秒で選ぶだけで解釈のズレが消える。
使う場面：短い依頼・専門用語が混ざる依頼・「いい感じに」を含む依頼のとき。
前提：依頼文があること。
指示（そのまま貼る）：
　次の依頼は複数の意味に取れる可能性があります。あなたが考えられる解釈を2〜3通り挙げ、それぞれ「この解釈だと成果物はこうなる」を1行で示してください。私がどれかを選びます。選ぶまで作業は始めないでください。
出力形式：解釈1／2／3、それぞれ「意味／その場合の成果物」。
つまずきどころ：解釈が1つしか出てこなければ、その依頼は明確。そのまま進めてよい。

────────────────────────────────
08. 「やらないこと」を先に言語化させる
────────────────────────────────
期待できるメリット：禁止事項を自分で全部書き出せなくても、AIに「やりがちだが今回は不要なこと」を挙げさせて、着手前に×を付けられる。余計な機能・誇張・脱線を防げる。
使う場面：範囲が広がりやすい依頼（「ついでにこれも」となりがちなもの）。
前提：目的が決まっていること。
指示（そのまま貼る）：
　この依頼で、あなたが「よかれと思って足しがちだが、今回は指示されていないこと」を5つ挙げてください。私が「これは不要」「これは入れて」を判断します。判断が終わるまで本体は作らないでください。
出力形式：「足しがちな要素／なぜ足したくなるか」の5行。
つまずきどころ：挙がった項目に自分で「不要／必要」を必ず返す。曖昧なままだとAIは"必要"側に倒しがち。

────────────────────────────────
09. 完成後の自己チェックを義務づける
────────────────────────────────
期待できるメリット：成果物と一緒に「成功条件を満たしているか」のAI自己採点が付くので、あなたが1から全部読み返さなくても、怪しい箇所に当たりを付けられる。
使う場面：チェックの時間が取りにくいとき／成果物が長いとき。
前提：成功条件を渡していること。
指示（そのまま貼る）：
　完成物の最後に「自己チェック」を付けてください。私が渡した成功条件を1項目ずつ再掲し、それぞれ「満たす／一部/満たさない」と、その根拠（本文の該当箇所）を書いてください。満たさない項目があれば、直す前にまず正直に報告してください。
出力形式：本体＋末尾に「成功条件／判定／根拠」の表。
つまずきどころ：全項目が「満たす」で根拠が薄いときは、AIが機械的に○を付けている合図。1〜2項目を指定して「その根拠を本文から引用して」と確認する。

────────────────────────────────
10. 引き継ぎメモを一緒に書かせる
────────────────────────────────
期待できるメリット：後日の自分や他の人が「なぜこの作りになっているか」を思い出せる。意図が消えて作り直す、を防げる。仕様が"バージョン管理される成果物"になる。
使う場面：あとで修正・拡張する前提のもの／チームで共有するもの。
前提：本体を作らせるフェーズ。
指示（そのまま貼る）：
　完成物と一緒に、短い引き継ぎメモを作ってください。「この成果物の目的」「満たしている成功条件」「あえてやらなかったこと」「未解決・保留にした点」「次にやるなら何から」の5項目を、それぞれ1〜3行で。専門用語には一言注釈を付けてください。
出力形式：本体＋「引き継ぎメモ」（5見出し）。
つまずきどころ：メモが本文の要約になっていたら「決定の理由と保留点を。要約は不要」と指定し直す。
```

**ポイント**: 10本すべてに共通する狙いは「作らせる前に一度止める」こと。止めるのは1〜2分で済み、そこで見つかったズレ1つが、完成後なら数十分の書き直しになります。
