# 🎁 オープンウェイト ライセンス罠チェックリスト

「オープンウェイト」「無料公開」という言葉だけで飛びつくと踏みやすい落とし穴を、事前に確認するためのチェックリストです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 新しいオープンウェイトモデルを導入する前に、上から順に確認してください。

```text
【オープンウェイト ライセンス罠チェックリスト】

■ ステップ1：「オープン」の中身を確認する
□ 重みが公開されているだけで、学習データ・訓練レシピは非公開ではないか？
  → YES: 完全なオープンソースではなく「オープンウェイト」止まりと理解する（再現・監査はできない前提で使う）
□ ライセンスはOSI（Open Source Initiative）承認のものか、独自ライセンスか？
  → 独自ライセンスの場合: 一般的なOSSライセンスとは権利範囲が異なる可能性がある。次のステップで条件を個別に確認する

■ ステップ2：商用利用の条件を確認する
□ 売上・収益の規模によって商用利用の可否が変わる条項はないか？
  → YES: 自社の年間売上が閾値（例: 2,000万ドル）を超えていないか確認する
  → 指示例: 「このライセンス文書を読み込んで、商用利用が制限される条件（売上・従業員数・利用規模など）をすべて日本語で抽出して」とAIに確認させる
□ 別途の許諾・契約が必要になるケースが明記されているか？
  → YES: 該当する場合は、実際に使い始める前に許諾申請の窓口・所要期間を調べておく

■ ステップ3：地域・利用者の制限を確認する
□ 利用可能な地域（Applicable Territory等）が限定されていないか？
  → YES: 自社・自分が該当地域に含まれるか確認する。除外地域からの利用は規約違反になる可能性がある
□ 特定の国・地域のユーザーを名指しで除外していないか？
  → YES: 除外理由（多くは進行中の訴訟リスクなど）を確認し、将来条件が変わる可能性も踏まえておく

■ ステップ4：帰属表示・クレジット表記の要否を確認する
□ 商用利用時にライセンス表記（クレジット）が必須とされていないか？
  → YES: 表記の書式・掲載場所（製品内・Webサイト等）の指定があるか確認し、公開前に対応する
□ 表記を省略した場合の扱いが明記されているか？
  → YES: 違反時のペナルティ（利用停止・損害賠償等）の有無も確認しておく

■ ステップ5：生成物の著作権・利用範囲を確認する
□ このモデルで生成したコンテンツ（画像・動画・コード等）の著作権は誰に帰属するか明記されているか？
  → 不明確な場合: 商用の最終成果物に使う前に、法務・契約担当に確認する
□ 生成物に第三者の著作権物が意図せず含まれるリスクについて、モデル提供元が何らかの免責・注意喚起をしているか？
  → YES: 生成物をそのまま公開せず、人の目でのチェック工程を挟む運用にする

■ ステップ6：将来の変更リスクに備える
□ ライセンス条件が将来変更される可能性について、契約書やFAQに言及があるか？
  → YES: 変更時の通知方法・既存利用者への猶予期間があるか確認しておく
□ 導入判断の根拠（確認したライセンス条件・確認日）を記録として残しているか？
  → NO: 指示例:「今日確認したこのモデルのライセンス条件を、確認日つきで社内共有用に1枚のメモにまとめて」とAIに整理させ、記録を残す
```

**ポイント**: ライセンス文書は英語かつ長文であることが多いため、AIに要約・条件抽出を手伝わせつつ、最終判断は必ず原文と法務担当で確認してください。
