# 🎁 「AIに任せる前」安全＆品質チェックリスト

個人情報を扱う自動化を、事故らせずに作って人に渡すための確認手順です。「作る前」と「動かす・渡す前」の2フェーズに分けて、AIへ渡してよいデータの判定、APIキーの管理、無料/有料ティアの選択、AI出力の免責、送信上限まで、YES/NO で判断できる形にしました。動画の仕組みだけでなく、GAS + 外部AI を使う自動化すべてに使えます。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 自動化を作り始める前に「作る前フェーズ」を、実際に動かす前・お客様や同僚に渡す前に「渡す前フェーズ」を、上から順に確認します。□ がすべて埋まるまでリリースしないのが目安です。

```text
【AIに任せる前 安全＆品質チェックリスト】

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ フェーズ1：作る前（設計を決める段階で確認する）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ ステップ1：AIに渡すデータの棚おろし
□ この自動化で外部AI（Gemini・ChatGPT等）に送るテキストに、氏名・連絡先・
  志望動機・病歴・口座番号などの個人情報が含まれるか
  → YES: 「その情報は本当にAIに送る必要があるか」を1項目ずつ見直す。
    要約に不要な列（電話番号・住所など）はAIに渡さず、担当者通知にだけ載せる設計にする。
□ 送るデータに、自社の未公開情報（単価・与信・人事評価）が混ざっていないか
  → YES: その列はAI処理の対象から外し、コードに「この列は送信しない」とコメントで明記する。
  指示例: 「F列の志望動機だけをAIに送り、D列の電話番号とE列の住所は送信しないでください」

■ ステップ2：無料ティアか有料ティアかを決める
□ 使うAIの無料枠は「入力を製品改善（学習）に使う」規約になっているか
  （Gemini API の無料ティアは「Content used to improve our products」と明記）
  → YES: 個人情報を送るなら、有料ティアに切り替えるか、応募者・顧客へ
    「AIで内容を要約します」と事前に断る文言をフォームに入れる。
□ 想定する処理件数で、無料枠のレート上限（1分あたり・1日あたりのリクエスト数）に
  収まるか
  → YES: そのまま無料枠で開始してよい。上限が近い場合は有料ティア（請求先アカウントの
    リンク）に上げる前提でコストを試算しておく。

■ ステップ3：APIキーの置き場所を決める
□ APIキーをスプレッドシートのセルや、コード本文に直書きしていないか
  → YES: 最低限、キーは「設定」シートの1セルにまとめ、そのシートを共有範囲から外す。
    可能なら Apps Script の「スクリプト プロパティ」に移し、コードからは名前で呼び出す。
  指示例: 「APIキーはコードに直書きせず、スクリプトプロパティ『GEMINI_API_KEY』から
    読み込む形にしてください」
□ このシート/ファイルを誰かに渡す予定があるか
  → YES: 渡す前にキーを削除する手順を、運用マニュアルの1行目に書く。

■ ステップ4：AIが失敗したときの挙動を決める（エラー分離）
□ AI処理が失敗したとき、業務の本筋（返信・登録・通知）まで一緒に止まる作りになって
  いないか
  → YES: AI処理と本筋の処理を別々の try-catch に分けるよう仕様書に明記する。
  指示例: 「自動返信とAI要約は必ず別のtry-catchに分け、AI要約がエラーでも自動返信は
    止めないでください。要約失敗時は『要約なし（APIエラー）』と記録し、原文つきで
    担当者へ通知してください」
□ AI処理が失敗したことに、運用者が気づける仕組みがあるか
  → YES: 失敗時はステータス列に印を残す、または管理者へ1通通知する、を仕様に足す。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ フェーズ2：動かす・渡す前（リリース直前に確認する）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ ステップ5：AI出力の品質と免責
□ AIの要約・分類・下書きを、人間の確認なしで最終判断（合否・与信・可否）に
  使っていないか
  → YES: その使い方をやめる。AI出力は「担当者が判断しやすくする参考情報」に留める。
□ AI出力を人に見せるメール・画面に、「AIによる生成。誤りを含む場合があります。
  最終判断には使わないでください」の一文が入っているか
  → YES: 入っていなければ、通知メールのテンプレートに固定文として追加する。
□ AI出力を10件ほど手で確認し、明らかな取りこぼし（資格・勤務条件の見落とし等）が
  ないか
  → YES: 取りこぼしがあれば、要約プロンプトに「資格・夜勤可否・勤務日は必ず拾う」等の
    ルールを足して再テストする。

■ ステップ6：送信・実行の上限
□ 1日に送るメール数が、使うアカウントの上限内か
  （Apps Script の一般アカウントは 100通/日、Google Workspace は 1,500通/日）
  → YES: 上限に近いなら Workspace アカウントに切り替えるか、送信を複数日に分ける。
□ 1回の処理が、スクリプトの実行時間上限（6分/回）に収まるか
  → YES: 収まらないなら、処理する行数を分割する（例：1回50行ずつ）よう仕様に足す。
□ 時間主導トリガーで自動実行する場合、トリガー合計の実行時間上限
  （一般 90分/日、Workspace 6時間/日）に収まるか
  → YES: 収まらないなら実行間隔を広げる。

■ ステップ7：渡す前の最終確認
□ 共有するシート/ファイルから、APIキー・自分の個人メール・テスト用の本番データを
  消したか
  → YES: 消したうえで、共有範囲を「必要な人のみ・編集可は最小限」に設定する。
□ 受け取る人向けに「AI要約は参考情報／個人情報を含むので共有範囲を絞る／
  APIキーは他人に見せない」の3点を明記した1枚メモを添えたか
  → YES: 添える。口頭だけで済ませない。
□ 生成されたコードを、AI任せにせず自分で1回通し読みしたか
  （送信先アドレスの取得元、対象行の条件、上書きする列が意図どおりか）
  → YES: 読んで問題なければリリース。1つでも不明な箇所があれば、その部分を
    AIに「この行は何をしていますか。初心者向けに説明して」と聞いてから判断する。
```

**ポイント**: このリストの半分は「AIに何を送らないか」を決める作業です。要約に不要な個人情報は最初からAIに渡さない設計にすると、無料/有料ティアの悩みも共有事故のリスクもまとめて小さくなります。

# 🎁 採用対応 自動化ワークシート

動画で作る「応募が入ると自動返信 → AIが要約 → 担当者へ通知」の仕組みが丸ごと入った Google スプレッドシートです。応募シート・設定・プロンプト集・動作確認済みのコード見本・完成形見本の6タブ構成。「ファイル → コピーを作成」で、その日から自分のドライブで使えます。

**受け取り方**: 下のリンクを開き、Google にログインした状態で「ファイル」→「コピーを作成」。元のシートは閲覧のみなので、必ずコピーしてから編集してください。

**使い方**: コピーしたシートの「①使い方」タブを上から読む → 「④プロンプト集」の文をコピーして Codex（またはお使いのコーディングAI）に貼る → 返ってきたコードを「拡張機能 → Apps Script」に貼って実行、の順です。

```text
■ 配布ワークシート（Google スプレッドシート・閲覧のみ → コピーして使用）
https://docs.google.com/spreadsheets/d/17E5lZTQjU_bb9yz3qI0_uTNSdmNlvhUf4Uv4WIbvvWQ/edit

■ 6つのタブと使う順番

① 使い方
   今日つくるものの全体像、進め方（第1形態 → 第2形態）、事前課題（Google AI Studio で
   無料 APIキーを取得）、運用上の約束3点（AI要約は合否判断に使わない／シート共有は
   採用担当のみ／APIキーは消してから共有）。まずここを読む。

② 応募シート
   フォーム回答を想定したメインの管理表。田中・鈴木のサンプルが2件入っている。
   第1形態の練習では、2行目のメールアドレスを「自分の Gmail」に書き換えて実行する
   → 自分宛に面接案内が届く。第2形態では F列（志望動機）に自分の言葉を1〜2行足してから
   実行する → 自分が書いた文章の AI要約が担当者通知として届く。

③ 設定
   コードを触らずに運用する場所。B3=Gemini APIキー（第2形態で使用）、
   B4=担当者メールアドレス（練習中は自分の Gmail）、B5=自動返信の件名、
   B6=自動返信の本文（本文中の {氏名} は送信時に応募者名へ自動で置き換わる）。
   お客様（施設）に渡すときは、ここだけ書き換えてもらえば運用できる設計。

④ プロンプト集
   Codex に貼る文が3本入っている。
   プロンプト①＝第1形態（自動返信マシン）を作る文。
   プロンプト②＝動いているコードに「AI要約＋担当者通知」を追加する文。
     最重要の設計条件として「自動返信とAI要約を別のtry-catchに分ける」「Gemini がエラーでも
     応募者への自動返信は絶対に止めない」「要約失敗時は『要約なし（APIエラー）』と書き、
     原文つきで担当者へ通知する」が明記されている。
   プロンプト③＝エラーが出たときのお直し用。エラーメッセージを貼る欄がある。

⑤ GASコード見本
   第1形態と完成形態それぞれの、動作確認済みコード。プロンプトでうまく生成できなかった
   ときは、これをコピーして「拡張機能 → Apps Script」に貼れば動く。

⑥ 完成形見本
   実行後にこうなればOK、という見本。田中＝AI要約が成功、鈴木＝「要約なし（APIエラー）」。
   鈴木の行は失敗例ではなく、エラー分離設計が効いて「AIが止まっても自動返信と担当者通知は
   届いている」状態を見せている。

■ よくあるつまずき
・元シートを直接編集しようとして書き込めない → 「コピーを作成」してから編集する。
・第1形態で自分にメールが来ない → ②応募シートのC列（メール）が自分の Gmail になっているか、
  H列（自動返信）が空か（既に「送信済み」だとスキップされる）を確認する。
・第2形態で要約が空になる → ③設定 B3 の APIキーが「AIza…」で始まる正しい文字列か確認する。
  それでも空なら、エラー分離設計どおり「要約なし（APIエラー）」と出るのが正常。
・人にシートを渡すとき → ③設定 B3 の APIキーを必ず消してから共有する。
```

**ポイント**: このシートは「介護施設の採用」を例にしていますが、②の列構成と③の文面を差し替えれば、日程調整・資料請求対応・予約受付など、他の「受け取って返す」業務にそのまま転用できます。
