# 🎁 Cursorユーザーの11月前 やることチェックリスト

Cursor で GPT（OpenAIのモデル）を使っている人が、2026年11月12日の提供停止（予定）までに何をすればいいかを、上から順に手を動かせる形にまとめたチェックリストです。「自分が GPT にどれだけ頼っているかの確認 → 既定モデルの乗り換え → APIキー持ち込みの手順と限界 → 指示文の作り直し → 記録の保存」の5ステップ構成。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 上から順に □ を確認し、`→ YES:` の行動を実行します。`指示例:` はそのまま AI（Cursor のチャットや他の AI）に貼って使える指示文です。全部を一度にやる必要はなく、ステップ1〜2を今日、3〜5を11月12日までに、が目安です。

```text
【Cursorユーザーの11月前 やることチェックリスト】

前提：2026年8月28日、OpenAI は Cursor へのモデル提供契約を打ち切ると発表した。
停止の「予定日」は2026年11月12日。両社は交渉中で確定ではないが、決裂すればその日で
Cursor から GPT 系モデルが使えなくなる。影響を受けるのは Cursor 利用の約5%（Cursor CEO 発言）。
ChatGPT や、OpenAI の API を直接使う他ツールには影響しない（Cursor の中だけの話）。


■ ステップ1：自分が GPT に依存しているか確認する

□ Cursor の設定 → Models（モデル一覧）を開いた
□ ふだんチャット／エージェントで選んでいるモデル名を確認した
 → YES（GPT / gpt- で始まる名前が中心）: このリストを最後まで実施する
 → YES（Claude / Gemini / Grok が中心）: 影響はほぼ無い。ステップ5だけ流し読みで良い

□ 直近1〜2週間の作業で、GPT でないと困った場面があったか思い出した
 → YES（特に無い）: 乗り換えは軽い。ステップ2で完了できる
 → YES（この用途は GPT が良かった、が複数ある）: ステップ3（APIキー）まで想定しておく

指示例: 「私は Cursor でコード補完とチャットに主に使っています。直近の私の使い方から、GPT を Claude か Gemini か Grok に替えたとき影響が大きそうな作業を挙げて、それぞれ代替案を教えてください。」


■ ステップ2：既定モデルを乗り換える（今日〜今週）

□ 既定モデルの候補を1つ決めた（下の目安を参考に）
 ・Claude（Anthropic）: コード用途で選ばれることが多い。もともと Cursor 利用の多数派
 ・Gemini（Google）: 今回の件と無関係。そのまま使える
 ・Grok（xAI）: 2026年7月8日から Cursor 全プランに搭載済み。SpaceXAI 製
□ Cursor の設定で既定モデルを上記に変更した
□ ふだんの作業を2〜3件、新しい既定モデルで実際に流してみた
 → YES（問題なし）: 乗り換え完了。ステップ4・5へ
 → YES（品質や挙動が変わって気になる）: もう1社を試す。それでも GPT が要るならステップ3へ

指示例: 「次の作業を、モデルを替えても同じ結果が出るように指示文を調整してください。対象作業：__（例：関数のリファクタと単体テスト生成）__。特定モデル名や、そのモデル固有の言い回しに依存しない書き方にしてください。」


■ ステップ3：どうしても GPT が要るなら、自分の API キーを用意する（10月中）

□ OpenAI のアカウントで API キー（利用の窓口になる文字列）を発行した
□ 支払い方法・使用量の上限を OpenAI 側で設定した（使った分だけ OpenAI に直接支払う形）
□ Cursor の設定で、その API キーを登録した
□ チャット／エージェントで GPT 系モデルが選べる・応答が返ることを確認した
 → YES: 当面の GPT 利用は確保できた。ただし下の注意を必ず読む
 → NO（機能によって使えない）: それは仕様の可能性が高い。ステップ2の乗り換えを主にする

【注意】API キー持ち込みでカバーされない範囲がある
 ・自動補完やエージェント系など、一部の機能はキーを入れても対象外とされている
 ・停止後にどこまで動くかは、OpenAI も Cursor も詳細を公表していない（2026年8月末時点）
 ・「キーを入れれば全部これまで通り」とは考えず、ステップ2の乗り換えと併用する

指示例: 「OpenAI の API キーを自分で発行して Cursor に登録する手順を、公式ドキュメントの用語に沿って順番に教えてください。あわせて、キーを登録しても使えない可能性がある機能を一覧にしてください。」


■ ステップ4：GPT 前提の指示文・設定を作り直す（11月12日まで）

□ よく使う指示文（プロンプト）を10個ほど、テキストファイルに書き出した
□ その中で「GPTだから通っていた書き方」を洗い出した
  （例：特定モデル名を指名している／そのモデル特有の出力形式を前提にしている）
□ 各指示文を、モデルを問わず通る書き方に直した
□ Cursor のルールファイル（.cursor/rules 等）に GPT 前提の記述がないか確認した
 → YES（直した）: どのモデルに切り替えても同じ品質を狙える状態になった

指示例: 「次の指示文セットを見て、特定の AI モデルに依存している箇所を指摘し、モデルを問わず同じ意図で動くように書き直してください。出力は『元の文／問題点／書き直し版』の3列の表で。指示文：__ここに貼る__」


■ ステップ5：大事な記録を手元に残す（11月12日まで）

□ GPT と作った重要なやり取り・生成物を、手元（ローカルのファイル）に保存した
□ よく使う指示文・設定を、Cursor の外にもコピーした
□ プロジェクトごとの「AIへの前提説明」を、1枚のメモにまとめた
□ 定期的にエクスポートする日（例：毎月1日）を決めてカレンダーに入れた
 → YES: ツールや契約が変わっても、積み上げを持ち出せる状態になった

指示例: 「このプロジェクトで私が AI に毎回説明している前提（構成・命名規則・やってほしくないこと）を、新しいモデルや別ツールにそのまま渡せる1枚の説明メモにまとめてください。」


■ 補足：情報の追い方

□ 「11月12日」は OpenAI の提案であって確定ではない。前倒し・延期・和解もありうる
□ ただし「何もせず待つ」のは避ける。決裂したらその日で止まる前提で準備する
□ Cursor / OpenAI の公式発表を月1で確認する（運営や規約の変更を早めに知るため）

指示例: 「Cursor と OpenAI の、Cursor 向けモデル提供に関する最新の公式発表を調べて、11月12日の予定に変更があったかどうかだけを、日付つきで簡潔に教えてください。」
```

**ポイント**: ステップ2まで終えれば、多くの人は「11月12日を過ぎても普通に使える」状態になります。ステップ3（APIキー）は"どうしても GPT でないと困る作業がある人"だけの保険で、全機能はカバーされない点に注意してください。
