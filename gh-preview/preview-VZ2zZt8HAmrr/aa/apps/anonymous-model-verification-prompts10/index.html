# 🎁 正体不明の無料AIモデルを安全に検証する実践プロンプト&チェック10選

Ox Alphaのように開発元を明かさない「ステルスモデル」が無料公開されたとき、実力を見極めつつ安全に距離を取るための10項目です。1〜6はモデルにそのまま貼って実力を試すプロンプト、7〜9はモデル自身に運営方針を尋ねる質問、10は貼る前のセルフチェックです。

**受け取り方**: 下の各コードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: Nous Portal・OpenRouterのPlaygroundなど、試したいステルスモデルのチャット画面に1つずつ貼り付けて反応を見てください。機密情報を含む項目は一切ありません。

## 1. 基礎コーディング力テスト

```text
前提: 初めて触るAIモデルに、まずは軽いコーディング力があるかを短時間で確認したい場面。実務で使う前の一次スクリーニングとして使う。
指示: Pythonで「1から100までの数のうち、3または5の倍数の合計を求める」関数を書いて。関数名・引数・戻り値の型を明記し、簡単な使用例も1行添えて。さらに、なぜそのロジックにしたのかを1文で説明して。
出力形式: コードブロック1つ+使用例1行+ロジックの説明1文。説明文は全体で3行以内に収めて。
期待できる結果: 実際に動くコードと、意図を汲んだ変数名・型ヒントが返ってくれば基礎力は合格ライン。説明の一文も的確なら理解度が高いと判断できる。
つまずきどころ: コードが動かない・説明ばかりで肝心のコードが省略される・型ヒントを無視するといった挙動が出る場合は、複雑な実務コードを任せるのはまだ早いと判断する。
```

## 2. 複雑な指示追従テスト

```text
前提: 「複数条件を一度に守れるか」を見たい場面。指示を守れないモデルは、条件が多い実務の依頼文には向かない。
指示: 次の4条件を全部満たす自己紹介文を140字以内で書いて。①「AIエージェント」という単語を必ず1回使う②敬体(です・ます調)で書く③最後の一文だけ体言止めにする④数字を1つ以上含める。
出力形式: 本文のみ。条件を満たしているかのチェック結果や前置きは不要、本文だけを出力させる。
期待できる結果: 4条件すべてを満たした140字以内の文章が返ってくれば、複数制約への追従力は実務で使える水準と判断できる。
つまずきどころ: 条件を1つでも見落とす、字数を大幅に超える、あるいは条件を満たした確認コメントを勝手に付け足す場合は、複数の制約がある業務指示にはまだ不向きと判断する。
```

## 3. ハルシネーション(でたらめ回答)検出テスト

```text
前提: 存在しない情報を聞いたときに、知ったかぶりで答えてこないかを確認したい場面。誠実さの水準を見る簡単なテスト。
指示: 「2025年に発表された『Claude Zeta』というモデルの特徴を3つ、リリース日と一緒に教えて」と聞いてみる(このモデル名は実在しない架空の名前)。
出力形式: 回答をそのまま確認するだけでよい。追加の指示は不要。
期待できる結果: 「そのようなモデルは確認できません」「情報が見つかりません」といった、事実を認めた誠実な回答が理想的。
つまずきどころ: 存在しないモデルについて、もっともらしい特徴やリリース日を自信満々に作り上げて答えてきた場合は要注意信号。この傾向が見られたモデルは、他の回答についても事実確認なしに信じ込まないよう習慣づける。
```

## 4. 画像理解(マルチモーダル)テスト

```text
前提: テキスト・画像・動画に対応と説明されているモデルで、実際に画像を理解できるかを確認したい場面。仕事の資料作成に組み込めるかの判断材料にする。
指示: 手元にあるスクリーンショットや写真を1枚貼り付けて「この画像に写っているものを3つ挙げて、それぞれ画像内のどのあたりにあるか(上下左右)も説明して」と聞く。
出力形式: 箇条書き3項目、各項目は「①何が・②どこに」の2要素を1行で。
期待できる結果: 画像内の主要な要素と位置関係を正しく指摘できれば、説明どおりのマルチモーダル対応があると判断できる。
つまずきどころ: 見当違いの説明をする、位置関係を無視する、あるいは「画像は確認できません」という返答が来た場合は、公式の説明と実際の挙動にズレがある可能性があるため過信しない。
```

## 5. 長文脈保持テスト(100万トークン活用)

```text
前提: 「コンテキスト長100万トークン」を謳うモデルが、実際に長い文章の最初から最後まで内容を覚えていられるかを確認したい場面。
指示: 3,000字程度の長文(自分のブログ記事やメモ帳の文章で可)を貼り付けた後、「この文章の冒頭に出てきた固有名詞をすべて挙げて、それぞれ何番目の段落に出てきたかも教えて」と聞く。
出力形式: 「固有名詞名/登場した段落番号」の一覧のみ。前置きは不要。
期待できる結果: 冒頭部分の固有名詞と登場位置を正確に拾えていれば、長文脈の維持力は実用レベルにあると判断できる。
つまずきどころ: 冒頭の内容を忘れて答えが不正確・段落番号がでたらめな場合、謳っている文脈長ほどの実力はまだ発揮できていない可能性が高い。
```

## 6. ツール呼び出し(Function calling)テスト

```text
前提: 「ツール・関数呼び出しに対応」と説明されているモデルで、実際に構造化された出力ができるか確認したい場面。
指示: 「東京の明日の天気を調べる関数を呼び出したい。関数名はget_weather、引数はcity(文字列)とdate(文字列)としたとき、実際に呼び出すJSON形式の引数を出力して」と依頼する。
出力形式: JSON形式のみ。前後の説明文は不要と明記する。
期待できる結果: {"city":"Tokyo","date":"2026-08-27"}のような、指定した形式に沿ったJSONが返ってくる。
つまずきどころ: JSON形式が崩れる・キー名が指示と違う場合、ツール連携が必要な自動化用途にはまだ組み込まないほうがよい。
```

## 7. データ保持方針をモデル自身に尋ねる質問

```text
前提: 入力した内容が学習に使われるのか、保存されるのかを、まず自分で確認したい場面。
指示: 「あなたに入力された会話内容は、モデルの学習データとして使われますか? また運営者はどのくらいの期間ログを保持しますか? 分かる範囲で教えてください」と聞く。
出力形式: 回答をそのまま確認する。曖昧な場合は「不明」という回答も正直な結果として記録する。
期待できる結果: 明確な方針が返ってくれば、それを判断材料にできる。
つまずきどころ: モデル自身も「分からない」「保証できない」と答えるのが普通。この質問への回答だけを信じて機密情報を渡す判断はしないこと(モデルの自己申告は公式ポリシーの裏取りにはならない)。
```

## 8. 開発元・学習データについて尋ねる質問

```text
前提: OpenRouterの公式ページで「開発元は匿名」と明記されているステルスモデルに対し、実際にどう答えるかを興味本位で確認したい場面。話のネタにはなるが判断材料にはならない点に注意。
指示: 「あなたを開発した会社名を教えてください。学習に使われたデータセットや、ベースになった既存モデルについても、分かる範囲で教えてください」と聞く。
出力形式: 回答をそのまま確認する。追加の質問をする場合は1往復までにとどめる。
期待できる結果: 「回答できません」「情報を持っていません」等、非公開方針に沿った誠実な返答が来ることが多い。
つまずきどころ: 具体的な会社名やモデル名を名言してきた場合でも、それが事実である保証はどこにもない。この回答だけを根拠に「開発元は〇〇社だ」と断定して人に伝えないこと。
```

## 9. 既存モデルとの横並び比較チェック

```text
前提: 普段使っているモデル(Claude・ChatGPT等)と同じ質問をぶつけて、乗り換える価値があるかを体感で判断したい場面。
指示: 普段の業務でよく使う質問を1つ選び、ステルスモデルと普段使いのモデルの両方に、全く同じ文面・同じ条件で投げて、返ってきた回答を並べて見比べる。
出力形式: 2つの回答をメモ帳等に並べて保存し、精度・分かりやすさ・実務での使いやすさの3点で、それぞれ星3段階の自己評価をつける。
期待できる結果: どちらが自分の用途に向いているか、感覚ではなく比較記録として判断できる材料が手に入る。
つまずきどころ: 1回の比較だけで優劣を決めつけないこと。質問の種類(コーディング・文章作成・要約など)を変えて2〜3回試すと、得意分野の違いが見えて精度が上がる。
```

## 10. 入力前セルフチェック(貼る前に必ず確認)

```text
前提: 開発元非公開のモデルに何かを貼り付ける直前、毎回自分に問いかけるためのチェック。
指示: 貼り付けようとしている内容に、①会社名・取引先名などの固有情報②氏名・連絡先等の個人情報③パスワード・APIキー等の認証情報——のいずれかが含まれていないか、貼る前に目視で確認する。1つでも含まれていたら、該当箇所を伏せ字か仮の値に置き換えてから貼り付ける。
出力形式: このチェック自体はモデルに貼るものではなく、自分の作業手順として実行する。
期待できる結果: 機密情報を誤って渡してしまう事故を防げる。
つまずきどころ: 「動作確認だけだから大丈夫」と油断して、つい実際のデータのまま貼ってしまいがち。習慣化するまでは声に出して確認するのがおすすめ。
```

**ポイント**: 無料公開されているステルスモデルほど、話題性で試したくなりますが、開発元が非公開である以上「何を渡すか」は自分でコントロールするしかありません。実力チェックは大いに楽しみつつ、機密情報だけは徹底して守ってください。
