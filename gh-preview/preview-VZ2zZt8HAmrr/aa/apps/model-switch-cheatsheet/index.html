# 🎁 不調時の代替モデル早見表

メインのAIモデルが不調に感じるとき、何を基準に・どこへ一時的に逃がすかを整理した早見表です。特定サービスの優劣を断定するものではなく、判断の軸を提供するものです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 不調を感じたタスクの種類を左から探し、判断軸に沿って自分の環境で実際に試してから切り替えを決めてください。

```text
【不調時の代替モデル早見表】

■ 使い方の原則
□ この表はどのサービスが優れているかの断定ではない。判断の「軸」を渡すためのものと理解する
→ YES: 以下の軸に沿って、実際に自分の目で2〜3件試してから決める
指示例: 「同じ依頼文を今のモデルと候補モデルの両方に投げて、結果を横に並べて」

■ タスク種別ごとの判断軸

1. 短い事実確認・要約
判断軸: スピード最優先。多少の精度差より待ち時間の短さで選ぶ。
確認ポイント: 誤字脱字・数字の転記ミスが無いか自分で目視確認する。

2. コード生成・デバッグ
判断軸: 誤検出で格下モデルに回されていないか、まずモデル名表示を確認する。
確認ポイント: 「脆弱性」「攻撃」等の単語を含む依頼は、意味を変えず言い換えてから再送する。

3. 長文の企画・構成案作成
判断軸: 一括で投げず、章立て→肉付けの2段階に分けた方が安定しやすい。
確認ポイント: 出力が急に短くなったら、利用上限に近づいていないかプラン画面を確認する。

4. 事実関係が重要な調査・リサーチ
判断軸: 固有名詞・数字・日付は必ず一次情報で裏取りする前提で使う。どのモデルでも鵜呑みにしない。
確認ポイント: 出典を示せない主張は「未確認」として扱い、そのまま人に共有しない。

5. 画像・音声など非テキスト系
判断軸: テキスト系より対応状況の変化が速いので、都度公式の対応表を確認する。
確認ポイント: 代替候補が無ければ、無理せず手動対応に一時的に切り替える。

■ 切り替えを検討する基準
□ 同じ不調が3回以上、複数のタスクで再現したか
→ YES: 重要タスクだけ一時的に代替モデルへ振り分ける
→ NO: 様子見でよい。切り替えは焦って決めない
指示例: 「直近の不調ログを見せるので、3回以上再現しているパターンがあるか整理して」

■ 切り替え後にやること
□ 代替モデルでの結果が、元の依頼の意図を満たしているか照合したか
→ YES: 問題なければそのまま継続。定期的にメインモデルの状態も見に戻る
→ NO: 照合してから採用する
指示例: 「代替モデルの出力を渡すので、元の依頼文の要件を1項目ずつ満たしているか確認して」

以上です。
```

**ポイント**: 「常にA社が上」という決めつけを避け、タスクごと・時期ごとに実際に試して判断する習慣が最も安定します。
