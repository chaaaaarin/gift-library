# 🎁 Claude Code⇔Codex 対応表＋スキル復旧プロンプト集

呼び方が変わるだけで機能はほぼ同じ、という対応関係を1枚で確認できる早見表と、インポート後に呼び出せなくなったスキルを復旧するためのプロンプト集です。

**受け取り方**: 表はそのまま参照用に、プロンプトは各コードブロックのコピーボタンでコピーするか、このファイルをダウンロードしてください。

## 対応表

| 項目 | Claude Code | Codex |
|---|---|---|
| 設定ファイル | CLAUDE.md | AGENTS.md |
| MCPサーバー設定 | JSON | TOML |
| スキル呼び出し | スラッシュコマンド | $記号 |
| 横道の会話 | /btw | /side |
| 思考の深さ調整 | /effort | /model（モデルに紐付く） |
| サブエージェント定義 | Markdown（1ファイル1ロール） | TOML（プロファイル形式で再宣言） |
| 権限管理 | permission allowlist（細かい） | sandboxレベル（粗い・同等物なし） |
| 設定変更フック | ConfigChange対応 | 非対応 |
| 出力スタイル | Output styles対応 | 非対応（モデル化されていない） |
| カスタムAPIエンドポイント | ANTHROPIC_BASE_URL | model_providerとして登録 |

## 復旧プロンプト集

インポート後にプラグインスキルが呼び出せなくなったときに使う、検証者の実例をベースにしたプロンプト集です。

```text
1. スキル未移行の洗い出し
前提: Codexへのインポートを終えたが、一部のスキルがスラッシュコマンドや$記号で呼び出せない状態になっている。
指示: 移行前に使っていたスキル一覧を渡すので、Codex側で1つずつ呼び出しを試し、動くもの・動かないものを分類して。
出力形式: スキルごとに「動作」「非動作」「未確認」の3分類にした表で出力して。
```

```text
2. GitHub公開スキルの再連携
前提: 動かなくなったスキルの名前と、元の入手元（分かる範囲）がある。
指示: GitHub上の公開リポジトリを探索し、同等のスキルを見つけて再連携する手順を提案して。ローカルのマーケットプレイス経由での導入も含めて検討して。
出力形式: スキルごとに「探索キーワード」「再連携の具体的な手順」をセットで、番号付きステップとして出して。
```

```text
3. ローカルマーケットプレイスの導入
前提: Codexでスラッシュコマンドが呼び出せない問題があり、ローカルのプラグインマーケットプレイス経由での解決が有効だと分かっている。
指示: ローカルマーケットプレイスを導入する手順を、初心者でも迷わないレベルまで分解して教えて。アプリの再起動が必要になるケースがあれば明記して。
出力形式: 番号付きステップで、各ステップの完了確認方法も添えて出力して。
```

```text
4. 重要スキルの復旧優先順位づけ
前提: 未移行のスキルが複数あり、それぞれの利用頻度が分かっている（利用頻度のリストを渡す）。
指示: 利用頻度をもとに復旧の優先順位をつけ、上位のものから着手する計画を立てて。全部を一度に直そうとせず、段階的に進める前提で。
出力形式: 優先順位付きのリストと、それぞれの復旧に必要な作業時間の見積もりを添えて出力して。
```

```text
5. シンボリックリンクによる設定同期
前提: Claude CodeとCodexの両方を併用しており、スキル定義ファイルやルール定義ファイルを同期させたい。
指示: シンボリックリンクを使って、片方の変更がもう片方に自動反映される構成を設計して。ディレクトリレベル・ファイルレベルどちらが適切かも判断して。
出力形式: ディレクトリ構成図と、実際に張るべきシンボリックリンクのコマンドをコードブロックで示して。
```

```text
6. 復旧完了後の動作回帰テスト
前提: 復旧作業を行ったスキルについて、元と同じ挙動をするか確認したい。
指示: 復旧したスキルの元の仕様（何をトリガーに、何をするか）を渡すので、同じ条件で呼び出したときに期待通りの結果が返るかのテストケースを作って。
出力形式: テストケースごとに「入力」「期待される出力」を明記した表で出力して。
```

**ポイント**: 復旧プロンプトはCodex・Claude Codeどちらに貼ってもそのまま使えます。実行結果は必ず目視確認してから本番環境に反映してください。
