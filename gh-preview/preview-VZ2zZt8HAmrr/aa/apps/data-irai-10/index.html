# 🎁 月曜の会議資料が、聞くだけで仕上がる「@Data」依頼文10選

売上表を ChatGPT の Work に渡して、下の依頼文を貼るだけで、「なぜ数字が落ちたか」の調べものから会議用のダッシュボード・報告書・スライドまで進みます。どの依頼文も「使った列と数字の定義」「根拠の集計」「推測かどうか」を先に書かせる形なので、出てきた結果をそのまま確かめて会議に出せます。

**受け取り方**: 各コードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**:
- ChatGPT を開いて Work に切り替え、プラグイン一覧で Data を選んでインストールします
- 新しいチャットに Excel・CSV を添付するか、必要に応じてデータ元（Google Drive・SharePoint・BigQuery・Snowflake など）を接続します
- 下の依頼文の［ ］を自社の内容に書き換えて貼り、送ります

## 最初に1回だけ確認すること

- ChatGPT Work は有料プラン（Plus 以上）で使えます。Free・Go では使えません
- 結果を会議や社外に出す前に、「どの表を使ったか・期間・絞り込み・数字の定義（税抜か、返品を引くか）」が頼んだとおりかを確かめます
- ダッシュボードを公開すると、分析に使ったデータもコピーされます。共有する相手に見せてよいデータかを先に確かめます
- データ元を接続した場合、見られるのは接続したアカウントの権限の範囲だけです

## 1. 売上が落ちた理由を調べて、会議用の1枚にする

**期待できるメリット**: 月別・カテゴリ別・チャネル別に表を何度も組み替えて「どこで落ちたか」を探す作業が、1回の依頼で「下がった金額が大きい順の3つ＋根拠の集計」になって返ってきます。手作業で半日かかっていた原因探しが、目安として30分ほどの確認作業になり、そのまま会議で見せる1枚まで作れます。

**使う場面**: 月曜の会議の前に「先月より売上が落ちた理由」を説明しなければならないとき。

**前提**: 7月・8月分の売上表（Excel か CSV）。日付・商品カテゴリ・販売チャネル・売上・返品数などの列があるもの。

```text
@Data 添付した売上表（2026年7月・8月分）を使って、
8月の売上が7月より下がった理由を調べてください。

1. 使った列と「売上」の定義（税抜か、返品を引くか）を最初に書く
2. 商品カテゴリ別・販売チャネル別に、下がった金額が大きい順に3つ挙げる
3. それぞれに、数字の根拠（どの集計か）を添える
4. データの抜けや重複があれば、分析の前に報告する

最後に、月曜の会議で見せる1枚のダッシュボードにしてください。
推測で埋めた部分は「推測」と書いてください。
```

**出てくるもの**: 使った列と「売上」の定義、データの抜け・重複の報告、下がった金額が大きい順の3つ（それぞれの集計の根拠つき）、会議で見せるダッシュボード1枚。

**つまずいたら**: 定義が自社の決まりと違うときは「売上は税抜・返品を引いた金額で計算し直してください」と続けて送ります。期間は依頼文とファイル名の両方で合わせます。

## 2. 分析を始める前に、データの抜けと重複を点検する

**期待できるメリット**: 二重に取り込まれた行や、空欄のまま残った数字に気づかないまま集計して、会議の後で数字を訂正する事態を防げます。表を上から目で追っていた点検が、目安として数分で「どの日付のどの行か」まで一覧になります。

**使う場面**: 別のシステムから書き出した表や、複数人が手で入力した表を初めて分析するとき。月ごとの表をつなげたとき。

**前提**: 点検したい表（Excel・CSV）。直す前の元のファイルは別に保存しておく。

```text
@Data 添付した［売上表］を、分析を始める前に点検してください。

1. 行数・期間（最初と最後の日付）・列の一覧と、それぞれの列が何を表すかを書く
2. すべての列が同じ内容の行（重複）があれば、日付と中身を一覧にする
3. 空欄・0・マイナスなど、おかしな値がある列と件数を、行の場所つきで書く
4. ある商品やチャネルだけ記録が途切れている期間があれば書く

まだ直さないでください。見つけたことを表にして止まってください。
判断がつかないものは「要確認」と書き、推測は「推測」と書いてください。
```

**出てくるもの**: 表の基本情報（行数・期間・列の意味）、重複・空欄・おかしな値の一覧（場所つき）、記録が途切れている期間の一覧。

**つまずいたら**: 重複かどうか迷う行は、元のシステムの画面や伝票で確かめてから「この行は削除して集計して」と指示します。

## 3. 前月比・前年同月比で、大きく動いた数字を3つ拾う

**期待できるメリット**: 「どの数字から見ればいいか」を探す時間がなくなり、会議の冒頭で話すべき3つがすぐ決まります。前年のデータがない項目を0と比べて「急増」と見誤る失敗も、依頼文の中で防いでいます。

**使う場面**: 月次の会議で、先月と去年の同じ月の両方と比べて説明したいとき。

**前提**: 比べたい月と、前月・前年同月を含む売上表（例: 2025年8月〜2026年8月の月別の表）。

```text
@Data 添付した［月別売上表（2025年8月〜2026年8月）］を使って、
［2026年8月］の数字のうち、大きく動いたものを調べてください。

1. 使った列と「売上」の定義（税抜か、返品を引くか）を最初に書く
2. 商品カテゴリ別・商品別・販売チャネル別に、前月比と前年同月比を出す
3. 増えた・減った金額が大きい順にトップ3を挙げ、どの集計から出したかを添える
4. 前年のデータがない項目は「比較できない」と書き、0として扱わない

結果は、表1枚と、会議で読み上げる3行の要約にしてください。
理由を推測で書く場合は「推測」と書いてください。
```

**出てくるもの**: 前月比・前年同月比の表、増えた・減ったトップ3（集計の根拠つき）、読み上げ用の3行の要約。

**つまずいたら**: 商品名が年によって変わっている場合は、「旧商品名［A］と新商品名［B］は同じ商品として集計して」と足します。

## 4. 取引先ごとの上位・下位と、先月からの変化を並べる

**期待できるメリット**: 卸先ごとの売上表を作り直して見比べる手間が省け、「発注が急に減った取引先」が表の上に出てきます。営業担当が今週どこに電話すべきかまで決まるので、数字の確認が次の行動につながります。

**使う場面**: 卸や法人向けの売上で、取引先ごとの変化を月に一度確かめたいとき。

**前提**: 取引先名の列がある売上表（表記ゆれがあれば先にそろえておくと正確）。

```text
@Data 添付した［売上表（2026年7月・8月分）］のうち、販売チャネルが「［卸］」の行だけを使って、
取引先ごとの売上を比べてください。

1. 使った列と「売上」の定義（税抜か、返品を引くか）を最初に書く
2. 取引先ごとに、7月・8月の売上、増減の金額と率、発注の回数を表にする
3. 8月の売上が多い順の上位3社と、減った金額が大きい順の3社を、根拠の集計つきで挙げる
4. 前月の半分以下になった取引先があれば、日付ごとの発注の変化を添える

最後に、営業担当が今週確かめるべきことを、取引先ごとに1行で書いてください。
理由がデータから分からない場合は「データからは不明」、推測は「推測」と書いてください。
```

**出てくるもの**: 取引先別の比較表、上位3社と減少が大きい3社、発注が半分以下になった取引先の日付ごとの変化、取引先ごとの確認事項。

**つまずいたら**: 同じ会社が「株式会社」の有無で別々に数えられていたら、「取引先名の表記ゆれをそろえてから集計して」と送ります。

## 5. 毎週の会議で見る数字を、5つに絞って決める

**期待できるメリット**: 「毎週どの数字を見るか」が人によってばらばらな状態から、計算式と定義が決まった5つの数字にそろいます。会議のたびに数字の出し方で揉める時間が減り、来週からは同じ表を更新するだけになります。

**使う場面**: 毎週の会議で見る数字（KPI）がまだ決まっていない、または増えすぎて誰も見ていないとき。

**前提**: いま手元にある売上表。会社の売り方（どのチャネルで売っているか）を1行で書けるようにしておく。

```text
@Data 私たちは［社員20人の雑貨メーカー］で、［自社オンラインショップ・直営店・卸］で売っています。
添付した［売上表］をもとに、毎週の会議で見る数字を5つに絞って決めてください。

1. 候補を10個出し、それぞれ「何が分かるか」と「どの列から計算するか」を書く
2. その中から5つ選び、選んだ理由と外した理由を1行ずつ書く
3. 5つそれぞれに、計算式・週の区切り方・「売上」の定義（税抜か、返品を引くか）を書く
4. 今のデータにない列が必要な数字は、「今は計算できない」と分けて書く

最後に、5つを並べた表の見本を、直近1週間の値を入れて作ってください。
推測で決めた部分は「推測」と書いてください。
```

**出てくるもの**: 数字の候補10個と説明、選んだ5つと理由、計算式と定義の一覧、直近1週間の値が入った表の見本。

**つまずいたら**: 候補が抽象的すぎるときは、「来週の打ち手が決まる数字だけにして」と条件を足します。

## 6. 在庫表と売上表を突き合わせて、売り逃しを見つける

**期待できるメリット**: 「売れ筋なのに急に売上が止まった」原因が在庫切れだったかどうかを、2つの表を並べて目で探さずに確かめられます。売り逃した金額の見込みも出るので、発注の見直しを数字で提案できます。

**使う場面**: 人気商品の売上が一時的にゼロになっている期間があり、在庫切れを疑っているとき。

**前提**: 日ごとの在庫数が分かる在庫表と、同じ期間の売上表。

```text
@Data 添付した［在庫表］と［売上表（2026年8月）］を、商品名で突き合わせてください。

1. 使った列と「売上」の定義（税抜か、返品を引くか）を最初に書く
2. 2つの表で商品名の書き方が違うものは、対応表を作って見せる
3. 在庫が0だった日と、売上の記録がない日が重なる商品と期間を一覧にする
4. その期間の前後2週間の1日あたり売上から、売れなかった金額の見込みを計算式つきで出す

在庫はあるのに売上が止まっている商品は、別の表に分けてください。
売り逃しの金額は「推計」と書き、実際の売上と混ぜないでください。推測は「推測」と書いてください。
```

**出てくるもの**: 商品名の対応表、在庫切れと売上ゼロが重なった期間の一覧、売り逃し金額の推計（計算式つき）、在庫があるのに売れていない商品の表。

**つまずいたら**: 在庫表が日ごとでなく週ごとしかない場合は、「週単位で突き合わせて」と書き換えます。

## 7. 経営向けの月次報告を、文書にまとめる

**期待できるメリット**: 分析結果を見ながら報告書の文章を一から書く作業が、結論・数字・理由・打ち手の順に並んだ下書きの手直しだけになります。目安として1〜2時間かかっていた月次報告の作成が、読み直しと修正中心の作業に変わります。

**使う場面**: 社長や役員に、毎月の売上の状況を文書で報告しているとき。

**前提**: 報告する月と前月の売上表。Word か Google ドキュメントで提出する前提（Data の文書にするスキル Convert To Doc を使う想定）。

```text
@Data 添付した［売上表（2026年7月・8月分）］から、社長に出す8月の月次報告を作り、
Word（または Google ドキュメント）の文書にしてください。

1. 結論（3行）: 8月の売上と前月比、いちばん大きい理由
2. 数字: カテゴリ別・チャネル別の表。表の下に、使った列と「売上」の定義（税抜か、返品を引くか）を書く
3. 理由: 売上を動かした理由を大きい順に3つ。それぞれに根拠の集計を添える
4. 来月の打ち手の案を3つ。データから言えることと、推測を分けて書く

専門用語は使わず、数字には必ず単位（円・％・件）を付けてください。
推測の部分には「推測」と書いてください。
```

**出てくるもの**: 結論・数字の表・理由トップ3・来月の打ち手の案がそろった月次報告の文書。

**つまずいたら**: 文章が長すぎるときは「A4で1枚に収めて」、社内の書式があるときは「添付したひな形の見出しの順に合わせて」と足します。

## 8. 会議用のスライドを、自社のひな形に合わせて作る

**期待できるメリット**: 分析結果をスライドに貼り直し、色や文字の大きさを社内の形式に合わせる作業が、5枚の下書きの確認だけになります。グラフの下に期間と定義が入るので、会議中の「この数字は税込？」という質問にもその場で答えられます。

**使う場面**: 上の1〜7で分析した結果を、月曜の会議でスライドにして説明したいとき。

**前提**: 同じチャットで分析を済ませておく。社内のスライドのひな形（PowerPoint など）があれば添付する（Data のスライドにするスキル Convert To Slides を使う想定）。

```text
@Data ここまでの分析結果を、月曜の会議で使うスライド5枚にしてください。
添付した［自社のスライドのひな形］の色・文字の大きさ・ページの並びに合わせてください。

1枚目: 結論（8月の売上と前月比を大きく1つ）
2枚目: どこで下がったか（カテゴリ別・チャネル別のグラフ）
3枚目: 理由トップ3（それぞれに根拠の数字）
4枚目: データの注意点（期間・使った列・「売上」の定義・見つかった重複や空欄）
5枚目: 今週決めたいこと（3つ）

各グラフの下に、期間と「売上」の定義を小さく入れてください。推測の部分は「推測」と書いてください。
```

**出てくるもの**: 結論・グラフ・理由・注意点・決めたいことの5枚のスライド。グラフごとの期間と定義の注記。

**つまずいたら**: ひな形どおりにならない部分は、見出しの順番と色だけ合わせてもらい、細かい見た目は開いた後に手で直します。

## 9. 毎週そのまま使えるダッシュボードに整える

**期待できるメリット**: 毎週月曜に同じ集計をやり直す作業が、新しい週の表を添付して「同じ形で作り直して」と頼むだけになります。使った列名と計算のしかたが一覧で残るので、担当が替わっても同じ数字が出せます。

**使う場面**: 1で作った会議用の1枚を、毎週の定例資料として続けたいとき。

**前提**: 毎週、同じ列の並びで書き出せる売上表。公開や共有の前に、見せてよい相手とデータの範囲を決めておく（Data のダッシュボードを作るスキル Build Dashboard を使う想定）。

```text
@Data 添付した［売上表］で、毎週月曜に見るダッシュボードを1つ作ってください。

1. 使った列と「売上」の定義（税抜か、返品を引くか）を、ダッシュボードの一番上に書く
2. 上段: 先週の売上、前の週との比較、前月の同じ週との比較
3. 中段: カテゴリ別・チャネル別の週ごとの推移のグラフ（それぞれ根拠の集計が分かるように）
4. 下段: 前の週から大きく動いた商品と取引先のトップ5

来週、同じ列の新しい表を添付すれば同じ形で作り直せるように、使った列名と計算のしかたを最後に一覧にしてください。
データに抜けや重複があれば注意書きとして上に出し、推測は「推測」と書いてください。公開や共有はまだしないでください。
```

**出てくるもの**: 定義つきの週次ダッシュボード、データの注意書き、来週作り直すための列名と計算方法の一覧。

**つまずいたら**: 公開すると分析に使ったデータもコピーされます。社外や他部署に見せるときは、見せてよい列だけの表で作り直してから共有します。

## 10. 商談の前に、取引先を出典つきで調べる（@Deep Research）

**期待できるメリット**: 商談の前に相手の会社のサイトやニュースを開いて回る下調べが、出典のリンクつきの1枚の資料にまとまります。事実と推測が分かれているので、商談で確かめるべき質問まで決めた状態で出かけられます。目安として1時間近くかかっていた下調べが、資料を読んでリンクを確かめる時間だけになります。

**使う場面**: 新しい取引先や、しばらく取引のなかった卸先と商談する前。

**前提**: ChatGPT の Work で Deep Research が使えるプラン（Plus・Pro・Business・Enterprise・Edu）。Data のインストールは不要。相手の会社名と、商談で話したいテーマ。

```text
@Deep Research 来週、［取引先の会社名］と［新しい商品の取り扱い］について商談します。
商談の前に、この会社のことを調べて1枚の資料にまとめてください。

1. 会社の概要（事業の中身・店舗や拠点・直近の動き）を、公開されている情報から書く
2. ［雑貨・生活用品］の取り扱いについて、最近の発表やニュースがあれば挙げる
3. 数字と事実には、1つずつ出典のリンクを付ける
4. 出典で確かめられた事実と、そこから考えた推測を、見出しを分けて書く

最後に、商談で聞くべき質問を5つ、理由つきで出してください。
```

**出てくるもの**: 出典リンクつきの会社概要、関連する最近の発表やニュース、事実と推測を分けた整理、商談で聞く質問5つ。

**つまずいたら**: 古い情報が混ざるときは「［2026年］以降の情報を優先して」と期間を足します。出典のリンクは開いて、数字が本当に書いてあるか確かめてから使います。

**ポイント**: どの依頼文も「定義を先に書く・根拠を添える・推測は推測と書く」の3つが入っています。自分で書き足すときも、この3行だけは消さずに残してください。
