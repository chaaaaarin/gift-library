# 🎁 X公式MCP セットアップ手順

Codex・Claude Code・CursorなどからXの公式MCP（`api.x.com/mcp`）に接続するための手順です。X Developer Consoleでのアプリ作成からOAuth認証まで、初回セットアップに必要な工程をまとめました。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 上から順番に進めてください。⑤の設定ファイルは自分が使うツール（Claude Desktop / Cursor / VS Code等）に合わせて置き場所を変えます。

```text
# X公式MCP セットアップ手順

## ① X Developer Consoleでアプリを作成
1. X Developer Consoleにログインし、新規アプリを作成する。
2. アプリの「User authentication settings」でOAuth 2.0を有効化する。
3. App permissionsは「Read and Write」を選択する(投稿・記事作成に必要)。
4. App typeは「Web App, Automated App or Bot」を選択する。
5. Callback URI / Redirect URLに次を完全一致で登録する:
   http://localhost:8080/callback
6. Website URLは任意(自分のサイト等で問題ない)。

## ② CLIENT_ID / CLIENT_SECRETを取得
- 保存後に表示されるClient IDとClient Secretを控える。
- この2つは秘密情報として扱い、チャット・ログ・共有設定ファイルに直接書かない。

## ③ xurlをインストール(いずれか1つ)
brew install --cask xdevplatform/tap/xurl
npm install -g @xdevplatform/xurl
curl -fsSL https://raw.githubusercontent.com/xdevplatform/xurl/main/install.sh | bash

## ④ MCPクライアント設定(例: Claude Desktop / Cursor共通形式)
{
  "mcpServers": {
    "xapi": {
      "command": "npx",
      "args": ["-y", "@xdevplatform/xurl", "mcp", "https://api.x.com/mcp"],
      "env": {
        "CLIENT_ID": "取得したCLIENT_ID",
        "CLIENT_SECRET": "取得したCLIENT_SECRET"
      }
    },
    "x-docs": {
      "url": "https://docs.x.com/mcp"
    }
  }
}
- Claude Desktopの場合: claude_desktop_config.json に上記を追記して再起動。
- Cursorの場合: .cursor/mcp.json (プロジェクト単位) または ~/.cursor/mcp.json (全体) に追記。
- startup_timeout_sec は300以上に設定する(初回ブラウザログインを待つため)。

## ⑤ 初回ログイン
1. 設定後、ツールを起動しXのツールが呼ばれるタイミングでブラウザが自動で開く。
2. 投稿したいXアカウントでログインし、アプリの連携を許可する。
3. 以降はトークンが自動更新されるため、再ログインは基本的に不要。

## ⑥ 動作確認
- 「Xで自分の直近の投稿を3件取得して」のような読み取り系の指示から試す。
- 書き込み系(投稿・記事公開)は、AGENTS.md/CLAUDE.mdの運用ルール
  (書き込み前ユーザー確認)が効いているかを必ず確認してから使う。

## つまずきやすいポイント
- 「アプリにアクセスできません」エラー → OAuth 2.0が有効か、
  Callback URLが完全一致しているか、権限がRead and Writeになっているかを確認。
- 401エラーが続く → CLIENT_ID/CLIENT_SECRETが正しい環境変数に
  渡っているか、トークンの再ログインが必要か確認。
- ツール一覧にXの項目が出てこない → クライアントを一度再起動する。
- 記事投稿がある回数で失敗し始める → API側の書き込みレート制限の
  可能性が高い。時間を空けるか、ブラウザ操作での代替投稿を検討する。
```

**ポイント**: CLIENT_SECRETやアクセストークンは、設定ファイルにそのまま書かず環境変数経由で渡す運用も検討してください。
