Claude Code を更新して切り替える

006既定 effort が下がったことを知る
既定 effort が下がったことを知る
/effort high
→ Opus 5.5 の既定 effort は medium。Opus 5 の high より1段浅い思考です。まず既定のまま数回試し、物足りなければ上げる、の順番が無駄がありません。

なぜ既定が下がったのか
→ Opus 5.5 は同じ仕事をより少ないステップで終えられるため、既定を medium に下げてもコストと速度のバランスが取れる、という設計です。逆に言うと、長時間のエージェント作業や難しい設計判断では自分で上げる必要があります。公表ベンチマークの 66.4% も xhigh での数字です。

007effort の5段階と使い分け
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
/effort で low〜max を切り替え。1セッション内でも作業フェーズに応じて変えるのが効きます。

・low：サブエージェント、定型作業、単純な修正
→ ツール呼び出しも前置きも少なくなる
・medium：日常の実装、通常のコーディング
→ Opus 5.5 の既定。まずここから
・high：知的負荷の高い実装、設計判断
→ 品質とトークン効率のバランス点
・xhigh：長時間のエージェント作業、複雑な実装
→ 公表ベンチマークもこの設定
・max：コストより正確さが重要なとき
→ 下の段で頭打ちを確認してから上げる

コツ：低いところから始めて、必要なときだけ上げる。長時間タスクは effort を上げたうえで、仕様を最初に全部渡すと成功率が上がります。

■ 14. 20件の事例から見えた、4つの勝ちパターン
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
うまくいっている人の指示の出し方には共通点があります。

1. 完成形を一息で渡す
→ 「できるだけリアルで美しい◯◯を作って」のように、ゴールの質まで含めて最初に渡す。途中で小出しにするより成功率が高い。
2. サブエージェントに割る
→ 1プロンプトから5体を並列で走らせた事例が最も高い評価を得た。Opus 5.5 は仕事の割り振りとチェックが上手くなっている。
3. 難しいものほど effort を上げる
→ 1時間半かけた事例はいずれも max / xhigh。既定の medium のままでは到達しない領域がある。
4. 既存ツールを操らせる
→ Blender・Unreal・Roblox Studio を直接操作させる使い方が成立している。コード生成だけの道具ではない。

■ 15. モデル使い分け早見表
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Opus 5.5 が出たことで、選び方はこう変わります。

・日常のコーディング全般 → Opus 5.5
　性能・価格・速度のバランスが最も良い。まずここ
・長時間の自律エージェント → Opus 5.5（xhigh）
　少ないステップで完了する。effort は上げる
・最難関の推論・長距離タスク → Fable 5.1
　最上位。ただし単価は 2.5 倍
・大量・高速・低コスト → Sonnet 5
　$2 / $10。分類や定型処理はここで十分
・サブエージェントの下働き → Sonnet 5 / Haiku 4.5
　読むだけ・調べるだけの役割に上位モデルは不要
・セキュリティ関連の作業 →（自動で Opus 4.8）
　指定しても切り替わる。想定しておく

コスト最適化の順番：まず effort を下げる → それでも足りなければモデルを落とす。上位モデルの低 effort が、下位モデルの高 effort を上回ることは珍しくありません。

出典: Anthropic 公式価格ページ ／ モデル移行ガイド ／ Claude Code ドキュメント

■ 16. 浮かれる前に：3つの注意点
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
発表から2日の情報です。以下は割り引いて読んでください。

・ベンチマークは自社計測
→ 66.4% は Anthropic が自社ハーネスで測った値（標準誤差 ±2.6pt）。独立評価の Artificial Analysis では 59.6%。公開ボードの数字と並べて比較することはできません。
・作例は「うまくいった1本」
→ X に上がるのは成功例です。何回やり直したか、どれだけトークンを使ったかは基本的に公開されていません。再現性は自分のデータで確かめる必要があります。
・セキュリティ作業では別モデルになる
→ cyber / bio / reasoning_extraction の分類器が動き、多くのセキュリティ作業は Opus 4.8 で処理されます。性能を期待した通りに出せない領域があります。

■ 17. 今日から動かすなら、この3ステップ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. Claude Code を更新して /model opus
→ v2.1.280 以降で Opus 5.5 に切り替わります。まずは既定の medium のまま、いつもの仕事を数回。
2. 物足りなければ /effort high

→ 「一文の指示からどう出たか」が読める公開リポジトリがあります。自分の指示の出し方を上書きするのが一番早い。
