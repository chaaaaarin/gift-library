━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ 「一部だけ直す」が正確になった
→ 「この椅子だけ木製に」「この文字だけ消して」が、背景や他の部分を巻き込まずに通る。
□ 参照写真の人物・商品の保持が強くなった
→ 添付した写真の顔・体型・商品の形が、編集しても別物になりにくい。
□ マルチターン編集に強くなった
→ 1枚に対して「もう少し明るく」「影を足して」と会話で少しずつ直せる。
□ 実世界の文字・情報の再現が良くなった
→ 指定した見出し・ラベルをそのまま描ける（長文はまだ苦手・■4参照）。
□ 透過背景・複雑なレイアウトに対応
→ PNGの透過切り抜き、複数要素の配置が安定した。
□ 速くなった（旧 Images 2.0 比で最大50%短縮）
→ 試作を何枚も回しやすい。
□ 配布・提供の範囲
→ ChatGPT／ChatGPT Work／Codex の全プラン（無料含む）、PC・スマホ・Webで順次利用可。

■ 2. プロンプトはこの順で書く（公式の型・6要素）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
特別な記号や書式は不要。短文でも箇条書きでも通る。読みやすさ優先で、次の順に書く。

□ (1) 主題と用途
→ 何を、何のために作るか。例）「ECサイト用の商品写真」「研修資料の解説図」
□ (2) 構図
→ 比率・配置・余白。例）「16:9」「右3分の1は文字を載せるので空ける」
□ (3) 視覚ディテール
→ 素材・光・色・画風。例）「実写風、彩度は強め」「白背景＋濃紺の線、影なし」
□ (4) 人物と動作（人物が入るとき）
→ 画角・大きさ・視線・持ち物。例）「肩から上、正面やや斜め、微笑み」
□ (5) 入れる文字（必要なとき）
→ 二重引用符で正確な文言を書き、位置と書体を指定。例）見出しは「"Market Opportunity"」左上、サンセリフ体
□ (6) 変える所と残す所を分ける（編集のとき）
→ 「◯◯だけ変える」「顔・構図・色・照明・ラベルは保持」「文字・ロゴ・透かしは足さない」

指示例（ゼロから作る）:
16:9のインフォグラフィックを作ってください。テーマは受注から出荷までの流れ。工程を左から右に4つ、角丸の箱と矢印で。白背景＋濃紺、重要な1工程だけ山吹色。短いラベル（各6文字以内）は正確に、他の文字は入れない。

■ 3. 画像を「一部だけ」直すとき
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ 直したい写真を1枚だけチャットに添付したか
→ YES: 次へ。複数貼るときは「1枚目＝対象／2枚目＝参照」と役割を明記する。
□ 変える対象を「位置＋色＋形」で特定できるか
→ YES: 「右奥の赤い看板」のように書く。「右の物」だけだと外す。
□ 残すものを列挙したか
→ YES: 「構図・色味・明るさ・他の被写体・影・遠近感は変えない」と毎回書く。
指示例: 添付画像から「画面左の電線」だけを消し、消した跡は空と自然につなげてください。それ以外は一切変えないでください。
□ 変更は1ターンにつき1つにしているか
→ YES: 「椅子を変える」と「壁の色を変える」は別々に頼む。まとめると他が動く。
□ 3回以上直したか
→ YES: 顔や細部がずれ始める。一度もとの画像から作り直す。

■ 4. 文字を入れるとき
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ 入れる文言を二重引用符で囲んだか
→ YES: 「"季節限定フェア"」のように。位置（左上・中央など）と書体も添える。
□ 文字量は「見出し＋箇条書き3行」までに抑えたか
→ YES: 長い文章は崩れる。長文が要るなら画像は枠だけ作り、文字は後から編集ソフトで載せる。
□ 固有名詞・ブランド名が崩れるか
→ YES: その語だけ「T-h-r-e-a-d のように1文字ずつ」スペルアウトして渡す。
□ 余計な文字が入るか
→ 「指定した文言以外の文字は入れない」「誤字を作らない」と明記する。
□ 出力後にやること
→ 必ず拡大してスペルと改行位置を目視。崩れた語だけ「この単語を直して、他は変えない」で修正。

■ 5. 透過背景がほしいとき
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ 「完全な透過背景」「PNG形式」と指定したか
→ YES: 「単色背景・チェッカー模様・床・影・小物は足さない」も一緒に書く。
□ 影がほしいか
→ 透過で切り抜いてから、別ターンで「真下に薄い楕円の影を1つだけ足して」と頼む。
□ 出力後にやること
→ 拡大して、髪・毛先・グラス・透明パーツの縁に背景色が残っていないか確認。残っていたら「縁の背景色を消してアルファチャンネルをきれいに」で再処理。

■ 6. 参照画像（見本）を渡すとき
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ その画像の「役割」を書いたか
→ 「スタイルの見本」「服の見本」「背景の見本」「主役の見本」と明示する。
□ 何を引き継ぎ、何を引き継がないか分けたか
→ 例）「配色・線の太さ・質感・光だけ引き継ぐ。構図と被写体はコピーしない」
□ シリーズで揃えたいか
→ 1枚目を見本に固定し、「同じ見本のまま、次はこのモチーフ」とモチーフ名だけ変えて続ける。

■ 7. モデル・品質の選び方
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ ふつうに ChatGPT で画像を作る
→ モデル選択は不要。画面の指示に従うだけでよい。
□ API／開発で使う（大量生成・自社サービス組み込み）
→ gpt-image-2.5-flare を選ぶ。速くて日常用途はこれで十分。旧 GPT Image 2 より高品質で遅延は約半分。
□ API で「編集の精度」が最優先（本番のキャンペーン用・作り込む商品画像）
→ gpt-image-2.5-sunburst を選ぶ。生成は遅いが、細かい編集指示の再現が高い。
□ 小さい文字・細かい情報・複数フォントを含む画像
→ 品質設定を上げて（high 以上）比較する。速度と要求品質のバランスで最小限に。

■ 9. 新機能の使いどころ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ Sketch（スケッチ）
→ チャットに「@Sketch」と入力すると、その場で下描きできる。構図やレイアウトを言葉で説明しづらいとき、ラフを描いて「この配置で」と渡す。チラシ・ポスター・物撮りのテンプレートも用意されている。
□ 画像へのコメント
→ 生成した画像の直したい場所に印（コメント）を置いて指示できる。「ここの色を」「この部分を消して」を言葉だけで特定しなくてよい。
□ プロンプトの共有
→ 使ったプロンプトを共有すると、相手が自分の写真・条件で同じ作り方を再実行できる。社内でテンプレを配るときに使う。

■ 10. うまくいかない時の逆引き
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ 症状：一部だけ直したいのに、他の部分まで変わる
→ 「◯◯だけ変える。構図・色・照明・他の被写体は保持」と残す物を列挙。変更は1ターン1つ。
□ 症状：編集を重ねたら人物が別人になった
→ もとの人物画像から作り直す。毎ターン「1枚目のまま顔・体型は変えない」と書き直す。
□ 症状：画像内の文字が誤字・意味不明になる
→ 文字量を見出し＋3行までに。崩れる語は1文字ずつスペルアウト。長文は枠だけ作り後から載せる。
□ 症状：透過にしたのに縁に白フチ・背景色が残る
→ 「縁の背景色を消してアルファチャンネルをきれいに」で再処理。拡大して毛先・透明部を確認。
□ 症状：スタイル見本を渡したのに構図までそっくりになる
→ 「配色・質感・光だけ引き継ぐ。構図と被写体はコピーしない」と範囲を絞る。
□ 症状：図解の要素が多すぎて読めない
→ 要素は4〜6個に絞る。まず骨組み（箱＋矢印＋短いラベル）だけ作り、凡例・注釈は別ターンで足す。
□ 症状：手・指が乱れる
→ 「手と指だけ自然な形に直して、他は変えない」で部分修正。
□ 症状：雰囲気の言葉（先進的・洗練された）で頼むと毎回違う絵になる
→ 具体的な場面・物・色・光に翻訳してから渡す。「時間帯・場所・何をしているか・主色・差し色」の5点を指定。
□ 症状：ピクセル単位で元画像を保ちたいのにわずかにズレる
→ プロンプトだけで完全一致は狙わない。重要な箇所は編集ソフトで合成する前提にする。
□ 症状：日本語ラベルがどうしても崩れる
→ ラベルは英数字にするか「ラベルは空にして」と頼み、後から自分で文字を入れる。
