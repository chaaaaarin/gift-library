# 🎁 Grok Bot vs Claude Cowork 使い分け早見表

どちらを選ぶべきか、状況別に判断できる早見表です。

**使い方**: 任せたい作業を思い浮かべながら、ステップ1から順に読み進めてください。

```text
【Grok Bot vs Claude Cowork 使い分け早見表】

■ ステップ1：任せたい作業はどこで行う?
□ ログインが必要な外部ツール・Webサイトをまたいで操作したい
→ YES: Grok Bot向き。ツールに直接ログインして横断操作する設計
指示例: 「CRMとメールを横断して顧客対応を進めて」と伝える

□ 手元のファイル・フォルダの整理や、Slack/Google Driveとの連携が中心
→ YES: Claude Cowork向き。ローカルファイル+連携アプリの横断が得意
指示例: 「このフォルダの資料を整理して、Slackで共有して」と伝える

■ ステップ2：使う人は誰?
□ 非エンジニアのPM・オペレーション担当が中心
→ YES: Claude Coworkを優先候補にする(対象ユーザーとして想定されている)
指示例: 「専門知識が無くても使える範囲で任せたい」と条件を明示する

□ 有料上位プランに既に入っている、または入る予定がある
→ YES: Grok Botも選択肢に入れて比較する
指示例: 「SuperGrok Heavy等の対象プランかどうかを確認して」と自分に問いかける

■ ステップ3：離席中の継続作業は必要か
□ 外出中・PCを閉じている間も作業を続けてほしい
→ YES: 常時稼働のGrok Botが向く。ただし共有コンピュータの注意点(合鍵チェックリスト参照)を先に確認する
指示例: 「重要なログインを含む作業は先にチェックリストで仕分けてから任せる」

■ ステップ4：迷ったら
□ 両方の条件に当てはまる作業がある
→ YES: 無理に1つに絞らず、ログイン横断作業はGrok Bot、ファイル中心の作業はClaude Coworkと使い分ける
指示例: 「この作業はどちらの得意領域に近いか」を都度確認してから任せる

判定の目安: どちらも本資料執筆時点(2026年8月)のベータ・プレビュー版。実際の挙動は変わる可能性があるため、契約前に必ず公式サイトで最新情報を確認する。
```

**ポイント**: 早見表はあくまで判断の出発点です。実際の契約プラン・料金は必ず公式サイトの最新情報で確認してください。

# 🎁 合鍵チェックリスト——渡していい仕事・渡しちゃダメな仕事

常駐AIエージェントに作業を任せる前に、その作業を「渡していいか」を5ステップで仕分けるチェックリストです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 任せたい作業を1つ思い浮かべながら、ステップ1から順に□をチェックしてください。

```text
【合鍵チェックリスト——渡していい仕事・渡しちゃダメな仕事】

■ ステップ1：その作業は「取り消せる」か
□ 送信・削除・支払いなど、実行後に取り消せない操作を含むか
→ YES: 承認を挟む設計にするか、渡す作業から外す
指示例: 「送信・削除・支払いが発生する手前で必ず私に確認して」と明示的に伝える

■ ステップ2：ログインするアカウントは共有していい相手か
□ 金融・人事・法務など、機密性の高いアカウントへのログインを含むか
→ YES: 専用のBot・専用のセッションに分け、他の作業と同じコンピュータで扱わない
指示例: 「このアカウントへのログインは他の作業と兼用しないで」と明示する

■ ステップ3：ミスの影響範囲はどこまで広がるか
□ 顧客・取引先など社外に影響が及ぶ可能性があるか
→ YES: 最初は社内向け・下書きどまりの作業から任せ、対外送信は人の確認を挟む
指示例: 「下書きまで作成し、送信は私が確認してから行う」と伝える

■ ステップ4：ログや記録が残るか
□ 何をしたかを後から確認できる仕組みがあるか(監査ログ等)
→ YES: 記録が無い場合は、チャット履歴で追える範囲の作業に留める
指示例: 「作業内容を都度チャットで報告して」と指示する

■ ステップ5：一度見せれば再現できる作業か
□ 手順が毎回同じで、10分以内で見せられる作業か
→ YES: 「教える」機能で覚えさせて任せる候補にする
指示例: 「今から1回だけやってみせるので、同じ手順を覚えて」と伝える

判定の目安: ステップ1〜3のいずれかで「渡さない」判断になった作業は、合鍵(常駐で任せる形)ではなく、その都度確認する形にとどめる。
```

**ポイント**: このチェックリストはGrok Botに限らず、常駐型のAIエージェント全般に任せる作業を仕分ける際に使えます。

**使い方**: カテゴリを1つ選び、該当する指示文をClaude Codeに貼るだけで、そのタスク専用のサブエージェント(役)を立てて仕事を任せられます。

## 営業支援

### 1. 見込み客の夜間リサーチ役

```text
前提: 毎朝、前日分の新規リードリストを見てから営業に出たい個人営業。
指示: 『リサーチ担当』というサブエージェントを立てて、渡したリストの企業を1件ずつ調べ、業種・規模・想定ニーズをまとめて。担当者名が公開情報にあれば添えて。
出力形式: 企業名/業種/規模/想定ニーズ1行/担当者名(あれば)の表形式。情報が取れなかった企業は「未確認」と明記し、憶測で埋めない。
```

### 2. 商談前チェックリスト作成役

```text
前提: 商談前に確認漏れで気まずくなった経験がある営業担当。
指示: 『商談準備担当』を立てて、商談相手の会社名と業種を渡したら、直近のニュース・競合動向・想定される質問を3〜5個ずつ洗い出して。
出力形式: 見出しごとの箇条書き。出典が不明な情報には(未確認)を付け、断定しない。
```

### 3. 見積書たたき台役

```text
前提: 毎回ゼロから見積書のフォーマットを作り直している中小企業の営業。
指示: 『見積担当』を立てて、渡した過去の見積書サンプルの型を覚えさせ、新しい商品名と数量だけ伝えたら同じ体裁で下書きを作れるようにして。
出力形式: 既存フォーマットに沿った見積書ドラフト(Markdown表)。金額欄は空欄のままにし、必ず人が確認してから使う前提であることを明記。
```

### 4. 失注理由の分析役

```text
前提: 同じ理由で何度も失注しているのに原因を言語化できていないチーム。
指示: 『振り返り担当』を立てて、渡した過去の商談メモ複数件から失注理由を分類し、頻出パターンを上位3つにまとめて。
出力形式: パターン名/該当件数/対策案1行、の表。個人名・企業名は伏せ字にする。
```

### 5. フォローアップメール下書き役

```text
前提: 商談後のお礼メールを毎回考えるのが面倒な営業担当。
指示: 『フォロー担当』を立てて、商談メモを渡したら、話した内容を踏まえたお礼メールの下書きを自分の口調に合わせて作って。
出力形式: 件名+本文のメール下書き1通。送信は必ず自分で確認してから、という一文を末尾に添える。
```

### 6. 競合比較表メンテ役

```text
前提: 競合の価格・機能が変わるたびに資料を更新し忘れる担当者。
指示: 『競合ウォッチ担当』を立てて、渡した競合サービスのURLと自社の比較観点リストをもとに、比較表のたたき台を作って。
出力形式: 観点/自社/競合A/競合B、の表。公開情報の裏取りができない項目は空欄にし、埋めない。
```

### 7. 紹介案件の棚卸し役

```text
前提: 紹介してもらった案件を追いきれず放置してしまうことがある担当者。
指示: 『案件棚卸し担当』を立てて、渡した紹介案件メモ一覧から、連絡が止まっている案件を洗い出して。
出力形式: 案件名/最終連絡日/次アクション案、の表。90日以上動きが無い案件は先頭に並べる。
```

### 8. 提案書の骨子役

```text
前提: 提案書を1から構成するのに毎回時間がかかる担当者。

```

### 9. 契約更新リマインド役


## 経理・請求処理

