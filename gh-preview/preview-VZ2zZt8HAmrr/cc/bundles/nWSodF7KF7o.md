# 🎁 バーベル戦略（10-80-10）実践チェックリスト

Fable 5に「何を残し」「何を安いモデルに渡すか」を決めるための、役割分担の判断シートです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: プロジェクトの開始時にこのチェックリストで役割分担を決め、そのままClaude Codeへの指示文（プロンプト）としても使えます。

```text
【バーベル戦略（10-80-10）実践チェックリスト】

■ ステップ1：最初の10%（設計・アーキテクチャ）をFable 5に任せる
□ 何を作るかの全体設計・アーキテクチャ判断
□ タスクの分解（どの部分をどのモデルに渡すか）
□ 難しい判断が必要な仕様確定

指示例:
「実装計画を、Fable 5の計画エージェントを使って立ててください」

■ ステップ2：中間の80%（実装・テスト生成）を安いモデルに渡す
□ 仕様が確定した実装作業
□ テストコードの生成
□ 定型的なリファクタリング
→ Sonnet系・Haiku系・Codex等、安いモデルに委譲する

指示例:
「この計画どおりに、実装はSonnetで進めてください」

■ ステップ3：最後の10%（整合性チェック）だけFable 5に戻す
□ 実装結果が当初の設計と食い違っていないかの確認
□ 見落としているエッジケースがないかのレビュー
→ 完成物のレビューだけなので、トークン消費は少なくて済む

■ ステップ4：Claude Codeでの実践方法（どちらか選ぶ）
□ ターミナル派: /advisorコマンドでアドバイザーモデルにFable 5を設定
  （※デスクトップアプリからは反応しないので注意）
□ デスクトップ/Webアプリ派: プロンプトで直接指示する
  「設計・計画のサブエージェントはFable 5、実装は別モデルにしてください」

■ ステップ5：効果の目安
□ この役割分担で、Fable 5単体運用と比べて
  35〜60%のコスト削減が報告されている
□ Sonnet5×Fable5の組み合わせでは、92%の品質を63%のコストで
  実現できたという実測値もある（Anthropic公式）
```

**ポイント**: `/advisor`はまだ不安定で起動に失敗することがあるので、重要な場面ではプロンプトでの明示指定も併用してください。


### 2. Effort×用途 使い分け早見表（早見表・逆引き）

# 🎁 Effort×用途 使い分け早見表

Fable 5・Mythos 5のeffortパラメータ（low/medium/high/xhigh/max）を、タスクの種類に応じてどう選ぶかの早見チェックリストです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: Claude Code / Claudeアプリでモデルを選ぶ画面の「個数」設定、またはAPIの`output_config.effort`にそのまま当てはめてください。

```text
【Fable 5 / Mythos 5 Effort使い分け早見表】

■ ステップ1：まずhigh（デフォルト）から始める
□ 複雑な推論・難しいコーディング・多くのエージェントタスクか？
  → YES: high（デフォルト）のままでOK。ここが既定の最適解

■ ステップ2：長時間・大規模タスクだけxhighへ
□ 30分を超える長時間のエージェント作業か？
□ 複数ファイルにまたがる大きな改修か？
□ 数百万トークン規模のトークン予算を使う作業か？
  → YES: xhighに上げる

■ ステップ3：ルーティン作業はmedium/lowへ下げる
□ 定型的な下書き・要約・単純なチャットか？
  → YES: medium
□ サブエージェントに渡す単純作業・速度優先のタスクか？
  → YES: low
  （Fable 5のlowは、旧モデルのxhigh相当を上回ることが多いので下げる価値がある）

■ ステップ4：maxは本当に限定する
□ 「絶対に間違えられない」判断が必要な、頻度の低い重要タスクか？
  → YES: maxを検討。それ以外は使わない
  （xhigh→maxの性能の伸びは緩やかで、コストだけ増えやすい）

■ ステップ5：コストの目算
□ Effortを1段階上げると、コストはおおむね1.5倍になる想定で試算する
□ 「モデルを1段階下げてEffortを上げる」方が、単純な単価計算より
  安くなることがあるので、両方試算してから決める

■ ステップ6：Opus系モデルを併用する場合の注意
□ Opus系モデルは「思考」トグルがオフだと推論が働かない
  → 使う前に必ずオンになっているか確認する
```

**ポイント**: 迷ったら「high（デフォルト）から始めて、様子を見て上下に振る」のが一番安全です。
