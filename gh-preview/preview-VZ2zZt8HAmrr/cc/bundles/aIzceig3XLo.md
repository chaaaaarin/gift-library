指示: 非推奨APIの使用箇所を全部洗い出し、新APIへ1箇所ずつ置き換えて。置き換えごとに該当テストを実行して。
出力形式: 置き換え済み・要確認（自動判断できなかった）の2リストに分けて最後に報告して。

4. 前提: 型注釈が不足しているコードベースの型安全性向上。
指示: 型チェッカーの警告が出ているファイルを優先度順に処理し、型注釈を追加して。any型は理由がなければ具体型に置き換えて。

出力形式: 置き換えたパターンの種類ごとに件数を集計し、最後に表で報告して。

# 🎁 セッション運用チェックシート

`/clear` `/compact` `/rewind` `/context` `/mcp`のどれを使うべきか迷ったときの判断フローです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 長時間タスクを始める前・作業の節目ごとに、上から順に判定してください。

```text
【セッション運用チェックシート】

■ ステップ1：これから始める作業は、今の会話と関係あるか
□ 全く無関係な新しい話題を始めようとしている
→ YES: /clearを実行してから始める
指示例: 「/clearしてから、〇〇について新しく始めて」

□ 関係はあるが、long-runの大きなタスクを1つ切り出したい
→ YES: run_in_background: trueかサブエージェントに切り出す
指示例: 「このタスクはバックグラウンドで実行しながら、他の作業を進めて」

■ ステップ2：席を外す・作業を中断する前か
□ しばらく（数時間以上）操作しない予定がある
→ YES: /compactを実行してから離席する
指示例: 「/compactしてから、いったん様子を見る」

□ 使用制限に達しそうな長時間タスクを投げる予定がある
→ YES: オートコンティニュー チェックボックスがオンになっているか確認する
指示例: 「Desktop版の設定でオートコンティニューがオンか確認して」

■ ステップ3：直近のやり取りに無駄なターンが混ざっていないか
□ 言い直し・脱線・失敗した試行が直近に何回かあった
→ YES: /rewindで不要なターンだけを巻き戻す
指示例: 「直近の2ターンをrewindして、その前の状態から続けて」

□ 会話全体が長くなってきたが、要点は必要
→ YES: /rewindではなく/compactで全体を圧縮する
指示例: 「ここまでの内容を/compactで圧縮して」

■ ステップ4：新しいセッション・新しいプロジェクトを開いた直後か
□ 今日はじめてこのプロジェクトを開いた
→ YES: /contextを実行し、何が読み込まれているか確認する
指示例: 「/contextで今何が読み込まれているか見せて」

□ CLAUDE.mdやMCP設定を最近変更した
→ YES: /contextで想定通りに反映されているか確認する
指示例: 「CLAUDE.mdを直したので/contextで反映を確認して」

■ ステップ5：使っていないMCPサーバーが動いていないか
□ このプロジェクトでは使わないはずのMCPサーバーがある
→ YES: /mcpで確認し、不要なら無効化する
指示例: 「/mcpで一覧を見せて、使っていないものは止めて」

■ ステップ6：モデル・effortを作業途中で変えたくなっていないか
□ 作業の途中でモデルやeffortを変更したい衝動がある
→ YES: 今回はそのまま進め、次回セッション開始時に変更する
指示例: 「モデルは今回変えずこのまま進めて。次回から変更を検討する」

■ ステップ7：長時間タスクが制限で中断された直後か
□ 使用制限に達して作業が止まり、リセット後に再開した
→ YES: 中断前の進捗記録（あれば）を確認してから続きを進める
指示例: 「中断前の進捗を確認してから、続きを進めて」

□ 進捗記録が残っていない
→ YES: 次回から、節目ごとに進捗を短く記録する運用に変える（長時間タスクの投げっぱなしテンプレート100選を参照）
指示例: 「次回から、区切りごとに進捗を1行で記録しながら進めて」
```

**ポイント**: 全ステップを毎回やる必要はありません。今の状況に近い項目だけ拾って判定してください。
