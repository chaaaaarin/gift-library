# 🎁 Obsidian×AI 仕事まかせ5点セット

動画で紹介した5つの裏技を、貼るだけで自分のボルトで再現できる指示文セットです。自己紹介のやり直し・会議メモの図解・雑メモの整理・止まった仕事の洗い出し・新規事業の案出しまで、Obsidian に置いたメモを材料にAIへ任せられるようになります。

**受け取り方**: 各コードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: Obsidian のボルトを Codex（GPT-6 Astra）か Claude Code で開き、場面に合う指示文を貼ってください。〔　〕は自分の内容に書き換えます。フォルダ名は「【第二の脳】自動構築キット」で作る形（00_自分／01_Inbox／02_会議／03_プロジェクト／04_会社）を前提にしています。

### 1. AIに"自分"を覚えさせる3枚のメモを作る

期待できるメリット: 新しい会話のたびに「私は〇〇の担当で…」と説明し直す必要がなくなります。AIの提案が、最初からあなたの仕事と判断基準に沿ったものになります。
使う場面: ボルトを作ったばかりのとき／AIの答えが毎回一般論で、自分の仕事に合わないと感じるとき。

```text
これから私に1問ずつ質問して、Obsidian のボルトに「自分メモ」を3枚作ってください。
・質問は全部で9問まで。1問ずつ聞き、答えにくそうなときは例を出す
・聞くこと：仕事と役割／使っているツールとAI／出力の好み／大事にしていること／やらないと決めていること／迷ったときの優先順位／今動いている案件と期限／保留中の案件／毎回説明し直していて面倒なこと
・作るノート：00_自分/自己紹介.md、00_自分/判断基準.md、00_自分/進行中.md
・各ノートの先頭にプロパティ（type／updated／tags）を付ける
・書き込む前に、3枚の中身を見せて私の確認をとる
・最後に AGENTS.md（なければ作る）に「作業の前に 00_自分 の3枚を読む」と1行足す
```

つまずきどころ: 答えが長いとメモも長くなり、毎回読む量が増えます。1枚が画面1枚に収まる長さを目安に「短くまとめて」と頼んでください。進行中.md は週に1回だけ見直します。Claude Code で使う場合は、CLAUDE.md の1行目に「@AGENTS.md」と書いておくと同じルールを読んでくれます。

### 2. 公式スキルを入れて、会議メモを図にする

期待できるメリット: AIが書いたメモでもリンクやプロパティの書き方が崩れず、会議メモを「決まったこと・宿題・担当・期限」が一目で分かる図（Canvas）にできます。
使う場面: 会議メモが長文のまま読み返されていないとき／宿題の抜け漏れを会議の直後に確かめたいとき。

```text
Obsidian 公式のAI向けスキル集「obsidian-skills」を使って、会議メモを図にしてください。
・まず、スキルが読み込まれているか確認する。入っていなければ入れ方だけ説明して止まる（勝手に入れない）
・02_会議/〔会議メモのファイル名〕.md を読み、決まったこと・宿題・担当・期限を抜き出す
・それを Canvas の図にする：真ん中に会議名、左に「決まったこと」、右に「宿題」。宿題は担当ごとにまとめて期限を添える
・保存先は 02_会議/〔会議名〕.canvas。元の会議メモは書き換えない
・最後に、会議メモの末尾へ図への [[リンク]] を1行足してよいか確認する
```

つまずきどころ: スキルが入っていないと、Canvas ファイルの書き方を間違えて Obsidian で開けないことがあります。最初の「読み込まれているか確認」で止まったら、先にスキルを入れてください。できた図は Obsidian のアプリで開いて確かめます。

### 3. 雑メモの仕分け係（放り込んだメモを仕分けて、リンクまで張る）

期待できるメリット: 01_Inbox に放り込むだけでよくなり、整理を自分でやらなくて済みます。関連するメモ同士が [[リンク]] でつながるので、グラフビューで見たときに話のつながりが見えるようになります。
使う場面: Inbox にメモが溜まってきたとき（週1回、またはメモが10枚を超えたとき）。

```text
01_Inbox にあるメモを、仕分け係として整理してください。
・まず全部読み、1枚ずつ「案件／お客様の声／会議／社内のこと／アイデア」のどれかに分ける
・メモごとに「移動先フォルダ／付けるプロパティ（type・tags・updated）／つなぐ既存ノート [[ ]]」を表にする
・既存ノートに追記した方がいいものは、追記する文を案として出す
・期限や依頼が書いてあるメモは、00_自分/進行中.md に載せる案を別枠で出す
・表を見せたら止まる。私が「OK」と言ってから移動と追記をする（削除はしない）
```

つまずきどころ: 表の段階で必ず止めるのがコツです。いきなり移動させると、どこに行ったか分からなくなります。仕分け先に迷うメモは「01_Inbox に残す」で構いません。

### 4. 止まっている仕事と、メモ同士の食い違いを棚卸しする

期待できるメリット: 自分でも忘れていた期限切れの宿題、頼まれたのに進行中に載っていない依頼、会議メモと進行中メモの日付のズレなどを、根拠のノート付きで一覧にできます。
使う場面: 週に1回の見直し／月末や四半期末／休み明けに状況を取り戻したいとき。
前提: 読み込む量が多いので、一度にたくさん読めるモデル（GPT-6 Astra など）で、使える回数に余裕があるときに使います。

```text
ボルト全体を読んで、止まっている仕事とメモ同士の食い違いを棚卸ししてください。
・読む範囲：00_自分／01_Inbox／02_会議／03_プロジェクト（99_アーカイブは読まない）
・見つけるもの：①期限が過ぎた・近い仕事 ②「次にやること」が空の案件 ③担当や期限が決まっていない宿題 ④頼まれたのに 00_自分/進行中.md に載っていない依頼 ⑤ノート同士で日付・数字・方針が食い違っている箇所
・1件ごとに「何が問題か／根拠のノート [[ ]] と該当する一文／次の一手の案」を表にする
・食い違いは、どちらが新しい情報かも書く
・ファイルは書き換えない。表だけ出す
```

つまずきどころ: ボルト全体を読むぶん、使う量が増えます。毎日は回さず週1回にし、メモが増えてきたら読む範囲を絞ってください（例: 02_会議 と 00_自分 だけ）。

### 5. 自社のメモから、新規事業の案を10本出す

期待できるメリット: 自社の強み・お客様の声・失注理由・社内の困りごとをつなげて、「自分の会社だからできる」案を根拠のメモ付きで10本並べられます。企画会議のたたき台がすぐに用意できます。
使う場面: 新規事業・新サービスの企画会議の前／閑散期の打ち手を考えたいとき。
前提: 04_会社 に、強み・お客様の声・失注理由・社内の困りごとのメモが1枚ずつ以上あること。

```text
04_会社 と 00_自分 のメモだけを材料に、自分の会社に合った新規事業の案を10本出してください。
・材料：自社の強み／お客様の声／失注理由／社内の困りごと
・1案ごとに「案の名前／誰のどんな困りごとを解決するか／使える自社の強み／根拠にしたノート [[ ]] と一文の引用／1か月でできる最初の一歩／弱点」を書く
・ボルトに根拠が無い思いつきは出さない。市場の大きさなど外の情報が要る所は「要調査」と書く
・最後に、すぐ試せる順に上位3本を選び、理由を1行ずつ書く
```

つまずきどころ: 材料のメモが薄いと、どこかで聞いたような案になります。お客様の声と失注理由は、日付と出どころを付けて1行ずつ足していくと、案が具体的になります。出てきた案は仮説なので、市場の大きさなどは別に調べてください。

**ポイント**: 1〜3は毎日の仕事の中で、4と5は「週1回」「月1回」と決めて使うと続きます。


### 3. 【第二の脳】自動構築キット（テンプレート）
# このファイルを Codex か Claude Code に1回貼って質問に答えるだけで、Obsidian のフォルダ構成・自分メモ3枚・AI用のルールファイルまでできあがります。フォルダ設計に悩む時間がなくなり、翌日から「あなたのことを知っているAI」で仕事を始められます。

# 🎁 【第二の脳】自動構築キット

このファイルを Codex か Claude Code に1回貼って質問に答えるだけで、Obsidian のフォルダ構成・自分メモ3枚・AI用のルールファイルまでできあがります。フォルダ設計に悩む時間がなくなり、翌日から「あなたのことを知っているAI」で仕事を始められます。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: Obsidian で空のボルト（メモを入れるフォルダ）を作り、そのフォルダを Codex か Claude Code で開いて、下の指示書を丸ごと貼ってください。

- **期待できるメリット**: 「どんなフォルダを作ればいいか」「AIに何を書いておけばいいか」を自分で考えずに、使い始めの形が1回のやり取りで整います。以後は新しい会話のたびに、自分の仕事を説明し直す必要がなくなります。
- **使う場面**: Obsidian を入れたばかりで、ボルトが空っぽのとき／メモはあるけれど、AIに読ませる形になっていないとき
- **前提**: Obsidian のアプリが入っていて、ボルトのフォルダを Codex（アプリ・CLI）か Claude Code で開ける状態
- **出力されるもの**: フォルダ6つ、00_自分 の3枚、AGENTS.md と CLAUDE.md、最後に作ったものの一覧表と「明日から最初にやること」3行

```text
【第二の脳 自動構築の指示書】
あなたは、このフォルダを Obsidian のボルト（メモの保管庫）として整える担当です。
次の手順で進めてください。各手順の終わりに、作るもの・変えるものを一覧で見せ、私が「OK」と言ってから次へ進んでください。

■ 手順1：フォルダを作る
次の6つを作ってください。すでにあるフォルダは作り直さず、中身にも触れないでください。
・00_自分（自分のことを書いたメモ3枚）
・01_Inbox（何でも放り込む場所。あとで仕分ける）
・02_会議（会議メモ）
・03_プロジェクト（案件ごとのメモ）
・04_会社（自社の強み／お客様の声／失注理由／社内の困りごと）
・99_アーカイブ（終わったもの）

■ 手順2：私に質問して、自分メモ3枚を作る
1問ずつ質問してください（全部で10問まで）。答えにくそうなときは例を出してください。「あとで」と答えた項目は空欄のままにしてください。
1. 仕事・役割・担当している業務
2. 一緒に働く相手と、使っているツール
3. よく使うAIと、その使い分け
4. 文章や出力の好み（トーン・形式）
5. 仕事で大事にしていること
6. やらないと決めていること
7. 迷ったときの優先順位（上から3つ）
8. 今動いている案件（名前・現状・次にやること・期限）
9. 保留中の案件
10. AIに毎回説明し直していて面倒なこと
答えをもとに、次の3枚を作ってください。
・00_自分/自己紹介.md（1〜4と10）
・00_自分/判断基準.md（5〜7）
・00_自分/進行中.md（8と9。案件ごとに「現状／次にやること／期限」）
各ノートの先頭には、Obsidian のプロパティ（type／updated／tags）を付けてください。書き込む前に、3枚の中身を見せて確認をとってください。

■ 手順3：AI用のルールファイルを作る
ボルト直下に AGENTS.md を作り、次のルールを書いてください。
・作業の前に 00_自分 の3枚を読む
・Obsidian の書き方（プロパティ、[[ノート名]] のリンク）を崩さない
・ファイルの移動・削除・上書きの前に、変更一覧を見せて確認をとる
・根拠にしたノートは [[ノート名]] で示す。ボルトに無いことは「ボルトに情報なし」と書く
・読むのは指示されたフォルダだけ。ボルト全体を読むのは棚卸しを頼まれたときだけ
・私から修正を指示されたら、会話の最後に 00_自分/反省メモ.md へ「日付／何が起きたか／次から守ること」を1件追記する
続けて、ボルト直下に CLAUDE.md を作り、1行目に「@AGENTS.md」とだけ書いてください（Claude Code は CLAUDE.md を読み、この1行で AGENTS.md の中身も読み込むため）。

■ 手順4：Obsidian の書き方をAIに覚えさせる
Obsidian 公式のAI向けスキル集「obsidian-skills」が使える状態か確認してください。
入っていなければ、入れ方だけを説明してください（Codex は skills フォルダを ~/.codex/skills へ、Claude Code はボルト直下の .claude フォルダへ）。私の許可なしにインストールはしないでください。

■ 手順5：週1回の整理ルールを書く
00_自分/進行中.md の末尾に、次の2行を書いてください。
・毎週金曜：終わった案件は 99_アーカイブ へ移す
・2週間動きのない案件は「保留」に移し、続けるか私に確認する

■ 最後に
作ったフォルダとファイルを表で一覧にし、「明日から最初にやること」を3行で教えてください。
```

- **つまずきどころ**: 質問に全部きれいに答えなくて大丈夫です。分からない所は「あとで」と答えれば空欄のまま作られるので、次の日に「進行中.md を一緒に埋めて」と頼めば続きから埋められます。すでにメモがあるボルトで使っても、手順1で「あるフォルダには触れない」と指示しているので、勝手な移動や削除は起きません。

**ポイント**: できあがった3枚は、週に1回だけ見直してください。古い前提のまま置いておくと、AIも古い前提で動きます。
