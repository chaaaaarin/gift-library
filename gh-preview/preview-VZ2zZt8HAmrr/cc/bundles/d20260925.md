# 🎁 Claude Code 初日セットアップ 丸投げプロンプト

貼るだけで、Claude Code 自身が「今の環境を診断 → ccusage・statusline・完了通知フックを入れる手順を1つずつ提示 → settings.json の雛形を作成」まで代行します。10本の解説を読む前に、その日のうちに「使ったお金が見える・切りどきが分かる・終わりに気づける」の3点がそろいます。黒い画面が苦手でも、コマンドは自分で実行しない設定にしてあるので安全に試せます。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: Claude Code を起動し、対象プロジェクトのルートで下の全文を貼って送信するだけです。出てきたコマンドは、中身を読んでから自分で1つずつ実行してください。

```text
あなたは、このマシンの Claude Code 環境を診断して、
「使ったお金とコストが見える状態」を最短で作る担当です。
コマンドを勝手に実行せず、私が自分で実行できる形で提示だけしてください。

【前提】
- 私はこのプロジェクトで日常的に Claude Code を使い始めたところです。
- ターミナル操作にあまり慣れていません。専門用語は一言かみ砕いて説明してください。
- 有料の外部サービス契約が必要になるものは、今回は提案に含めないでください。

【やってほしいこと】
1. 環境の確認
   - OS が macOS / Linux / Windows のどれかを判定して報告してください。
   - node（Node.js）と bun が入っているか、`node -v` `bun -v` 相当で確認する
     コマンドを提示し、入っていない場合の入れ方も1行で添えてください。
   - ~/.claude/settings.json が既にあるかどうかを確認するコマンドを提示してください。

2. 導入手順の提示（3点。それぞれ「実行コマンド」と「これで何が変わるか1行」をセットで）
   a. ccusage : 使ったトークンとコストを日別・モデル別に出す。まず `npx ccusage@latest`
      をそのまま試すコマンドと、その読み方（どの列が金額か）を説明してください。
   b. ccstatusline : 画面下に「残りコンテキスト・コスト・git ブランチ」を常時表示する。
      `npx -y ccstatusline@latest` で対話設定に入る手順と、最小構成（3項目だけ）の
      おすすめを提示してください。
   c. 完了通知フック : Claude が入力待ち・完了になったら OS の通知を出す。
      私の OS に合った Notification フックのコマンド（macOS は osascript、
      Linux は notify-send、Windows は PowerShell）を1つ選んで提示してください。

3. settings.json の雛形
   - 上の c を反映した ~/.claude/settings.json の JSON を、
     既存の設定を壊さない形（hooks キーに Notification を追記する形。
     既存 hooks があれば兄弟キーとして足す）で書いてください。
   - すでに settings.json がある場合は「この部分だけ足す」という差分の形で示してください。

【出力形式】
- 「1. 環境の確認」「2. 導入手順」「3. 雛形」の3見出しで、番号付きで。
- コマンドは1行ずつ独立したコードブロックにして、コピーしやすくしてください。
- 最後に「今日はここまでやれば十分」という1〜3個の最小ステップを箇条書きでまとめてください。

【制約】
- コマンドを私のマシンで実行しないでください。提示だけにとどめてください。
- 判断に迷うところ（OS が特定できない、Node が無い等）は、進めずに私に質問してください。
- 出力はレビューしてから実行する前提で書いてください。
```

**ポイント**: 「実行しないで、提示だけ」と釘を刺してあるので、出てきたコマンドは必ず中身を読んでから自分で流してください。ccusage の金額は、定額プラン（Pro / Max）の場合は API 単価換算の推定額で、実請求とは一致しません。

# 🎁 10ツール 導入＆撤退 早見シート

10本それぞれの「入れるコマンド → 最初の確認方法 → 向かない人 → 合わなかった時の戻し方」を1枚にまとめた実践チェックリストです。入れる前にこの1枚を見ておくと、「入れたけど使えなかった」「消し方が分からない」で詰まらなくなります。上から順に、Claude Code を入れた初日から使い込むまでの順で並んでいます。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 気になったツールの行だけ見て、コマンドを1つ実行 → 「最初の確認」で動いたか確かめる → 合わなければ「戻し方」で消す。1日1本ずつで十分です。

```text
【10ツール 導入＆撤退 早見シート】

■ ステップ1：まず「見える化」3点（初日にやる）

□ ①ccusage を試す（使ったトークンとコストを日別・モデル別に出す）
  → 実行: npx ccusage@latest
  → 最初の確認: 日付ごとの表と "Total" の金額（USD）が出れば成功
  → 向かない人: 定額プラン（Pro/Max）で「実際の請求額」を知りたい人
    （出るのは API 単価換算の推定額。実請求とは一致しない）
  → 戻し方: インストール不要（npx はその場実行）。残るファイルなし
  指示例: 「ccusage の出力の見方を説明して。どの列が実コストの推定額？」

□ ②ccstatusline を入れる（画面下に 残量・コスト・ブランチ を常時表示）
  → 実行: npx -y ccstatusline@latest  （対話画面で項目を選ぶ）
  → 最初の確認: Claude Code を開き直し、いちばん下の行に情報バーが出れば成功
  → 向かない人: 画面をすっきり保ちたい人／Node.js も Bun も入れたくない人
  → 戻し方: ~/.claude/settings.json の "statusLine" のブロックを削除して保存
  指示例: 「statusLine の設定を settings.json から外して、元の表示に戻して」

□ ⑧完了通知フックを1つ足す（入力待ち・完了で OS の通知）
  → 実行: ~/.claude/settings.json の "hooks" に "Notification" を追記
    （macOS は osascript、Linux は notify-send、Windows は PowerShell）
  → 最初の確認: 手動許可モードにして作業を投げ、席を立つと通知が来れば成功
  → 向かない人: 通知が多いと無視してしまう人（1日で慣れて効かなくなる）
  → 戻し方: settings.json の "Notification" ブロックを削除して保存
  指示例: 「私の OS 用の Notification フックを settings.json に追記して。
           既存の hooks は壊さないで」

■ ステップ2：初期設定を整える

□ ③claude-code-templates（CLAUDE.md・エージェント・コマンド・MCP を選んで導入）
  → 実行: npx claude-code-templates@latest
  → 最初の確認: 選んだ要素が .claude/ 以下に作られていれば成功
  → 向かない人: 何が効いているか常に把握したい人（入れすぎると切り分け不能）
    ／寄せ集めの品質・ライセンスのばらつきが気になる人
  → 戻し方: .claude/ 以下に追加されたファイル／フォルダを手で削除
  指示例: 「.claude/ に今週追加されたファイルを一覧にして。各行が何をするものか1行で」

□ ④公式プラグイン マーケットプレイス（Anthropic 選定の拡張を1コマンドで）
  → 実行: /plugin  でマネージャを開く → /plugin install <名前>@claude-plugins-official
  → 最初の確認: /help の Custom commands タブに <プラグイン名>: が並べば成功
  → 向かない人: 公式マーケットの品ぞろえ（数が絞られている）で足りない人
    → コミュニティ版は玉石混交。フック・MCP は入れる前に中身を見る
  → 戻し方: /plugin のマネージャから該当プラグインを uninstall
  指示例: 「今入っているプラグインを一覧にして。それぞれが追加するフックと MCP を教えて」

■ ステップ3：できることを広げる

□ ⑤Playwright MCP（作った画面を Claude 自身に開いて確かめさせる）
  → 実行: claude mcp add playwright npx @playwright/mcp@latest
  → 最初の確認: claude mcp list に playwright が出て、
    「localhost:xxxx を開いてトップの見出しを読んで」が通れば成功
  → 向かない人: 触らせる範囲を絞れない人（公式が「セキュリティの防壁ではない」と明記）
    ／1回のやり取りのトークンを増やしたくない人
  → 戻し方: claude mcp remove playwright
  指示例: 「Playwright MCP で http://localhost:3000 を開いて、
           フォーム送信まで一連の動作確認をして。結果を箇条書きで」

□ ⑥claude-code-router（操作感そのままで別モデルに振り分け）
  → 実行: npm install -g @musistudio/claude-code-router  → ccr ui
  → 最初の確認: 管理画面が開き、ログにモデルの振り分け結果が出れば成功
  → 向かない人: 非公式の中継を挟みたくない人／各モデルのプロバイダ規約を
    自分で確認する時間がない人／設定を最小に保ちたい人（Node.js 22 以上が必要）
  → 戻し方: ccr を経由しない起動に戻す（通常の claude で起動）。
    不要なら npm uninstall -g @musistudio/claude-code-router
  指示例: 「調べ物・要約は安いモデル、コード修正は既定モデル、という
           振り分けルールの設定例を作って。各行に狙いのコメントを付けて」

■ ステップ4：回し方を強くする

□ ⑦ccmanager / Claude Squad（git worktree ごとにセッションを分けて並行作業）
  → 実行（ccmanager）: npm install -g ccmanager  → ccmanager
    実行（Claude Squad）: brew install claude-squad  → cs
  → 最初の確認: 作った worktree ごとにセッション行が並び、
    「作業中／入力待ち／待機」の状態が見えれば成功
  → 向かない人: git worktree・tmux を触ったことがない人
    ／Claude Squad は AGPL-3.0 なので、自社サービスへの組み込みを考えている人
    ／並行させるとレビューが追いつかない人
  → 戻し方: セッションを終了し、git worktree remove <パス> で作業フォルダを削除。
    ツール自体は npm uninstall -g ccmanager
  指示例: 「今ある worktree を一覧にして、マージ済みのものを教えて。削除コマンドも出して」

■ ステップ5：どこからでも・自分好みに

□ ⑨Happy（スマホから Claude Code の進捗を見る・指示する）
  → 実行: npm install -g happy  → 通常の claude の代わりに happy で起動
  → 最初の確認: スマホアプリでペアリングし、PC の作業がスマホに表示されれば成功
  → 向かない人: 端末間同期の中継サーバーを経由したくない人
    （自分で立てることは可能）／公式アプリでないと困る人
  → 戻し方: happy を使わず通常の claude で起動する。
    不要なら npm uninstall -g happy
  指示例: （Happy 側の操作なので Claude Code への指示は不要）

□ ⑩tweakcc（テーマ・思考中の表示語などを微調整）
  → 実行: npx tweakcc  （対話画面で色・表示を選ぶ）
  → 最初の確認: Claude Code を開き直し、テーマや思考表示が変わっていれば成功
  → 向かない人: Claude Code を頻繁に更新する人
    （更新のたびに npx tweakcc --apply で当て直しが必要）
    ／機能が増えると期待している人（見た目・体感の調整だけ）
  → 戻し方: npx tweakcc で「Restore original」を選ぶ（元の cli.js に戻す）
  指示例: （tweakcc 側の操作なので Claude Code への指示は不要）

■ 迷ったら：今日やる3つだけ
  □ ①ccusage で先月いくら使ったか出す
  □ ②ccstatusline で画面下に残量を出す
  □ ⑧完了通知フックを1つ足す
  → この3つが入れば、体感はいちばん変わる。残りは困ったときに戻ってくればいい。
```

**ポイント**: コマンドは中身を読んでから実行してください。特に ⑥⑦⑧はグローバルインストールや設定ファイルの変更を伴うので、「戻し方」の行を先に確認しておくと安心です。
