# 🎁 X自動投稿エージェント AGENTS.md / CLAUDE.mdテンプレート

Codex（AGENTS.md）やClaude Code（CLAUDE.md）にそのまま置ける、X自動運用エージェント用の運用ルールです。書き込み前レビュー・レート制限対策・コスト意識を最初から組み込んであります。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: プロジェクト直下に `AGENTS.md`（Codex）または `CLAUDE.md`（Claude Code）として保存するだけです。

```text
# X自動運用エージェント運用ルール

## 基本方針
- このエージェントはX(Twitter)の投稿・記事下書き・ネタ収集・分析を担当する。
- 目的は「作業の下ごしらえを自動化すること」であり、「人間の確認なしに公開すること」ではない。

## 書き込み操作は必ずユーザー確認を取る
- 投稿(post)、記事公開(article_publish)、フォロー、DM、ブックマーク操作など
  アカウントの状態を変える操作はすべて、実行前に内容をユーザーに提示し、
  明示的な承認を得てから実行する。
- 「下書きを作成して」という指示だけを受けた場合、勝手に公開まで進めない。
- 承認を待つ間にタスクがタイムアウトしそうな場合は、下書きの内容を
  ファイルまたはチャットに残してから待機する。

## レート制限・エラー時のフォールバック
- 429(レート制限)や5xxエラーを受けたら、即座にリトライせず指数バックオフで待機する
  (目安: 1回目30秒→2回目2分→3回目5分、3回失敗したら人間に報告して停止)。
- 記事投稿がAPI経由で一定回数(目安: 1日10回程度)に達して失敗する場合は、
  Computer Use(ブラウザ操作)による代替投稿に切り替えてよいか確認を取る。
- X APIのクレジット切れ(402エラー等)を検知したら、投稿を止めて
  ユーザーに残高不足を報告する。黙って別の方法で投稿を強行しない。

## トーン・品質チェック(生成役と検証役を分ける)
- 生成した投稿文・記事は、公開前に次を確認してから提示する。
  - ブランドトーン(普段の口調・一人称)から外れていないか
  - ハッシュタグを不自然に詰め込んでいないか
  - 誇張・断定しすぎた表現がないか
- 可能であれば、このチェックは生成したエージェント自身の自己申告だけで済ませず、
  別セッション/別エージェントに「検証役」として同じ基準でチェックさせる
  (同じエージェントに生成と採点の両方を任せ続けると、チェックが徐々に
  甘くなりやすいため)。
- チェックで疑わしい点があれば、修正案と一緒に理由をユーザーに提示する。

## コスト意識
- 書き込み系操作(投稿・記事公開)は従量課金であることを前提に、
  同じ内容を無駄に複数回実行しない。
- 大量の読み取り(検索・タイムライン取得等)を伴うタスクは、
  実行前に想定件数をユーザーに伝える。

## 規約遵守
- 自動フォロー・自動いいね・自動RT・自動DMなど、
  エンゲージメントファーミングに該当する操作は行わない。
- Bot運用であることをアカウントのbio等に明記する運用を前提とする。
```

**ポイント**: 「書き込み前ユーザー確認」の項目は削らずそのまま使うことを推奨します。ここを外すと誤投稿・規約違反のリスクが一気に上がります。

# 🎁 GitHub Actions 定時実行ワークフロー例

X投稿ワークフローをリポジトリで管理したい場合の、GitHub Actions定時実行のひな形です。実際に投稿文を作る部分は自分のスクリプト・エージェント呼び出しに差し替えて使います。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: `.github/workflows/x-post.yml` として保存し、リポジトリのSecretsに認証情報を登録してから使います。

```text
name: x-scheduled-post

on:
  schedule:
    # 毎日 09:00 JST (UTC 00:00) に実行
    - cron: "0 0 * * *"
  workflow_dispatch: {}   # 手動実行もできるようにしておく

concurrency:
  group: x-scheduled-post
  cancel-in-progress: false

jobs:
  post:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - name: リポジトリをチェックアウト
        uses: actions/checkout@v4

      - name: Node.jsをセットアップ
        uses: actions/setup-node@v4
        with:
          node-version: "20"

      - name: xurlをインストール
        run: npm install -g @xdevplatform/xurl

      - name: 投稿スクリプトを実行
        env:
          CLIENT_ID: ${{ secrets.X_CLIENT_ID }}
          CLIENT_SECRET: ${{ secrets.X_CLIENT_SECRET }}
        run: |
          # ここで投稿文を生成し、429/5xxは指数バックオフで最大3回リトライする
          # 失敗が続く場合はジョブを失敗させて通知に委ねる(黙って握りつぶさない)
          node scripts/generate-and-post.js

      - name: 失敗時にSlack通知
        if: failure()
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}
        run: |
          curl -X POST -H 'Content-type: application/json' \
            --data '{"text":"x-scheduled-post が失敗しました。ログを確認してください。"}' \
            "$SLACK_WEBHOOK_URL"
```

**ポイント**: `cancel-in-progress: false` にしているのは、前回の投稿処理が終わる前に次のcronが重複起動して二重投稿するのを防ぐためです。認証情報は必ずGitHub Secretsに登録し、YAMLに直書きしないでください。

# 🎁 投稿・記事Markdownテンプレート

X運用でよく使う型を、通常ポスト用3種と記事(Article)用1種のテンプレートにまとめました。〇〇の部分を埋めるだけで下書きの土台になります。

**使い方**: 該当する型をコピーし、〇〇部分を埋めてからAIに「この型に沿って清書して」と渡すと安定します。

```text
## 型A: 結論先出し型(通常ポスト)
〇〇は△△だった。

・理由1
・理由2
・理由3
詳細はスレッドで。

## 型B: 問いかけ型(通常ポスト)
〇〇について、こう思ったことはないですか？
「△△」
実は□□という理由があります。
(1〜2行で簡潔に)

## 型C: 体験談型(通常ポスト)
実際に〇〇をやってみた。
起きたこと: △△
直したこと: □□
学び: ××

## 型D: 記事(Article)雛形

## 結論
150字程度で、この記事で伝えたいことを先に書く。

## 背景・問題提起
なぜこの話をするのか、どんな悩み・疑問から始まったかを書く。

具体的な内容。数字や実例があれば入れる。

## 本論2: △△
本論1と対になる視点、または発展した内容。
```

# 🎁 X公式MCP セットアップ手順

Codex・Claude Code・CursorなどからXの公式MCP（`api.x.com/mcp`）に接続するための手順です。X Developer Consoleでのアプリ作成からOAuth認証まで、初回セットアップに必要な工程をまとめました。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 上から順番に進めてください。⑤の設定ファイルは自分が使うツール（Claude Desktop / Cursor / VS Code等）に合わせて置き場所を変えます。

```text
# X公式MCP セットアップ手順

## ① X Developer Consoleでアプリを作成
1. X Developer Consoleにログインし、新規アプリを作成する。
2. アプリの「User authentication settings」でOAuth 2.0を有効化する。
3. App permissionsは「Read and Write」を選択する(投稿・記事作成に必要)。
4. App typeは「Web App, Automated App or Bot」を選択する。
5. Callback URI / Redirect URLに次を完全一致で登録する:
   http://localhost:8080/callback
6. Website URLは任意(自分のサイト等で問題ない)。

## ② CLIENT_ID / CLIENT_SECRETを取得
- 保存後に表示されるClient IDとClient Secretを控える。
- この2つは秘密情報として扱い、チャット・ログ・共有設定ファイルに直接書かない。

## ③ xurlをインストール(いずれか1つ)
brew install --cask xdevplatform/tap/xurl
npm install -g @xdevplatform/xurl
curl -fsSL https://raw.githubusercontent.com/xdevplatform/xurl/main/install.sh | bash

## ④ MCPクライアント設定(例: Claude Desktop / Cursor共通形式)
{
  "mcpServers": {
    "xapi": {
      "command": "npx",
      "args": ["-y", "@xdevplatform/xurl", "mcp", "https://api.x.com/mcp"],
      "env": {
        "CLIENT_ID": "取得したCLIENT_ID",
        "CLIENT_SECRET": "取得したCLIENT_SECRET"
      }
    },
    "x-docs": {
      "url": "https://docs.x.com/mcp"
    }
  }
}
- Claude Desktopの場合: claude_desktop_config.json に上記を追記して再起動。
- Cursorの場合: .cursor/mcp.json (プロジェクト単位) または ~/.cursor/mcp.json (全体) に追記。
- startup_timeout_sec は300以上に設定する(初回ブラウザログインを待つため)。

## ⑤ 初回ログイン
1. 設定後、ツールを起動しXのツールが呼ばれるタイミングでブラウザが自動で開く。
2. 投稿したいXアカウントでログインし、アプリの連携を許可する。
3. 以降はトークンが自動更新されるため、再ログインは基本的に不要。

## ⑥ 動作確認
- 「Xで自分の直近の投稿を3件取得して」のような読み取り系の指示から試す。
- 書き込み系(投稿・記事公開)は、AGENTS.md/CLAUDE.mdの運用ルール
  (書き込み前ユーザー確認)が効いているかを必ず確認してから使う。

## つまずきやすいポイント
- 「アプリにアクセスできません」エラー → OAuth 2.0が有効か、
  Callback URLが完全一致しているか、権限がRead and Writeになっているかを確認。
- 401エラーが続く → CLIENT_ID/CLIENT_SECRETが正しい環境変数に
  渡っているか、トークンの再ログインが必要か確認。
- ツール一覧にXの項目が出てこない → クライアントを一度再起動する。
- 記事投稿がある回数で失敗し始める → API側の書き込みレート制限の
  可能性が高い。時間を空けるか、ブラウザ操作での代替投稿を検討する。
```

**ポイント**: CLIENT_SECRETやアクセストークンは、設定ファイルにそのまま書かず環境変数経由で渡す運用も検討してください。

# 🎁 X投稿前チェックリスト

自動生成した投稿・記事を公開する前に、規約・レート制限・レビューの観点で最終確認するためのチェックリストです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 投稿・記事公開の直前に、上から順にチェックしてください。1つでも✗があれば公開を止めます。

