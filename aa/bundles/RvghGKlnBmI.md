# 🎁 OpenCodex導入トラブルシューティング＆接続チェックリスト

OpenCodexのセットアップでよくあるつまずきを、ステップごとに確認できる形にまとめました。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: セットアップの手が止まった時に、該当するステップを上から確認してください。

```text
【OpenCodex導入トラブルシューティング＆接続チェックリスト】

■ ステップ1：インストール前の確認
□ Node.js 18以上が入っているか（ターミナルで node -v を実行）
→ YES: そのままインストールへ進む
□ 入っていない、またはバージョンが古い
→ YES: 公式サイトから最新のNode.jsをインストールしてからやり直す

■ ステップ2：インストールと起動のつまずき
□ npm install -g @bitkyc08/opencodex でエラーが出る
→ YES: 権限エラーの場合が多いので、案内された別コマンドで再インストールを試す
□ ocx start してもブラウザで管理画面が開かない
→ YES: ターミナルに表示されたURL（通常 http://localhost:10100）を手動でコピーしてブラウザに貼る

■ ステップ3：プロバイダー接続時の確認
□ APIキー方式のプロバイダーを追加したのに、Codexのモデル選択肢に出てこない
→ YES: ocx start のターミナルは閉じずに、Codexアプリを一度完全に終了してから再起動する
□ 管理画面でプロバイダーが緑ランプにならない
→ YES: APIキーが正しくコピーされているか（前後の空白混入がないか）を確認し貼り直す
指示例: このAPIキーの前後に余分な空白や改行が入っていないか確認してください

■ ステップ4：ログイン型プロバイダー（xAI・Anthropic・Kimi等）の確認
□ ログインは成功したのに、モデルが選択肢に表示されない
→ YES: そのサービスが有料プラン・会員登録を必須としていないか確認する
□ 認証コードの入力画面が反応しない
→ YES: 一度ページを再読み込みしてから、ログインボタンを押し直す

■ ステップ5：Codex画面の表示が「OpenAI」のままに見える時
□ モデルを切り替えたはずなのに、画面上は「Codex OpenAI」と表示される
→ YES: 裏側では別AIが呼ばれている場合があるので、OpenCodex管理画面の「Logs」で実際の呼び出し先を確認する
□ ログ画面でも意図したAIが呼ばれていない
→ YES: モデル指定が provider/model 形式（例: anthropic/claude-opus-5）になっているか確認する

■ ステップ6：セッション・履歴のつまずき
□ OpenCodexを再起動したら過去の会話が消えた
→ YES: ピン留めされたセッションは残るため、重要な会話は事前にピン留めしておく
□ 元の状態（OpenAIモデルのみ）に戻したい
→ YES: OpenCodexのアンインストールコマンドを実行すると、Codexは元の状態に復元される

■ ステップ7：ローカルAI（Ollama）接続時の確認
□ Ollamaのモデルをダウンロードしたのに応答が遅い、または返らない
→ YES: 使用モデルのサイズがパソコンのメモリ容量に対して大きすぎないか確認する
□ Ollamaを無料プロバイダーとして追加したのにCodexに出てこない
→ YES: Ollama自体が起動した状態か確認してから、Codexを再起動する
```

**ポイント**: 迷ったら「Codexを一度完全に終了して再起動する」を先に試すと、多くのつまずきが解消します。
