# 🎁 コンテキスト予算セルフ診断シート

自分のCodex利用が、知らないうちに272,000トークン超の価格帯（入力2倍・出力1.5倍）を踏んでいないかを、5ステップで確認できるシートです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: そのままメモアプリやAGENTS.mdに貼り付け、月に一度チームや自分で見返してください。

```text
【コンテキスト予算セルフ診断シート】

■ ステップ1：現在の設定を確認する
□ ~/.codex/config.toml に model_context_window の指定はあるか
□ ある場合、その値は272,000を超えているか
→ YES: ステップ2へ進む
→ NO（デフォルトのまま）: 診断は不要。そのまま使って問題ない

■ ステップ2：超えている理由を確認する
□ 1M（またはそれに近い値）にした理由を、直近の作業内容で説明できるか（大型リファクタ等）
→ YES: ステップ3へ進む
→ NO（なんとなく設定した）: 一度デフォルトに戻す（設定を消すか、model_context_window=272000に戻す）
指示例: 「今の作業に本当に大きな窓が必要か、直近1週間のタスク内容を踏まえて判断して」とCodexに聞いてみる

■ ステップ3：利用経路を確認する
□ 契約はOpenAI公式（APIキーまたはChatGPTアカウント）か、それとも中継業者（再販業者）経由か
→ 中継業者経由の場合: 契約先の管理画面で「従量課金の切り替え」設定が有効になっているか必ず確認する
→ 公式契約の場合: ステップ4へ進む

■ ステップ4：コスト試算をする
□ 直近1週間で、272,000トークンを超えるセッションが何回あったか把握しているか
→ YES: おおよその追加コストを計算し、想定内かどうか確認する
→ NO: 次の1週間は作業の節目でAIに消費トークンの目安を報告させる運用に切り替える
指示例: 「このセッションでおおよそ何トークン使ったか、作業の節目で教えて」と伝えておく

■ ステップ5：運用ルールを固定する
□ 大きな窓を使う作業とデフォルトのままで良い作業の線引きができているか
→ YES: その線引きをAGENTS.mdかチームの運用メモに書き残す
→ NO: 「大型リファクタ・長時間の一気通貫作業のみ1M可、それ以外はデフォルト」のようなシンプルな基準から始める
```

**ポイント**: 一度診断して終わりにせず、月1回など定期的に見返すと、設定の変更忘れによる高額請求を防ぎやすくなります。

# 🎁 圧縮事故防止チェックリスト

コンテキスト窓の「圧縮（自動要約）」が起きたときにありがちな事故——以前決めた値を忘れる、却下したコードを再提案される等——を防ぐためのチェックリストです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 長時間セッションに入る前に一度目を通し、圧縮が起きそうなタイミングで該当項目を実行してください。

```text
【圧縮事故防止チェックリスト】

■ ステップ1：セッション開始時に確認する
□ model_auto_compact_token_limit（自動圧縮が発動するトークン数）を把握しているか
→ YES: ステップ2へ進む
→ NO: config.tomlを開いて確認する。未設定ならデフォルト値が使われている
指示例: 「今の設定で、圧縮は何トークンあたりで発動する？」とCodexに確認する

■ ステップ2：作業開始時にAGENTS.mdを最新化する
□ 直近で決まった命名規則・却下した実装方針が、AGENTS.mdに反映されているか
→ NO: 圧縮で消えてしまう前に、要点だけ先に書き足しておく
指示例: 「今回決まった方針を、AGENTS.mdに追記できる形で3行にまとめて」

■ ステップ3：圧縮が近そうなサインに気づく
□ Codexの応答が急に大枠の話に戻る、以前の指摘を繰り返す、といった兆候が出ていないか
→ YES: すぐにステップ4（要約の保存）を行う
→ NO: 通常どおり作業を継続する

■ ステップ4：圧縮前に要点を保存する
□ 直近の意思決定・却下した案・未着手のタスクを、圧縮前に書き出させたか
→ NO: 「ここまでの決定事項・却下した案・残タスクを箇条書きで要約して」と依頼してから続行する
指示例: 「圧縮される前に、今の状況を次のセッションでも使える形で要約して」

■ ステップ5：圧縮が起きた直後に検算する
□ 圧縮後の最初の応答で、以前決めた値や方針が正しく引き継がれているか
→ NO（ズレている）: 保存しておいた要約を貼り直し、正しい前提で再開する
→ YES: そのまま作業を続ける

■ ステップ6：セッションを終えるとき
□ 次回に持ち越す情報を、AGENTS.mdか作業メモに保存したか
→ NO: 終える前に「今日の要点を3行で」とまとめさせてから保存する
```

**ポイント**: 圧縮は「悪いこと」ではなく必ず起きる仕組みです。起きる前提で、要点をこまめに書き出す習慣をつけるのがいちばんの事故防止になります。
