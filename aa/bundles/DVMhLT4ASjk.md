# AIエージェント権限見直しチェックリスト

今週のAISI公式報告・Black Hatでの公表を踏まえ、自分が使っているAIエージェントの権限設定を点検するための実務チェックリストです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 業務でAIエージェントを導入している・検討している場合に、上から順にチェックしてください。

```text
【AIエージェント権限見直しチェックリスト】

■ ステップ1：現在の権限範囲を洗い出す
□ インターネットへの接続は許可されているか、許可範囲はどこまでか
□ ファイルの読み取り・書き込みはどの範囲まで許可されているか
□ 実行可能なコマンド・APIはどこまで許可されているか
指示例: 「今使っているAIエージェントの設定を確認し、インターネット接続・ファイル操作・コマンド実行それぞれの許可範囲を一覧にして」

■ ステップ2：評価環境と本番環境の条件差を確認する
□ 導入前のテスト・評価時に、本番より緩い権限設定を使っていないか
□ 評価用に無効化した安全フィルタ・制限が、本番でも無効のままになっていないか
→ YES(緩いままになっている): 本番切り替え時に権限設定を必ず引き締める
→ NO(適切に分離できている): 次のステップへ進む

■ ステップ3：異常行動の検知体制を確認する
□ エージェントが想定外の外部通信・ファイル操作をした場合、検知できる仕組みがあるか
□ 検知までにかかる時間の目安を把握しているか(今週の事例では公式報告で約1時間)
→ YES: 検知の仕組みを維持・強化する
→ NO: ログ監視やアラート設定の導入を検討する

■ ステップ4：停止・隔離までの導線を確認する
□ 異常を検知してから、エージェントを停止・隔離するまでの手順が明文化されているか
□ 誰が停止の判断・実行をする権限を持っているか決まっているか
指示例: 「エージェントの異常行動を検知した場合の停止・隔離手順を、担当者と手順つきで文書化して」

■ ステップ5：複数エージェント間の情報共有リスクを確認する
□ 複数のエージェントが同じリポジトリ・共有領域にアクセスできる設定になっていないか
□ エージェント同士が意図せず指示・認証情報を共有できる経路がないか
→ YES(共有できる経路がある): アクセス範囲を分離するか、共有領域への書き込み権限を見直す

■ ステップ6：定期見直しのスケジュールを決める
□ 権限設定を見直す頻度(月1回等)を決めているか
□ 新しいAIエージェント関連インシデントが報じられた際に、臨時で見直すルールがあるか
指示例: 「毎月最終営業日に、AIエージェントの権限設定一覧を見直すリマインダーを設定して」

■ 補足：意図的に緩い設定でテストする場合の注意
□ 評価目的で意図的に権限を緩めるテストを行う場合は、必ず隔離された環境で実施する
□ テスト終了後は権限設定を元に戻したことを、担当者以外の第三者も確認する
```

**ポイント**: 「今のところ問題が起きていない」は権限が適切という証拠にはならない。今週の事例はいずれも通常運用ではなく評価環境で発覚したものであり、本番相当の設定を定期的に点検する。

# AIニュース監視エージェント構築レシピ100選

週刊AIインシデント監視ログでも実際に使っている、AIニュースを自分の代わりに自動巡回・分類・報告してくれるエージェントを組むための指示文集です。分野別に10カテゴリ×10本、全100本入りです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: Claude Codeやチャット画面にそのまま貼り、〈対象企業名〉〈対象期間〉などの〈〉部分をご自身の状況に置き換えてください。cron等の定期実行に組み込む前提の指示文も含まれます。

## 監視対象リストの設計

### 1. ウォッチ企業リストの初期構築

```text
前提: AIニュースを監視したいが、毎回どの企業を追うか迷ってしまう。
指示: OpenAI・Anthropic・Google DeepMind・Meta AI・Microsoft・Alibaba・Moonshot AI・MiniMax等、主要AI企業のリストをまず作って。各社の公式ブログ・Release Notes・プレスルームのURLもセットで集めて。
出力形式: 企業名/公式ブログURL/プレスルームURL/優先度(高中低)の表。今後この一覧を巡回対象として使い回せる形にして。
```

### 2. ウォッチ対象モデルの棚卸し

```text
前提: 自分が業務で使っている・検討中のAIモデルだけを重点的に追いたい。
指示: 現在使用中/検討中のモデル名を教えるので、それぞれの提供元・公式アップデート告知の確認先(Changelog/Release Notes URL)を一覧化して。
出力形式: モデル名/提供元/更新情報の確認先URL/最終確認日(空欄)の表。次回以降、この表の最終確認日を更新しながら使う運用にして。
```

### 3. 競合サービスのウォッチリスト化

```text
前提: 自社サービスと競合するAI機能をリリースしている企業を把握しておきたい。
指示: 指定した自社領域(例: カスタマーサポートAI)に競合するサービスを提供する企業・プロダクトを検索し、リストアップして。各社の新機能告知チャネル(Twitter/X公式・ブログ)も確認して。
出力形式: 競合企業名/プロダクト名/新機能告知チャネルURL/直近の主要アップデート1行の表。
```

### 4. 業界インフルエンサー・研究者リストの作成

```text
前提: AI業界の一次情報を早く掴んでいる個人アカウントをフォローリスト化したい。
指示: AI研究者・業界アナリストで、新モデル発表や業界動向を早期に投稿する傾向のあるXアカウントを検索して、アカウント名・専門分野・フォロワー規模の目安を整理して。
出力形式: アカウント名(@handle)/専門分野/情報の早さの評判(あれば)の一覧。个人名の要不要は投稿を読んでから判断する前提で構わない。
```

### 5. 監視トピックのキーワード設計

```text
前提: 検索のたびにキーワードを考え直すのが面倒なので、定型セットを作っておきたい。
指示: 「新モデルリリース」「資金調達」「セキュリティインシデント」「規制」「人事異動」の5カテゴリそれぞれについて、WebSearchで使う検索キーワードの組み合わせを英語・日本語の両方で複数案作って。
出力形式: カテゴリ名ごとに、日本語キーワード案3つ・英語キーワード案3つの箇条書き。今後の検索プロンプトにそのまま流用できる形式で。
```

### 6. RSS/公式フィードの収集先一覧化

```text
前提: 公式発表をSNS経由でなく直接フィードで受け取りたい。
指示: 主要AI企業・研究機関の公式ブログRSSフィード、または相当するフィード代替(Release Notesページ等)のURLを確認して一覧化して。RSSが無い場合は代替の巡回先を明記して。
出力形式: 企業名/RSSフィードURL(または代替巡回先)/フィード形式(RSS/Atom/なし)の表。
```

### 7. 重複排除ルールの設計

```text
前提: 同じニュースを複数ソースで見つけて二重報告してしまうのを防ぎたい。
指示: 同一ニュースを複数の検索結果から見つけたときに「同一事案」と判定するための基準(発表日・企業名・キーワードの一致度)を提案して。
出力形式: 判定基準を3〜4項目の箇条書きで。基準を満たしたら「重複」として1件にまとめるルールも明記して。
```

### 8. 監視対象の優先度マトリクス作成

```text
前提: 全部を同じ熱量で追うと疲れるので、重要度に応じてメリハリをつけたい。
指示: 自分の業務内容(具体的に伝える)を踏まえ、監視対象の企業・トピックを「毎日確認」「週1確認」「月1確認」の3段階に振り分けて。
出力形式: 頻度段階ごとの対象リスト(表または箇条書き)。振り分けた理由も1行ずつ添えて。
```

### 9. 除外ルールの設計

```text
前提: 自分の業務に関係ないAIニュース(例: ゲームAI等)まで拾ってしまうのを防ぎたい。
指示: 自分が関心を持たない領域(具体的に伝える)を教えるので、検索結果からそれらを除外するための除外キーワード・除外ドメインの案を作って。
出力形式: 除外キーワード一覧・除外ドメイン一覧を箇条書きで。誤って重要ニュースまで除外しないよう、除外条件の粒度に注意して。
```

### 10. 監視リストの定期見直しルール

```text
前提: 作ったウォッチリストが古くなっていないか、定期的にチェックする仕組みが欲しい。
指示: 月1回、これまでのウォッチリスト(企業・モデル・キーワード)を見直し、直近3か月ニュースに出てこない対象は「格下げ」、新たに頻出する対象は「追加候補」として提案する手順を作って。
出力形式: 「見直し手順」を3〜4ステップの箇条書きで。判定基準(頻出回数の目安等)も数字で明記して。
```

### 3. 今週のAIニュース緊急度診断シート（チェックリスト）
# 見つけたAIニュースが「今すぐ動くべきもの」か「知識として蓄積しておけばよいもの」かを、その場で判定するためのチェックリストです。

# 今週のAIニュース緊急度診断シート

見つけたAIニュースが「今すぐ動くべきもの」か「知識として蓄積しておけばよいもの」かを、その場で判定するためのチェックリストです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 気になったニュースを見るたびに、このシートに沿って上から順にチェックしてください。

```text
【今週のAIニュース緊急度診断シート】

■ ステップ1：severityタグを特定する
□ AIエージェントの誤作動・セキュリティ事案に関する内容か → ALERT
□ 経営トップ・組織体制・投資マネーに関する内容か → SHIFT
□ 新モデル・新機能のリリースに関する内容か → DEPLOY
□ 法制度・政府の枠組みに関する内容か → COMPLIANCE
□ スマホ・開発ツールなど身近な変化に関する内容か → LIFE
指示例: 「このニュースがALERT/SHIFT/DEPLOY/COMPLIANCE/LIFEのどれに当たるか、理由も添えて判定して」

■ ステップ2：影響範囲を確認する
□ 自分(自社)の業務・利用中のサービスに直結するか
□ 業界内では話題だが自分には直結しないか
□ 一般ユーザーの生活にまで及ぶ話か
→ YES(自分に直結): ステップ3以降を必ず進める
→ NO(直結しない): 知識として記録するだけでよい

■ ステップ3：不可逆性を確認する
□ 期限までに動かないと手遅れになる話か(例: サービス終了・移行期限)
□ 後からいつでも対応できる話か(例: 新機能の追加)
→ YES(期限あり): 緊急度を1段階引き上げる
→ NO(いつでも対応可): 通常の優先度のままでよい

■ ステップ4：緊急度スコアを算出する
□ ステップ2・3で「YES」が多いほど緊急度は高い
→ 2項目ともYES: 緊急度「高」
→ 1項目のみYES: 緊急度「中」
→ どちらもNO: 緊急度「低」

■ ステップ5：緊急度に応じて行動する
□ 緊急度「高」 → 今日中に社内共有・対応方針を検討する
□ 緊急度「中」 → 今週中に詳細を確認し、必要なら対応を検討する
□ 緊急度「低」 → 知識として記録し、月次の振り返りでまとめて見返す
指示例: 「このニュースリストの各項目に緊急度(高/中/低)を付けて、高評価の項目には今日中にやるべきことを1行で添えて」

■ 補足：ALERTタグは無条件で緊急度を1段階引き上げる
□ AIエージェントの権限逸脱・セキュリティインシデントに関する情報は、影響範囲が見えるまで様子見にしない
□ 自社で同種のツールを使っている場合は、ステップ2の判定を待たずに権限設定を確認する
```

**ポイント**: 緊急度は「ニュースの話題性」ではなく「自分が動かないと手遅れになるか」だけで判定する。話題性で「高」を付けない。
