# 🎁 メール・議事録・報告が“考えずに片づく” Astra仕事プロンプト10選

毎日発生するのに地味に時間を食う事務作業——メール処理、議事録整理、資料の下書き、日報——を、Astraに貼るだけで終わらせる10本です。1本ごとに「前提・指示・出力形式」まで書き込んであるので、名前や条件を差し替えればそのまま動きます。全部使うと、1日あたり30〜60分の“作業ではない作業”が消えます。

**受け取り方**: 下の各コードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 1〜3はメール、4〜5は会議まわり、6〜8は資料・数字、9〜10は1日の締め。`（　）` の部分を自分の状況に置き換えて貼ってください。

---

## 1. 長いメールスレッドを「3行＋次アクション」に要約

```text
期待できるメリット: 20往復あるスレッドを読み返す10分が、30秒で「今どうなっていて、次に何をすべきか」が分かる状態になる。返信の抜け漏れが減る。
使う場面: 出張・休み明け、または横から入った案件で、長いスレッドの経緯を素早く把握したいとき。
前提・状況: スレッド全文を貼り付けられる。関係者は複数。
指示: これから貼るメールスレッドを読んで、(1)現在の状況を3行以内、(2)決まったこと・決まっていないこと、(3)私（受信者）が次に取るべきアクションと締め切り、を整理してください。誰が何を言ったかの発言者は明記し、推測で補った部分は「※推測」と付けてください。
出力形式・制約: 「状況（3行）／決定事項／未決事項／私の次アクション（期限つき）」の見出し順。全体で15行以内。敬語や挨拶文は不要、事実だけ。
つまずきどころ: スレッドの一部だけ貼ると誤読する。引用のネスト（>>>）が深くても全文貼る。日付が本文に無いと時系列がずれるので、分かる範囲で送信日時も残して貼る。
```

## 2. 受信メールへの返信ドラフトを3トーンで用意

```text
期待できるメリット: 「なんて返そう」で止まっていた時間がなくなる。丁寧さの強度違いを見比べて選べるので、送信前の推敲が最小限で済む。
使う場面: 少し気を使う相手（社外・上位者・クレーム気味）への返信を書くとき。
前提・状況: 相手のメール本文と、こちらが伝えたい結論（YES/NO/条件つき等）が決まっている。
指示: 次のメールへの返信案を、トーン違いで3つ作ってください。伝えたい結論は「（例：納期は2週間ずらしたい。理由は先方都合の仕様変更）」。案A=丁寧かつ簡潔、案B=より低姿勢でクッション多め、案C=対等でビジネスライク。いずれも言い訳がましくならないようにし、代替案を必ず1つ添えてください。
出力形式・制約: 各案は件名＋本文、本文は200字前後。冒頭の時候の挨拶は入れない。相手を責める表現・過度な謝罪の連発は避ける。
つまずきどころ: 結論を曖昧に渡すと3案とも歯切れが悪くなる。「何を・いつまでに・なぜ」を1文で先に固めてから貼る。
```

## 3. 溜まった未読メールを重要度順に仕分け

```text
期待できるメリット: 受信トレイを上から順に開いて消耗する時間がなくなる。「今日中に返すべき5件」だけに集中できる。
使う場面: 朝イチ、または会議が続いた後で未読が20〜50件たまっているとき。
前提・状況: 未読メールの「送信者・件名・冒頭2〜3行」を一覧で貼り付けられる。
指示: これから貼る未読メール一覧を、対応の緊急度で並べ替えてください。判断軸は、期限の明示／依頼か情報共有か／自分が一次対応者か。各メールに「今日返す・今週中・見るだけ・無視可」のいずれかを付け、今日返す分にはひとことで返信方針を添えてください。
出力形式・制約: 「区分／送信者／件名／ひとこと方針」の表。今日返す分を上に。全体で30行以内。原文の引用はしない。
つまずきどころ: 本文冒頭しか貼らないと「実は末尾に依頼がある」メールを取りこぼす。依頼系は本文全部を貼る。社内の定例通知はまとめて「見るだけ」に落として構わない。
```

## 4. 会議のアジェンダを目的・時間配分つきで作成

```text
期待できるメリット: 「とりあえず集まる」会議が、始まる前から着地点の見える会議になる。準備の15分が3分になり、会議自体も短くなる。
使う場面: 自分が主催する打ち合わせの招集前、議題がぼんやりしているとき。
前提・状況: 会議の相手・持ち時間・ざっくりした目的が決まっている。
指示: 次の会議のアジェンダを作ってください。参加者は「（例：営業2名・開発1名・自分）」、時間は「（例：30分）」、達成したいこと（この会議のゴール）は「（例：次のリリース範囲を1つに決める）」。各議題に目的・所要時間・その場で出すべき結論を割り当て、最後に「決まらなかった場合の持ち帰り方」も入れてください。
出力形式・制約: 「ゴール（1行）／議題（番号・所要分・狙う結論）／終了時の確認事項」。合計時間が持ち時間を超えないように配分する。
つまずきどころ: ゴールを「共有する」「話し合う」にすると時間配分ができない。「◯◯を1つ決める」「◯◯の可否を判断する」のように動詞を具体化して渡す。
```

## 5. 議事メモを「決定・宿題・保留」に再構成

```text
期待できるメリット: 箇条書きの殴り書きメモが、そのまま関係者へ共有できる議事録になる。清書の20分がゼロになり、宿題の担当と期限が抜けなくなる。
使う場面: 会議直後、自分のメモアプリに断片的に書いた内容を整える必要があるとき。
前提・状況: 発言メモ（時系列・箇条書き・言い回しは雑でよい）を貼り付けられる。
指示: これから貼る会議メモを、(1)決定事項、(2)宿題（担当者・期限つき）、(3)保留・次回持ち越し、(4)共有事項、の4区分に整理してください。担当や期限がメモに無いものは「担当未定／期限未定」と明示し、勝手に埋めないでください。曖昧な発言は断定に変換せず「〜という意見」と残してください。
出力形式・制約: 4区分の見出し順。宿題は「担当／内容／期限」の表。全体をそのままメール貼り付けできる素のテキストで。冒頭に会議名と日付の空欄を用意する。
つまずきどころ: メモに主語が無いと宿題の担当が取れない。せめて発言者のイニシャルだけでもメモに残しておくと精度が上がる。
```

## 6. 資料・原稿のファクトチェックと穴の指摘

```text
期待できるメリット: 提出前に「数字は合っているか」「論理が飛んでいないか」を第三者目線で洗える。差し戻しや指摘での手戻りが減る。
使う場面: 提案書・記事・社内報告を出す直前のセルフレビュー。
前提・状況: 完成間近の本文を貼り付けられる。事実確認が必要な箇所が含まれる。
指示: これから貼る文章を、公開前提でレビューしてください。(1)事実・数値で裏取りが必要な箇所を抜き出し、確認方法を添える、(2)論理の飛躍・根拠不足の箇所、(3)誤解を招く表現、(4)冗長で削れる段落、を指摘してください。書き直しはせず、指摘と修正の方向性だけ挙げてください。
出力形式・制約: 「該当箇所（引用は10字程度）／種類／なぜ問題か／どう直すか」の表。重要度の高い順。文章全体の書き換え案は出さない。
つまずきどころ: 「良し悪しを評価して」と頼むと褒めるだけで終わる。「公開したら困る点を挙げて」と否定側で指示する。社外秘の数字を貼る場合は伏せ字にしてから渡す。
```

## 8. 数字レポートに添えるコメント文を書く

```text
期待できるメリット: 「先月比プラス8%、要因は〜」の説明文を毎月ゼロから考える時間がなくなる。数字の羅列が“読める報告”になる。
使う場面: 月次の売上・KPI・アクセス数などをまとめた表に、上司や役員向けの short コメントを付けるとき。
前提・状況: 主要な数値（今期・前期・前年同期など）と、増減の背景として思い当たることを箇条書きで渡せる。
指示: 次の数値にコメント文を付けてください。データは「（例：今月の問い合わせ数120件、先月98件、前年同月110件）」。増減の背景メモは「（例：今月から比較記事を2本公開／月末にキャンペーン）」。事実（数字）と解釈（要因）を分け、確証のない要因は「可能性がある」と表現してください。次月の見通しも1行入れてください。
出力形式・制約: 200字前後を2案。1案は淡々と、もう1案はやや前向きなトーン。誇張や断定的な因果（「〜のおかげで」）は避ける。
つまずきどころ: 背景メモを渡さないと当たり障りのない一般論になる。心当たりを3つほど箇条書きで添えると具体的なコメントになる。
```

## 9. ToDoの棚卸しと優先順位づけ

```text
期待できるメリット: 頭の中とメモに散らばったタスクが1枚に整理され、「今日やる3つ」が決まる。あれこれ気になって集中できない状態から抜けられる。
使う場面: 週明けや、タスクが増えて何から手を付けるか分からなくなったとき。
前提・状況: 抱えているタスクを思いつく順に箇条書きで書き出せる（粒度はバラバラでよい）。
指示: これから貼るタスク一覧を、緊急度（期限の近さ）と重要度（成果へのインパクト）の2軸で仕分けしてください。(1)今日やる（3つまで）、(2)今週やる、(3)人に振る・頼む、(4)やめる・後回し、に分類し、大きいタスクは最初の一歩だけ切り出してください。期限が不明なものは「要確認」と付けてください。
出力形式・制約: 4分類の見出し順。今日やる3つには「最初の一歩（15分で着手できる形）」を添える。全体で25行以内。
つまずきどころ: タスクの粒度が大きすぎる（例：「新サービスの企画」）と着手できない。「〜の草案を1枚書く」まで分解させると動ける。振れる相手がいるものは名前を書いておく。
```

## 10. 1日の終わりの日報と翌日の段取り

```text
期待できるメリット: 日報作成の10分が2分になり、書きながら「明日の朝いちで何をやるか」まで決まる。翌朝の助走時間が消える。
使う場面: 退勤前。今日やったことを軽くメモできる状態で、日報の提出と明日の準備をまとめて済ませたいとき。
前提・状況: 今日の作業を箇条書き（時間帯・内容・詰まった点）でざっと書き出せる。
指示: これから貼る今日のメモから、(1)日報（成果・進行中・課題の3項目）、(2)明日やることリスト（優先順にmax5件、各件に最初の一歩）、(3)関係者に共有・相談すべき事項、を作ってください。日報は事実ベースで、頑張ったアピールや反省文は入れないでください。
出力形式・制約: 日報はそのまま提出できる素のテキストで、各項目3行以内。明日やることは「タスク／最初の一歩／想定所要」。全体で20行以内。
つまずきどころ: メモに「詰まった点・中断した理由」を書いておかないと、明日やることの精度が落ちる。うまくいかなかったことも短く残してから貼る。
```

**ポイント**: どのプロンプトも、出力はそのまま提出せず必ず目を通してから使ってください。特に数字・固有名詞・日付は、Astraが埋めた箇所（「※推測」「要確認」と付く部分）を自分で確定させてから共有・送信してください。
