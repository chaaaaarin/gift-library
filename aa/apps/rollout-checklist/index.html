001ステップ1：プランと対象範囲を確認する
□ 自社のSlackプランがEnterprise/Teamか、Pro/Max相当かを確認したか
→ YES: Claude Tagが使えるのはEnterprise/Teamのみ。Pro/Max相当なら従来のClaude Code in Slack方式を検討する
□ Slack Codeを試す対象を、まず1チームに絞れているか
→ YES: 全社一斉導入ではなく、小さく始めて運用を確認してから広げる
指示例: 「自社のSlackプランと、Claude Tag対象範囲の候補チームを一覧化して」
002ステップ2：権限設計を決める
□ Claudeを常駐させるチャンネルの範囲（公開/非公開）を決めたか
→ YES: 「/invite @Claude」で追加した範囲だけが対象になることを関係者に周知する
□ チャンネルごとに、Claudeがアクセスできるツール・情報の範囲を管理者が設定したか
→ YES: 機密性の高いチャンネルには不要な連携ツールを付けない
□ トークン支出の上限を組織単位・チャンネル単位で設定したか
→ YES: 想定外のコスト増を防ぐため、まず低めの上限から始める
指示例: 「このチャンネルでClaudeに許可するツール・情報アクセスの範囲案を作って」
003ステップ3：セキュリティとレビュー体制を確認する
□ 本番環境への反映前に、必ず人による承認を挟むフローになっているか
→ YES: Slack Codeは承認必須の設計だが、運用ルールとして明文化しておく
□ 「チームで見ているから安心」で済ませず、レビューの質を保つ担当者を決めたか
→ YES: 忙しいチャンネルではレビューが形骸化しやすいため、責任者を明確にする
□ Claudeがスレッド内の他の指示に従う仕組みであることを、利用者に周知したか
→ YES: 信頼できない外部からの投稿が混ざるチャンネルでは特に注意喚起する
指示例: 「このチャンネルの承認フローと、レビュー担当者の割り当て案を整理して」
004ステップ4：コストと契約範囲を確認する
□ Slack Codeのチャンネル機能自体は無料だが、各AIエージェント本体は別契約が必要なことを関係者が理解しているか
→ YES: 「チャンネルが使えるから追加費用なし」という誤解を防ぐ
□ Claude Tagの導入クレジットの対象・期限を確認したか
→ YES: ベータ期間中の条件変更に備え、契約担当者と定期的に確認する
指示例: 「Slack CodeとClaude Tagそれぞれの費用構造を、社内向けに1枚で説明できる形にまとめて」
005ステップ5：移行・展開計画を立てる
□ 旧来のClaude in Slackアプリを使っている場合、移行期限と移行手順を確認したか
→ YES: 期限を過ぎると自動移行される場合があるため、事前に管理者が把握しておく
□ 1チームでの試験導入後、他チームへ展開する順序を決めたか
→ YES: 業務の定型度が高いチームから優先的に展開すると定着しやすい
□ 導入効果を測る指標（対応時間の短縮・PR起点の割合など）を決めたか
→ YES: 数字がないと「効果があったか」を後から判断できない
指示例: 「試験導入後、次に展開するチームの優先順位とその理由を提案して」

以上、5ステップです。ステップ1〜3は導入前に必須、ステップ4〜5は展開を広げる段階で確認してください。
