公式定番

001GitHub — 例1
このリポジトリの未マージのPRを一覧にして、レビュー待ちが長い順に並べて教えて。それぞれ、誰がレビュー待ちで止まっているか、放置されている日数も添えて。
002GitHub — 例2
このPRの差分を確認して、バグの可能性や設計上の懸念があれば指摘して。良い変更であればそれも伝えつつ、そのままレビューコメントとして投稿できる文面案を作って。
003GitHub — 例3
直近1週間にクローズされたIssueを一覧化して要約して。バグ報告と機能要望のどちらが多いか、対応に時間がかかった傾向があれば併せて教えて。
004Slack — 例1
このチャンネルの今日のやり取りを要約して。決定事項と、まだ誰も対応していないタスクを分けてリストにし、タスクには関係してそうな担当者も添えて。
005Slack — 例2
この質問に対する返信の下書きを、丁寧なトーン・簡潔なトーン・砕けたトーンの3パターンで作って。どれを送るか自分で選びたいので、それぞれ2〜3文程度でお願い。
006Slack — 例3
自分宛のメンションのうち、まだ返信していないものだけを抽出してリストにして。緊急度が高そうなものには印をつけて、返信の優先順位も提案して。
007Notion — 例1
この文字起こしをもとにミーティングメモをNotionのページとして整理して。決定事項・宿題（担当者と期限つき）・保留事項の3つに分けて、既存のミーティング議事録と同じ体裁で保存して。
008Notion — 例2
Notion内で〇〇に関連するページを検索して一覧にして。似た内容が複数見つかった場合は、どれが最新か・重複していないかも確認して教えて。
009Notion — 例3

010Gmail — 例1
今日届いたメールの中から、返信が必要なものだけを優先度順にまとめて。自動送信・お知らせメール等の返信不要なものは除外して、締切がありそうなものには理由も添えて。
011Gmail — 例2
このメールへの返信案を、丁寧だが簡潔なトーンで作って。相手からの質問には全て答えつつ、長くなりすぎないように要点だけに絞って。
012Gmail — 例3

014Google Drive — 例2

# 🎁 Codex神プラグイン30選 導入プロンプト90選

30個のプラグインを、1個につき3本ずつ「そのまま貼って試せる」プロンプトにしました。プラグインをインストールした後、対応するプロンプトを貼るだけで使い始められます。

**受け取り方**: 各カードのボタンでコピー、または全件ダウンロードしてください。GitHub上ではこのファイルのコードブロックから直接コピーできます。

**使い方**: 該当するプラグインをインストールしてから、対応する番号のプロンプトをCodexのチャット欄に貼り付けてください。

## 公式定番
### 1. GitHub — 例1
```text
このリポジトリの未マージのPRを一覧にして、レビュー待ちが長い順に並べて教えて。それぞれ、誰がレビュー待ちで止まっているか、放置されている日数も添えて。
```
### 2. GitHub — 例2
```text
このPRの差分を確認して、バグの可能性や設計上の懸念があれば指摘して。良い変更であればそれも伝えつつ、そのままレビューコメントとして投稿できる文面案を作って。
```
### 3. GitHub — 例3
```text
直近1週間にクローズされたIssueを一覧化して要約して。バグ報告と機能要望のどちらが多いか、対応に時間がかかった傾向があれば併せて教えて。
```
### 4. Slack — 例1
```text
このチャンネルの今日のやり取りを要約して。決定事項と、まだ誰も対応していないタスクを分けてリストにし、タスクには関係してそうな担当者も添えて。
```
### 5. Slack — 例2
