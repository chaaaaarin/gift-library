個人のパスワード・アカウント診断

001使い回しパスワードの棚卸し
前提: 自分が複数のサービスで同じ、または似たパスワードを使い回していないか不安。
指示: 主要サービス(メール・SNS・ネットバンキング・ショッピング)ごとに、パスワードの使い回しリスクをどう自己点検すればよいか、チェック手順を教えて。実際のパスワード文字列は書かせない。
出力形式: 手順を番号付きで5〜7ステップ。各ステップに「なぜ危険か」を1行添えて。実際のパスワードは絶対に入力させない前提で書いて。
002多要素認証の導入優先順位
前提: 多要素認証(MFA)をどのサービスから設定すべきか分からない。
指示: メール・クラウドストレージ・SNS・金融系サービスの4カテゴリで、MFA導入の優先順位とその理由、代表的な設定方法(認証アプリ/SMS/セキュリティキー)の違いを整理して。
出力形式: 優先度(高中低)付きの表。各カテゴリに推奨MFA方式とその理由を1行で添えて。
003パスワードマネージャー選定基準
前提: パスワード管理ツールを導入したいが選び方が分からない。
指示: 個人利用に適したパスワードマネージャーを選ぶ際に確認すべき基準(暗号化方式・オフライン利用可否・端末間同期・料金)を整理して。特定製品の推奨は避け、判断基準そのものを提示して。
出力形式: 確認項目を箇条書きで6項目以上。各項目に「なぜ重要か」を1行添えて。
004漏えい済みメールアドレスの確認方法
前提: 自分のメールアドレスが過去の情報漏えいに含まれていないか確認したい。
指示: メールアドレスが公開データベースに漏えいしていないか確認する一般的な方法と、漏えいが確認できた場合に取るべき対応手順を整理して。
出力形式: 確認方法→発覚時の対応、の2段階構成。対応手順は優先順位付きで。
005退職・解約したサービスアカウントの整理
前提: もう使っていないサービスのアカウントを放置していないか心配。
指示: 何年も使っていないサービスのアカウントを洗い出し、退会・削除すべきか休眠のままにすべきかを判断する基準を教えて。放置するリスクも具体的に。
出力形式: 判断フローチャート形式のテキスト(条件分岐)。放置するリスクを3つ以上列挙して。
006セキュリティ質問の見直し
前提: 「母親の旧姓」等のセキュリティ質問がSNSから推測されうるか不安。
指示: SNSやプロフィール公開情報から推測されやすいセキュリティ質問の種類と、より安全な設定方法(でたらめな答えを使う場合の管理方法含む)を教えて。
出力形式: 推測されやすい質問例を5つ、それぞれの対策を1行ずつ添えて。
007家族共有アカウントの権限整理
前提: 家族で共有しているストリーミング・クラウド等のアカウント権限が曖昧になっている。
指示: 家族で共有しているサービスごとに、誰がどこまでの権限(閲覧のみ/編集可/管理者)を持つべきかを整理する棚卸しシートの項目を設計して。
出力形式: サービス名/利用者/推奨権限/確認頻度の4列表のひな形。
008休眠SNSアカウントの乗っ取りリスク点検
前提: 長期間ログインしていないSNSアカウントが乗っ取られていないか確認したい。
指示: 長期間放置したSNSアカウントについて、乗っ取りの兆候(見覚えのない投稿・ログイン履歴・連携アプリ)を確認する手順を整理して。
出力形式: 確認する箇所を5つ以上、それぞれ「どこを見るか」を具体的に。
009APIキー・トークンの棚卸し
前提: 過去に発行したAPIキーやアクセストークンを使い回したり放置していないか不安。
指示: 個人開発で発行したAPIキー・アクセストークンについて、有効期限切れ・不要になったものを洗い出し、失効させる手順を整理して。実際のキー文字列は書かせない。
出力形式: 洗い出し観点を箇条書きで、失効手順は一般的な流れを番号付きで。
010パスワードリセット導線の悪用チェック
前提: パスワードリセット機能が悪用されていないか(不審なリセットメール等)を確認したい。
指示: 身に覚えのないパスワードリセットメールを受け取った場合に、それが正規のものか攻撃の予兆かを見分ける観点と、取るべき初動対応を整理して。
出力形式: 見分ける観点を3つ以上、初動対応を優先順位付きで箇条書き。

フィッシング・詐欺メール判定

011送信元ドメインの見分け方
前提: 受信したメールの送信元が本物の企業か偽装か見分けたい。
指示: メールの送信元アドレス・表示名・ドメインを見て、なりすましを見抜くためのチェックポイントを整理して。実際に届いたメールの文面を貼るので、一般的な注意点と照らして確認して。
出力形式: チェックポイントを5項目以上の箇条書き。最後に総合判定(要注意/概ね安全/判断不能)の目安を添えて。
012URLリンクの安全確認手順
前提: メール内のリンクをクリックする前に安全性を確認する方法を知りたい。
指示: メール本文のリンクについて、クリックせずにリンク先の安全性を推測・確認する具体的な手順(ホバー確認・短縮URL展開・ドメイン照合等)を教えて。
出力形式: 手順を番号付きで、それぞれ「何を確認するか」を明記して。
013緊急性を煽る文面のパターン抽出
前提: 「今すぐ対応しないとアカウント停止」等の煽り文句に引っかからないようにしたい。
指示: フィッシングメールによくある緊急性・恐怖心を煽る典型的な文言パターンを整理し、正規の企業連絡との違いを教えて。
出力形式: 典型パターンを5つ以上の例文とともに、正規メールとの違いを1行ずつ添えて。
014添付ファイルの危険度判定
前提: 受信メールの添付ファイル(請求書等の名目)を開いてよいか判断したい。
指示: 添付ファイルの拡張子・ファイル名・送信元の組み合わせから危険度を判断する基準を整理して。開く前に取るべき確認手順も。
出力形式: 危険度が高い拡張子・組み合わせの一覧と、開く前のチェック手順を箇条書きで。
015QRコードフィッシングの見分け方
前提: メールやポスターのQRコードを読み取っても大丈夫か不安。
指示: QRコードを使ったフィッシング(クイッシング)の手口と、読み取り前後で確認すべきポイントを整理して。
出力形式: 手口の説明を2〜3行、確認ポイントを箇条書きで5項目以上。
016なりすましSMS(スミッシング)の判定
前提: 宅配便や銀行を装ったSMSが届いたが本物か判断したい。
指示: 宅配便・銀行等を装ったSMSの典型的な手口と、本文中のリンクや電話番号から真偽を判断する手順を整理して。
出力形式: 典型的な手口を3つ以上、判断手順を番号付きで。
017経営者・上司なりすましメールの対策
前提: 取引先や上司を装った振込依頼メールへの対策を知りたい(ビジネスメール詐欺対策)。
指示: ビジネスメール詐欺(BEC)の典型的な手口と、振込・支払い依頼メールを受け取った際に組織として確認すべき手順を整理して。
出力形式: 手口の説明と、社内で徹底すべき確認フローを番号付きで5ステップ以上。
018偽ショッピングサイトの見分け方
前提: SNS広告で見つけたショッピングサイトが本物か怪しいか判断したい。
指示: 個人が偽ショッピングサイトを見分けるためのチェックポイント(URL・運営者情報・レビュー・支払い方法等)を整理して。
出力形式: チェックポイントを6項目以上の箇条書きで、それぞれ確認方法を1行添えて。
019フィッシング被害後の初動対応
前提: 誤ってフィッシングサイトに情報を入力してしまった場合の対応を知りたい。
指示: フィッシングサイトに個人情報やパスワードを入力してしまった直後に取るべき初動対応の手順を、優先順位付きで整理して。
出力形式: 優先順位付きの番号リスト。パスワード変更・カード停止・関係機関への連絡等の観点を含めて。
020組織内フィッシング訓練メールの企画
前提: 社内でフィッシング耐性を高めるための模擬訓練メールを企画したい。
指示: 社内向けフィッシング訓練メールを企画する際の、題材選定・実施頻度・結果のフィードバック方法についての設計指針を整理して。
出力形式: 企画の骨子を項目立てで(題材/頻度/フィードバック方法/注意点)。

SNSアカウントの安全設定点検

021公開範囲設定の総点検
前提: SNSの投稿・プロフィールがどこまで一般公開されているか把握したい。
指示: 主要SNS(X・Instagram・Facebook・LinkedIn等)ごとに確認すべき公開範囲設定の項目(投稿範囲・フォロワー一覧・位置情報)を整理して。
出力形式: サービスごとに確認項目を3つ以上、設定変更の一般的な手順を添えて。
022連携アプリの権限棚卸し
前提: SNSアカウントに連携している外部アプリの権限が過剰になっていないか確認したい。
指示: SNSアカウントに連携された外部アプリ・サービスの権限を洗い出し、不要な連携を解除する判断基準を整理して。
出力形式: 洗い出し手順と、解除すべきかどうかの判断基準を箇条書きで。
023プロフィール情報の推測リスク点検
前提: プロフィールの生年月日・出身地等から個人情報が推測されないか心配。
指示: SNSプロフィールに公開している情報(生年月日・出身校・勤務先等)が、なりすましや標的型攻撃にどう悪用されうるかを整理し、公開範囲の見直し案を提示して。
出力形式: 情報項目ごとの悪用リスクを1行ずつ、見直し案を箇条書きで。
024位置情報付き投稿のリスク確認
前提: 旅行や自宅周辺の写真投稿に位置情報が付いていないか確認したい。
指示: 投稿に位置情報(EXIF・タグ付け)が含まれているかの確認方法と、含まれていた場合の削除・無効化手順を教えて。
出力形式: 確認方法と削除手順を分けて番号付きで。
025フォロー・フォロワーの不審アカウント点検
前提: 不審なアカウントにフォローされている・自動フォローしていないか確認したい。
指示: フォロー・フォロワーリストから、ボットや詐欺目的の不審アカウントを見分ける特徴を整理して。
出力形式: 不審アカウントの特徴を5つ以上の箇条書きで。
026ログインセッションの棚卸し
前提: SNSに複数端末からログインした履歴を確認し、身に覚えのないセッションがないか点検したい。
指示: 各SNSで「ログイン中のデバイス・セッション一覧」を確認する一般的な手順と、身に覚えのないセッションを見つけた場合の対応を教えて。
出力形式: 確認手順と対応手順を分けて番号付きで。
027DM経由の詐欺・勧誘の見分け方
前提: SNSのDMで届いた投資・副業の勧誘が詐欺かどうか判断したい。
指示: SNSのDMで届く投資・副業勧誘の典型的な手口と、危険信号となるフレーズ・パターンを整理して。
出力形式: 典型的な手口3つ以上と、危険信号となるフレーズの例を箇条書きで。
028子ども・家族アカウントの安全設定
前提: 家族がSNSを使う際に設定すべきプライバシー・安全機能を整理したい。
指示: 年齢層別(未成年含む)に、SNSで優先的に設定すべきプライバシー・安全機能を整理して。
出力形式: 年齢層ごとに推奨設定を3項目以上、理由も添えて。
029アカウント復旧手段の事前準備
前提: SNSアカウントが乗っ取られた場合に備えて復旧手段を事前に整えておきたい。
指示: 主要SNSでアカウント乗っ取り時に使える復旧手段(登録メール・電話番号・バックアップコード)を、今のうちに確認・整備するチェックリストを作って。
出力形式: サービス横断のチェックリスト形式。今すぐ確認すべき項目を優先順に。
030退職者・元メンバーのSNS運用権限整理
前提: 会社の公式SNSアカウントの運用権限が元担当者に残っていないか確認したい。
指示: 組織の公式SNSアカウントについて、運用担当者の異動・退職時に権限を確実に引き継ぎ・剥奪するためのチェック手順を整理して。
出力形式: 引き継ぎ・剥奪のチェックリストを番号付きで6項目以上。

自分のコード・リポジトリの脆弱性チェック

031依存ライブラリの既知脆弱性スキャン
前提: 自分のプロジェクトが使っている外部ライブラリに既知の脆弱性がないか確認したい。
指示: 対象プロジェクトの依存関係ファイル(package.json/requirements.txt等)を読み込み、既知の脆弱性が報告されているバージョンが含まれていないか確認して。修正版がある場合は更新方針も提案して。
出力形式: 脆弱性が見つかったライブラリ名/現バージョン/推奨バージョン/深刻度の表。
032シークレット・APIキーの誤コミット確認
前提: リポジトリの履歴にAPIキーやパスワードを誤ってコミットしていないか確認したい。
指示: リポジトリのコミット履歴・現在のコードから、APIキー・パスワード・トークンらしき文字列が含まれていないか走査して。見つかった場合の失効・除去手順も教えて。
出力形式: 検出結果の一覧(ファイル名/該当箇所/種類の推定)と、失効・履歴除去の手順を分けて。
033入力値検証の抜け漏れ点検
前提: ユーザー入力を受け付ける箇所で検証(バリデーション)が漏れていないか確認したい。
指示: 対象コードのユーザー入力を受け付ける箇所を洗い出し、SQLインジェクション・XSS等につながりうる検証漏れがないか点検して。
出力形式: 箇所ごとにリスクの種類と、検証追加の提案をセットで一覧化。
034認証・認可ロジックのレビュー
前提: 自作アプリの認証・権限チェックのロジックに抜け穴がないか確認したい。
指示: 対象コードの認証(ログイン)・認可(権限チェック)処理を読み、権限昇格や認証バイパスにつながりうる箇所がないか指摘して。
出力形式: 指摘箇所ごとに、具体的な悪用シナリオと修正方針を添えて。
035エラーメッセージからの情報漏えい確認
前提: エラー画面やAPIレスポンスに内部情報が漏れていないか確認したい。
指示: 対象コードのエラーハンドリング部分を確認し、スタックトレースや内部パス等の機密情報がユーザーに露出していないか点検して。
出力形式: 露出箇所の一覧と、本番環境向けの修正提案を添えて。
036HTTPSと証明書設定の点検
前提: 自分のWebサービスの通信が正しく暗号化されているか確認したい。
指示: 対象ドメインの証明書設定・リダイレクト設定について、一般的に確認すべき項目(有効期限・混在コンテンツ・強制HTTPS化)を整理して。
出力形式: 確認項目を箇条書きで5項目以上、確認方法も添えて。
037依存パッケージの供給元信頼性チェック
前提: npm/PyPI等からインストールしたパッケージの提供元が信頼できるか確認したい。
指示: 特定パッケージについて、メンテナンス状況・ダウンロード数・既知の問題報告など、信頼性を判断する材料の集め方を教えて。
出力形式: 確認observationの手順を箇条書きで、判断基準も添えて。
038ログ出力への機密情報混入チェック
前提: アプリのログにパスワードや個人情報が平文で出力されていないか確認したい。
指示: 対象コードのログ出力箇所を洗い出し、パスワード・トークン・個人情報が平文で記録されていないか点検して。
出力形式: 該当箇所の一覧と、マスキング・除外の修正案を添えて。
039CORS・APIアクセス制御の設定確認
前提: 自作APIのCORS設定が緩すぎて誰でもアクセスできる状態になっていないか確認したい。
指示: 対象APIのCORS設定・アクセス制御を確認し、意図しないオリジンからのアクセスを許可していないか点検して。
出力形式: 現在の設定内容の要約と、推奨設定への修正案。
040デプロイ前セキュリティチェックリストの作成
前提: 本番リリース前に確認すべきセキュリティ項目を毎回抜け漏れなくチェックしたい。
指示: 個人開発〜小規模チームのWebアプリを想定し、本番リリース前に確認すべきセキュリティチェックリストを作成して。
出力形式: カテゴリ別(認証/通信/依存関係/ログ/権限)にチェック項目を整理したリスト。

Webサイト・フォームのセキュリティ点検

041お問い合わせフォームの入力対策確認
前提: 自社サイトのお問い合わせフォームがスパム・攻撃の踏み台にされていないか確認したい。
指示: お問い合わせフォームについて、スパム対策(reCAPTCHA等)・入力値検証・送信頻度制限の観点から、確認すべき項目を整理して。
出力形式: 確認項目を箇条書きで、未対応の場合の対策案も添えて。

# AIで自分の身を守る セキュリティ点検プロンプト100選

GPT-5.6-Cyber・Daybreakは審査制で一般の人は使えませんが、ChatGPTやClaude等の身近なAIに「自分の身の回りのセキュリティ点検」を手伝わせることは今日からできます。10カテゴリ×10本、全100本入りです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: ChatGPTやClaude等のチャット画面にそのまま貼って使ってください。実際のパスワード・APIキー等の機密情報そのものはAIに入力しないでください。

## 個人のパスワード・アカウント診断

### 1. 使い回しパスワードの棚卸し

```text
前提: 自分が複数のサービスで同じ、または似たパスワードを使い回していないか不安。
指示: 主要サービス(メール・SNS・ネットバンキング・ショッピング)ごとに、パスワードの使い回しリスクをどう自己点検すればよいか、チェック手順を教えて。実際のパスワード文字列は書かせない。
出力形式: 手順を番号付きで5〜7ステップ。各ステップに「なぜ危険か」を1行添えて。実際のパスワードは絶対に入力させない前提で書いて。
```

### 2. 多要素認証の導入優先順位

```text
前提: 多要素認証(MFA)をどのサービスから設定すべきか分からない。
指示: メール・クラウドストレージ・SNS・金融系サービスの4カテゴリで、MFA導入の優先順位とその理由、代表的な設定方法(認証アプリ/SMS/セキュリティキー)の違いを整理して。
出力形式: 優先度(高中低)付きの表。各カテゴリに推奨MFA方式とその理由を1行で添えて。
```

### 3. パスワードマネージャー選定基準

```text
前提: パスワード管理ツールを導入したいが選び方が分からない。
指示: 個人利用に適したパスワードマネージャーを選ぶ際に確認すべき基準(暗号化方式・オフライン利用可否・端末間同期・料金)を整理して。特定製品の推奨は避け、判断基準そのものを提示して。
出力形式: 確認項目を箇条書きで6項目以上。各項目に「なぜ重要か」を1行添えて。
```

### 4. 漏えい済みメールアドレスの確認方法

```text
前提: 自分のメールアドレスが過去の情報漏えいに含まれていないか確認したい。
指示: メールアドレスが公開データベースに漏えいしていないか確認する一般的な方法と、漏えいが確認できた場合に取るべき対応手順を整理して。
出力形式: 確認方法→発覚時の対応、の2段階構成。対応手順は優先順位付きで。
```

### 5. 退職・解約したサービスアカウントの整理

```text
前提: もう使っていないサービスのアカウントを放置していないか心配。
指示: 何年も使っていないサービスのアカウントを洗い出し、退会・削除すべきか休眠のままにすべきかを判断する基準を教えて。放置するリスクも具体的に。
出力形式: 判断フローチャート形式のテキスト(条件分岐)。放置するリスクを3つ以上列挙して。
```

### 6. セキュリティ質問の見直し

```text
前提: 「母親の旧姓」等のセキュリティ質問がSNSから推測されうるか不安。
指示: SNSやプロフィール公開情報から推測されやすいセキュリティ質問の種類と、より安全な設定方法(でたらめな答えを使う場合の管理方法含む)を教えて。
出力形式: 推測されやすい質問例を5つ、それぞれの対策を1行ずつ添えて。
```

### 7. 家族共有アカウントの権限整理

```text
前提: 家族で共有しているストリーミング・クラウド等のアカウント権限が曖昧になっている。
指示: 家族で共有しているサービスごとに、誰がどこまでの権限(閲覧のみ/編集可/管理者)を持つべきかを整理する棚卸しシートの項目を設計して。
出力形式: サービス名/利用者/推奨権限/確認頻度の4列表のひな形。
```

### 8. 休眠SNSアカウントの乗っ取りリスク点検

```text
前提: 長期間ログインしていないSNSアカウントが乗っ取られていないか確認したい。
指示: 長期間放置したSNSアカウントについて、乗っ取りの兆候(見覚えのない投稿・ログイン履歴・連携アプリ)を確認する手順を整理して。
出力形式: 確認する箇所を5つ以上、それぞれ「どこを見るか」を具体的に。
```

### 9. APIキー・トークンの棚卸し

```text
前提: 過去に発行したAPIキーやアクセストークンを使い回したり放置していないか不安。
指示: 個人開発で発行したAPIキー・アクセストークンについて、有効期限切れ・不要になったものを洗い出し、失効させる手順を整理して。実際のキー文字列は書かせない。
出力形式: 洗い出し観点を箇条書きで、失効手順は一般的な流れを番号付きで。
```

### 10. パスワードリセット導線の悪用チェック

```text
前提: パスワードリセット機能が悪用されていないか(不審なリセットメール等)を確認したい。
指示: 身に覚えのないパスワードリセットメールを受け取った場合に、それが正規のものか攻撃の予兆かを見分ける観点と、取るべき初動対応を整理して。
出力形式: 見分ける観点を3つ以上、初動対応を優先順位付きで箇条書き。
```

```text
出力形式: チェックポイントを5項目以上の箇条書き。最後に総合判定(要注意/概ね安全/判断不能)の目安を添えて。

```

```text

指示: フィッシングメールによくある緊急性・恐怖心を煽る典型的な文言パターンを整理し、正規の企業連絡との違いを教えて。

```

### 14. 添付ファイルの危険度判定

```text
出力形式: 危険度が高い拡張子・組み合わせの一覧と、開く前のチェック手順を箇条書きで。
```

### 15. QRコードフィッシングの見分け方

```text
前提: メールやポスターのQRコードを読み取っても大丈夫か不安。
指示: QRコードを使ったフィッシング(クイッシング)の手口と、読み取り前後で確認すべきポイントを整理して。
出力形式: 手口の説明を2〜3行、確認ポイントを箇条書きで5項目以上。
```

### 16. なりすましSMS(スミッシング)の判定

```text
指示: 宅配便・銀行等を装ったSMSの典型的な手口と、本文中のリンクや電話番号から真偽を判断する手順を整理して。
```

### 18. 偽ショッピングサイトの見分け方

```text
前提: SNS広告で見つけたショッピングサイトが本物か怪しいか判断したい。
```


## インシデント発生時の初動対応

### 91. 不審な挙動を発見した際の第一報テンプレート

```text

指示: マルウェア感染が疑われる端末について、被害拡大を防ぐための初動隔離手順(ネットワーク切断・証拠保全・関係者連絡)を整理して。
```
