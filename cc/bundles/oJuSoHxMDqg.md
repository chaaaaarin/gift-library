### 2. Gatekeeper式 権限設計チェックリスト（チェックリスト）
# AIに社内システムの何をどこまで渡すかを決めるための判断基準を、Cloudflare OSのGatekeeperの考え方をもとにまとめました。

# 🎁 Gatekeeper式 権限設計チェックリスト

AIに社内システムの何をどこまで渡すかを決めるための判断基準を、Cloudflare OSのGatekeeperの考え方をもとにまとめました。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 新しくAIエージェントに何かを任せるたびに、上から順に確認してください。指示例はそのままClaude Codeに貼れます。

```text
【Gatekeeper式 権限設計チェックリスト】

■ ステップ1：何を渡すか棚卸しする
□ AIエージェントに今どんな権限を渡しているか、一覧で把握できている
→ YES: 次のステップへ進める
□ 「念のため」で必要以上に広い権限を渡している箇所がある
→ YES: 削れる権限がないか洗い出す
□ APIキーやトークンをAIに直接渡している
→ YES: 仲介役（Gatekeeper相当の仕組み）を挟めないか検討する
指示例: 今Claude Codeに渡しているアクセス権限を全部洗い出して、実際に使っているものだけに絞る案を出して。

■ ステップ2：権限を最小単位に割る
□ リポジトリ・フォルダ単位でアクセス範囲を絞れている
→ YES: 部門・プロジェクト単位でも同様に絞れないか検討する
□ 読み取りと書き込みの権限を分けて考えられている
→ YES: 書き込みが必要な操作だけ人の承認を挟む設計にする
□ 一時的にしか使わない権限が、恒久的に付与されたままになっている
→ YES: 期限付き権限に切り替える
指示例: このタスクに必要な最小限の権限だけを持つ設定に変更して。タスク完了後は自動で失効するようにして。

■ ステップ3：観測ログを残す
□ AIが何に・いつアクセスしたか、後から追跡できる
→ YES: 監査ログとして定期的に見返す運用にする
□ 成果物を共有するとき、共有先が元データを見る権限を持つか確認している
→ YES: 権限を回避した共有が起きない設計になっている
□ 異常なアクセスがあった場合、即座に遮断する手順が決まっている
→ YES: 緊急時にも安心して運用できる
指示例: AIエージェントのアクセスログを記録する仕組みを設計して。異常があれば通知が飛ぶようにして。
```

**ポイント**: 「渡せるか」ではなく「渡さなくて済むか」から考えると、権限は自然と最小になります。
