```text
15. 送るのと探すのを止める
（保存先: .claude/settings.json／2つの道具を使えなくして、こちらから送れないようにする。指定子は付けずツール名だけ書く。）
{
  "permissions": {
    "deny": ["SendMessage", "ListAgents"]
  }
}

16. 送受信の両方を止める
（保存先: .claude/settings.json／受け取りを捨て、送るのと探すのも封じる。個人の環境で完全に無効化したいときの最小形。）
{
  "permissions": {
    "deny": ["SendMessage", "ListAgents"]
  },
  "crossSessionInbound": "refuse"
}

17. 組織全体で無効にする
（保存先: 管理設定（managed settings）／利用者が上書きできない形で全員に適用する。受け口自体は用意されるが、届いたものは全部捨てられる。）
{
  "permissions": {
    "deny": ["SendMessage", "ListAgents"]
  },
  "crossSessionInbound": "refuse"
}

18. 探すのだけ許して、送るのは止める
（保存先: .claude/settings.json／他のセッションの存在は把握できるが、こちらからメッセージは出せない状態にする。）
{
  "permissions": {
    "deny": ["SendMessage"]
  }
}

19. 受け取りだけ止めて、送るのは残す
（保存先: .claude/settings.json／こちらからの連絡は続けたいが、外からの割り込みは避けたいときに。）
{
  "crossSessionInbound": "refuse"
}

20. 一時的に全部止めて起動する
（使い方: 設定ファイルを書き換えずに、そのセッションだけ完全に無効化する。切り分けの検証にも使える。）
claude --settings '{"permissions":{"deny":["SendMessage","ListAgents"]},"crossSessionInbound":"refuse"}'

21. 停止の副作用を確認する
（確認事項: SendMessageを止めると、同じセッション内の助手やチームへの連絡も一緒に消える（同じ道具を使っているため）。停止前に読み合わせる。）
# SendMessage を deny すると、次のものが同時に使えなくなる
# ・他のセッションへのメッセージ送信
# ・このセッション内のサブエージェントへの連絡
# ・エージェントチームの同僚への連絡
#
# 「外からの割り込みだけ止めたい」なら deny ではなく
# crossSessionInbound: "refuse" だけを使う

22. 停止できているか確かめる
（確認事項: 拒否しているセッションは見た目に変化が出ないため、設定ファイル側で確認するしかない。）
# 拒否設定のセッションは /status にも他セッションの一覧にも
# 「拒否中」とは表示されない。必ず設定ファイルで確認する
#
# 確認するファイル（下ほど優先度が高い）
#   ~/.claude/settings.json
#   <プロジェクト>/.claude/settings.json
#   <プロジェクト>/.claude/settings.local.json
#   管理設定（managed settings）

## 無人・バックグラウンドで動かす

23. 無人ワーカーに受け取らせる
（使い方: 対話なしで動かすワーカーは承認の確認を出せないため、保留になると止まったままになる。acceptを明示して起動する。）
claude -p "指示内容" --settings '{"crossSessionInbound":"accept"}'

24. 名前を付けて起動する
（使い方: 宛先として指定しやすいよう、起動時に役割の分かる名前を付ける。付けないと作業フォルダ名から自動で命名される。）
claude --name migration-worker

25. 名前を付けて裏で走らせる
（使い方: 背面で動かすセッションにも名前を付けておくと、後から宛先に指定しやすい。背面セッションも一覧に出る。）
claude --bg --name test-runner "テストを最後まで走らせて、終わったら結果を知らせて"

26. 動いているセッションに後から名前を付ける
（使い方: 起動済みのセッションの名前を変える。連携を始める前にやっておくと迷子にならない。）
/rename payments-api

27. 無人ワーカー用の設定をファイルにまとめる
（保存先: 任意の場所（例: ~/.claude/worker-settings.json）／毎回コマンドに長い指定を書かずに済む。）
{
  "crossSessionInbound": "accept",
  "isolatePeerMachines": true
}

28. 設定ファイルを指定して無人起動する
（使い方: 上のファイルを渡して起動する。ユーザー設定を汚さずに、そのワーカーだけの挙動にできる。）
claude -p "指示内容" --settings ~/.claude/worker-settings.json

## 確認と切り分けをする

29. 届く相手を一覧で見る
（使い方: いまメッセージを届けられる相手を表示する。認識されない場合は、機能自体がない（バージョン不足など）と判断できる。）
/list-agents

30. 同じ意味の別名で確認する
（使い方: /list-agents と同じ内容が出る。打ちやすいほうを使えばよい。）
/peers

31. 自分の受け口のアドレスを見る
（使い方: 機能が有効なセッションには、受け口のアドレスが表示される行がある。ここが出なければ有効になっていない。）
/status

32. バージョンを確認する
（使い方: 必要なのは v2.1.224 以降。これより前だと機能そのものが存在しない。）
claude --version

33. 切り分けの順番を手元に置く
（使い方: 届かないときに、上から順に確認する。原因の大半はこの5項目のどれかに当たる。）
1. /list-agents が認識されるか
   → されない: バージョン不足・非対応の基盤・通信を減らす環境変数を疑う

2. claude --version が v2.1.224 以降か
   → 未満: 更新する

3. 相手が一覧に出ているか
   → 出ない: 同じマシンか／同じファイルが見える環境か（コンテナの内外）を確認

4. 相手の受け取り設定が refuse になっていないか
   → なっている: 相手側の設定ファイルを確認

5. 相手が別マシン・ブラウザ版でないか
   → そうなら: こちらから会話を始めることはできない（返信のみ）

34. 受け口の環境変数を確認する
（使い方: フックやコマンドから自分のセッションへ投函するときに使うアドレス。どのフックより前に渡される。）
echo "$CLAUDE_CODE_MESSAGING_SOCKET"

## フック・スクリプトから投函する

35. 受け口の変数が使えるか確かめる
（保存先: 任意のシェル／フックやBashコマンドの中でこの変数が空でなければ、そこへ投函できる。）
if [ -n "$CLAUDE_CODE_MESSAGING_SOCKET" ]; then
  echo "受け口あり: $CLAUDE_CODE_MESSAGING_SOCKET"
else
  echo "受け口なし（機能が無効か、対応していない環境）"
fi

36. 親から引き継いだ変数と混同しない
（確認事項: 各セッションは自分の受け口を渡す。親セッションのものを引き継ぐことはないので、入れ子で動かしても取り違えは起きない。）
# セッションごとに別の値が入る
# 親セッションの受け口を子が引き継ぐことはない
#
# 確認: 2つのセッションでそれぞれ実行し、値が違うことを見る
echo "$CLAUDE_CODE_MESSAGING_SOCKET"

37. サンドボックスから受け口へ届かせる
（保存先: .claude/settings.json／サンドボックス内のコマンドから受け口へ到達させたいときに、接続を明示的に許可する。）
{
  "sandbox": {
    "network": {
      "allowAllUnixSockets": true
    }
  }
}

38. 特定の受け口だけ許可する
（保存先: .claude/settings.json／全許可を避け、必要なものだけを通す。パスは /status か環境変数で確認した値に置き換える。）
{
  "sandbox": {
    "network": {
      "allowUnixSockets": ["<受け口のパス>"]
    }
  }
}

39. 自分の子プロセスからの投函の挙動を押さえる
（確認事項: 受け取り設定が何も当てはまらないとき、自分の子プロセスからの投函は配達される。ただし確認できる範囲がOSで違う。）
# 子プロセスからの投函が「自分の子である」と検証できる範囲
#
# Linux（WSL 2 の中を含む）
#   → 子プロセスが終了済みでも検証できる
#
# macOS
#   → 投函したプロセスが動いている間だけ検証できる
#
# コンテナで PID 1 として動いている場合
#   → 検証できない
#
# 検証できないときは「権限の階級を名乗らないメッセージ」
# と同じ扱いになり、確認を飛ばすセッションでは保留される

40. バックグラウンド起動をまとめて設定する
（保存先: .claude/settings.json／背面セッションが作業場を隔離する挙動を切りたい場合に。切ると同じ場所を触るので衝突に注意。）
{
  "worktree": {
    "bgIsolation": "none"
  }
}

```

**ポイント**: 受け取りを止める `refuse` はプロジェクト設定から指定すると他のどの指定より優先されます。逆に「送るのを止める」設定は、同じセッション内の助手への連絡も一緒に消える点に注意してください。
